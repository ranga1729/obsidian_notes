#### Critical Chain Scheduling
Critical chain scheduling is a technique that allows variability in the task durations. 
Tasks are estimated as,
1. Optimistic duration
	The shortest possible time a task could take, assuming everything goes well.
2. Most likely duration
3. Pessimistic duration
	The longest possible time a task could take, assuming problems or delays occur.

##### Project buffer calculation,
$$
\text{Project buffer} = \frac{1}{2} \left( \sum{\text{Pessimistic}} - \sum{\text{Most likely duration}} \right)
$$
![[Pasted image 20250515133550.png]]
- The project buffer is always placed at the end of the project schedule to provide maximum protection for the project end date.
##### Project length Calculation
$$
\text{Project length} =  \sum{\text{Most Likely}} + {\text{Project buffer}})
$$
Ex:
![[Pasted image 20250515123415.png]]

$$
\text{Project buffer} = \frac{1}{2} \left( \sum{\text{Pessimistic}} - \sum{\text{Most likely duration}} \right)

#### Resource Contention
Resource contention occurs when multiple tasks or projects compete for the same limited resources at the same time. 

ex: 
	Two tasks need the same engineer

Why it matters ?
	Leads to bottleneck
	Affects scheduling and deadlines
	Need prioritizing or rescheduling to resolve

> [!NOTE] Critical chain vs Critical Path
> - Critical Path : The sequence of schedule activities that determines the duration of the project.
> - Critical Chain : The sequence of activities and resources that determines the duration of the project. 

During a resource contention, we should focus on the Critical Chain rather than critical path. 

#### Multi-Project Issues and Multitasking
- Single tasking is efficient more than multitasking. 
Ex: A resource has 3 tasks from different projects. 
- Sequential completion : Task A -> Task B -> Task C
	![[Pasted image 20250515134055.png]]
	Task A : 3 days
	Task B : 6 days
	Task C : 9 days
	Average = 6 days
- If the resource multitask by doing one day of each task at a time. 
	![[Pasted image 20250515134147.png]]
	Task A : 7 days
	Task B : 8 days
	Task C : 9 days
	Average = 8 days
	33% longer than the first approach.

How to sequence multiple projects to achieve optimal efficiency with resources,
![[Pasted image 20250515135444.png]]
Running multiple projects parallel causes resource contention, leading to delays or inefficiencies. Instead of parallel execution, the projects are now sequenced. 
- Tasks are rearranged to avoid contention for the critical shared resource (called the pacing/drum resource).
- This sequencing leads to smoother resource usage, less multitasking, and often a shorter total project duration overall.

> [!NOTE] Pacing/Drum Resource
> A pacing resource is the most constrained or heavily used resource in a project or across multiple projects. everything needs to be scheduled around it to avoid overload and delays.
> In CCPM,
> 	- Identify the drum resource.
> 	- Schedule tasks and projects so that this resource is not overloaded.


#### Recommendations for Critical chain Scheduling
1. Do three-point estimation for tasks
	Optimistic, Most likely, Pessimistic
2. Schedule tasks using the most likely times
3. Add a project buffer to protect the project end date from uncertainties.
4. Focus on Critical Chain rather than Critical Path
5. Minimize multitasking by sequencing projects
6. Protect the pacing/drum resource from interruptions to maximize the number of projects performed
