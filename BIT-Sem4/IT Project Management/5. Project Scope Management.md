**Project scope management** includes the process involved in defining and controlling what is or what is not included in a project. 

**Scope** refers to all the work involved in creating the products of the project and the process used to create them. 

A **deliverable** is a product produced as part of a project. 
Ex: hardware, software, documents

**Scope Planning** : Deciding how the scope will be defined. 
**Creating the WBS(Work Breakdown Structure)** : Subdividing the major project deliverables into smaller, more manageable components.
**Scope verification** : Formalizing acceptance of the project scope.
**Scope control** : Controlling changes to project scope.

****
#### Planning scope management
The scope management plan is a document that includes descriptions of how the team will prepare the project scope statement, create the WBS, verify completion of the project deliverables, and control requests for changes to the project scope.

Inputs,
	Project charter,
	Preliminary scope statement,
	Project management plan

#### Creating the work Breakdown Structure(WBS)
A WBS is a deliverable-oriented grouping of the work involved in a project.
A WBS is a foundation document that provides the basis for planning and managing project schedules, costs, resources, and changes.

**Decomposition** : Subdividing project deliverables into smaller pieces.

##### Approaches to Develop a WBS
1. Guidelines
	Some organizations provide guidelines for preparing WBS
2. Analogy approach
	Review WBSs of similar projects and tailor to your project.
3. Top-down approach
	Start with largest items of the project and break them down.
4. Bottom-up approach
	Start with the specific tasks and roll them up.

****
##### Controlling Scope
**Variance** : Difference between planned and actual performance. 
Goals of scope controlling,
	1. Influence the factors that cause scope changes.
	2. Ensure changes are processed according to procedures developed as part of integrated change control.
	3. Manage changes when they occur.

*****
#### Suggestions for improving User Input,
1. Place users on the project team. 
2. Hold regular meetings with defined agendas.
3. Have users sign off on key deliverables presented at meetings. 
4. Regular deliveries to users and sponsors. 
5. Don't promise things you can't deliver. 
6. Co-locate users with developers. 

Considerations for Agile/adaptive environments,
1. Follow a requirement management process.
2. Use techniques such as prototyping and use case modeling
3. Put requirements in writing and keep them current.
4. Create a requirements management database.
5. Conduct testing throughout the project life cycle.
6. Review changes from a system perspective. 
7. Emphasize completion dates.
8. Allocate resources specifically for handling change requests and enhancements.
