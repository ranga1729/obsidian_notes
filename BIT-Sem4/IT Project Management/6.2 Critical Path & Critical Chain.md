## Critical Path Method (CPM)
![[Pasted image 20250514192718.png]]
The Critical Path Method (CPM) is a schedule network analysis technique. CPM was developed by the DuPont Corporation in 1957.
==Critical path is the longest duration path through a network of tasks.==
Critical tasks are those tasks that lie on the critical path

##### Task Parameters,
According to PMBOK, every scheduled task can be defined by four parameters:
- **Early Start (ES)**: Earliest possible point in time when a task can start
- **Early Finish (EF)**: Earliest possible point in time when a task can finish
- **Late Start (LS)**: Latest possible point in time when a task can start
- **Late Finish (LF)**: Latest possible point in time when a task can finish
Early Start and Early Finish dates are calculated using **means of Forward Pass**.
Late Start and Late Finish dates are calculated using **means of Backward Pass**.
##### Float/Slack Time
- Float is the amount of time a task can slip before delaying the project schedule. (a buffer time)
- Two common types:
	- **Free Float**: Time a single task can be delayed without delaying the early start of any successor task
    - **Total Float**: Time a single task can be delayed without delaying project completion
- Mathematically defined as: Float = LS - ES or LF - EF
- Critical path has zero or negative Total Float
- A project can have several critical paths

Ex:

##### Benefits of CPM
- Project planning and control
- Time-cost trade-offs
- Cost-benefit analysis
- Contingency planning
- Reducing risk
##### Limitations of CPM
- Assumes low uncertainty in schedule dates
- Does not consider resource dependencies
- Less efficient use of buffer time
- Less focus on non-critical tasks that can cause risk
- Based only on deterministic task duration
- Critical path can change during execution

These limitation are addressed in Critical Chain Project Management(CCPM).

## Critical Chain Project Management (CCPM)
![[Pasted image 20250515101757.png]]
Critical chain method is a schedule network analysis technique that modifies the project schedule to account for limited resources. It mixes deterministic and probabilistic approaches to schedule network analysis.

CCPM takes advantage of best practices from:
- PMBOK: Planning and control processes
- Theory of Constraints (TOC): Remove bottlenecks to resolve constraints
	A methodology for improving performance by focusing on the limiting factor (constraint) in a system. The core idea is that every system has a constraint, and improving it leads to overall performance gains.
- Lean: Eliminate waste
	A framework that focuses on eliminating waste and maximizing value delivery in software development processes.
- Six Sigma: Reduce variations
	A data-driven methodology for improving processes by reducing defects, minimizing variation, and increasing efficiency.
##### Challenges CCPM Addresses
- **Parkinson's Law**: Work expands to fill the available time
- **Murphy's Law**: What can go wrong will go wrong
- **Student Syndrome**: People only work at full capacity when deadline is near
- **Bad Multi-Tasking**: Can delay start of successor tasks
##### Key Concepts in CCPM
- Resource constrained situations
- Optimum use of buffers:
    - **Project Buffers (PB)**: Buffer time at the end of the project
    - **Feeding Buffers (FB)**: Buffer time at the end of a sequence of tasks
    - **Resource Buffers (RB)**: Alert indicating when a resource is needed to perform a task
##### CCPM Implementation Process
1. Remove safety time and reduce task durations by 50%
2. Create schedule on Late Finish dates, remove resource constraints, and identify critical chain
3. Add Project Buffer (50% of the tasks duration) and add Feeder buffer to non-critical chain

##### Buffer Calculation
- Simple case: 50% of project duration
	Project duration = 11 days
	50% of the duration = 5.5 days
	Project buffer = 5 days (rounded)
- Aggressive case: Square root of the sum of squares method (SSQ)
