### Traditional Switch Architecture
Switching functions are traditionally segregate into three separate categories(layers or planes),
1. Control planes
2. Management planes
3. Data planes

![[Pasted image 20250529143228.png]]
	SNMP(Simple Network Management Protocol) is a networking protocol used for management and monitoring of network connected devices in internet protocol networks.

##### 1. Data plane
Purpose : Handles the actual movement of packets. 
Location : Runs in hardware(ASICs - Application-Specific Integrated Circuit)
Main function : Forwards packets based on pre-defined rules
Responsibilities :
	Packet buffering,
	Packet scheduling,
	header modification,
	forwarding

- If an arriving data packet's header information is found in the forwarding table, it may be subjected to some header field modification and then will be forwarded without any intervention of the other two planes. 
- If the header information is not available in the forwarding table or if the packet is belong to some other control protocol, then in it has to process by the control plane.
##### 2. Control plane
Purpose : Makes decision about where traffic should be sent 
Location : Runs in software on the switch's CPU.
Function : 
	Runs routing protocols(ex: OSFP, BGP)
	Builds routing and MAC tables(forwarding tables)

- These routing protocols responsible for managing the active topology of the network. 
##### 3. Management plane
Purpose : Allows administrator to configure and monitor the device.
Location : Runs software interfaces like CLI, SNMP or Web UI.
Function : Provides tools for configuration, logging and remote access.

- This layer extracts information from or modifies data in the control and data planes.

#### Evolution of Switches and Control planes
In early days, except the physical layer, all most everything was controlled using software. hardware vendors wrote their own software to perform these tasks. 
Now most basic functions like forwarding and filtering decisions are implemented entirely in hardware. 
![[Pasted image 20250530135756.png]]

#### Hardware forwarding and control in software
1. Bridging (Layer two forwarding)
	Basic layer two MAC forwarding of packets is handled in the hardware tables. 
2. Routing (Layer three forwarding)
	To keep the high-speed links and to route packets at link speeds, layer three forwarding functionality is implemented in hardware tables.
3. Advanced filtering and prioritization
	General traffic management rules (ACLs) are handled via hardware tables located in the hardware.
4. Control
	Used to make broader routing decisions and to interact with other devices in order to converge on topologies and routing paths implemented in software that runs autonomously inside the devices.
*****
#### Control Software
- Control software is the intelligence program that determines optimal paths and responds to outages and new networking demands.
- SDN(Software Defined Network) is about moving that control software off of the device and into a centrally located compute resource which is capable of seeing the entire network and making decisions which are optimal, given a complete understanding of the situation.

SDN separate the network activities by,
1. Forwarding, filtering and prioritization
	Forwarding responsibilities implemented in hardware tables remain on the device.
2. Control
	Complicated control software is removed from the device and placed into a centralized controller.
3. Application
	Applications are run above the controller.

****
### Software Defined Networks
The centralized software-based controller in SDN provides an open interface on the controller to allow for automated control of the network.

Characteristics,
1. Plane separation
	Separation of the forwarding and control planes
2. Simplified device and centralized control
3. Network automation and virtualization
	Distributed state abstraction - Provide a global network view
	Forwarding abstraction - forwarding behaviors are not vendor specific
	Configuration abstraction - defines the goals of the network without considering how it is implemented in the physical hardware
4. Openness 
	Open SDN is standard, well documented and not proprietary.

Two main APIs,
1. Northbound API
	Allowing software applications to be plugged into the controller, and thereby allowing that software to provide the algorithms and protocols that can run the network efficiently.
2. Southbound API
	The OpenFlow interface that the controller uses to program the network devices.

- SDN Devices : Devices composed of an API for communication with the controller, an abstraction layer, and a packet processing function. 
- SDN Controller : Controller maintains a view of the entire network, implements policy decisions, controls all the SDN devices that comprise the network infrastructure, and provides a northbound API for applications.
- SN Applications : Applications run above the SDN controller, interfacing to the network via the controller’s northbound API.

#### OpenFlow
OpenFlow is a communication protocol that defines the communication between data plane and the control plane. It enables the separation of the control plane from the data plane in networking devices like switches and routers.

It doesn't describe the behavior of the controller itself, but used for the **controller to communicate with the data plane** (switches/routers). It tells the switches how to handle network packets.

This OpenFlow systems consist of an OpenFlow controller which communicates to one or more OpenFlow Switches. 

OpenFlow protocol,
1. Defines the specific messages and message formats exchanged between controller(control plane) and device(data plane)
2. Defines how the device should react in various situations and how should respond to commands from the controller.
