Automated network management tools need to be,
- Communicate with different devices from multiple vendors
- Centralize coordination of network components
	Example: Monitoring the corporate network using a central dashboard, pushing security updates remotely to devices

ISO Network management framework provides five management functional areas,
1. Fault management 
2. Accounting management
3. Configuration management
4. Performance management
5. Security management

#### Fault Management 
Fault management encompasses fault detection, isolation and correction of abnormal operation of the OSI Environment. Faults cause open systems to fail to meet their operational objectives and they may be persistent or transient. Faults manifest themselves as particular events (e.g., errors) in the operation of an open system. Error event detection provides a capability to recognize faults. Fault management includes functions to
- Maintain and examine error logs
- Accept and act upon error detection notifications 
- Trace and identify faults 
- Carry out sequences of diagnostic tests
- Correct faults

Faults and errors should be distinguished.
- A **fault** is a flaw or defect in a system — like a bug in code or a hardware issue.
- An **error** is the incorrect output or behavior that occurs when a fault is triggered during execution.
In short, Fault is the cause, **error** is the effect.

User expectations on fault management,
- Reliable problem resolution
- Same fault should not be happening again and again
- Quality network services delivered on a consistent basis
- Problems to be corrected immediately. 
- Keep informed of the network status
- Notified of the approximate time that the service will be resumed

Functional requirements of a Network management systems,
1. Detecting and reporting 
	- A mechanism to allow it users to log events and errors
	- monitoring events and errors
	- Identify faults by analyzing errors and events
	- Generate event reports for users
	- Broadcast notifications
2. Diagnosis of faults
	- Allow users to activate predefined diagnostic and testing procedures
	- Allows users to request fault related data, stats and status information
3. Correction of faults
	- change or reset resource attributes. 
	- Provide a mechanism to track network operation. 
	- Provide a robust fault manager system.

#### Accounting Management 
“Accounting management enables charges to be established for the use of resources in the Open System Interconnection Environment (OSIE), and for costs to be identified for the use of those resources. Accounting management includes functions to: 
- Inform users of costs incurred or resources consumed
- enable accounting limits to be set and tariff schedules to be associated with the use of resources;
- enable costs to be combined where multiple resources are invoked to achieve a given communication objective.”

User expectations,
- users and administrators need to be able to specify the kinds of accounting information to be recorded
- verify user's authorization to access and manipulate information

Functional requirements,
- Ability to record and generate accounting information
- The Ability to Control the Storage of and Access to Accounting Information
- The Ability to Report Accounting Information
- broadcast accounting news such as network resource billing rate changes or accounting limit changes
- The Ability to Set and Modify Accounting Limits
- The ability to define accounting metrics
#### Configuration Management 
Configuration identifies, exercises control over, collects data from and provides data to open systems for the purpose of preparing for, initializing, starting, providing for the continuous operation of, and terminating interconnection services. Configuration management includes functions to: 
- set the parameters that control the routine operation of the open system
- associate names with managed objects and sets of managed objects
- initialize and close down managed objects
- collect information on demand about the current condition of the open system
- obtain announcements of significant changes in the condition of the open system
- change the configuration of the open system.
#### Performance Management 
Performance management enables the behavior of resources in the OSIE and the effectiveness of communication activities to be evaluated. Performance management includes functions to: 
- gather statistical information; 
- maintain and examine logs of system state histories; 
- determine system performance under natural and artificial conditions; 
- alter system modes of operation for the purpose of conducting performance management activities.
#### Security Management
The purpose of security management is to support the application of security policies by means of functions which include: 
- the creation, deletion and control of security services and mechanisms
- the distribution of security-relevant information
- the reporting of security-relevant events.

### Simple Network Management Protocol(SNMP)
SNMP (Simple Network Management Protocol) is a standard network protocol used for monitoring and managing devices on IP networks — such as routers, switches, servers, printers, and more.

SNMP let network administrators,
- Monitor network performance(data rates, CPU load, Uptime, errors, running processes)
- Detect and troubleshoot issues
- Configure or manage network devices remotely.
	set or change device parameters

Key components,
1. SNMP Manager(or NMS) : Central system that polls or receives data from devices
2. SNMP Agent : Software running on the network device being monitored
3. MIB(management Information Base) : A virtual database that defines what can be monitored or controlled

SNMP uses,
1. UDP 161 port : SNMP Managers to communicate with SNMP Agents
2. UDP 162 port : when agents send unsolicited Traps to the SNMP Manager.

**Protocol Data Unit(PDUs)** are used for the communication between manager and agents. Each SNMP message contains a protocol data unit to inform the receiving party the actions that should be takes.

**MIB (Management Information Base)** 
Every Agent maintains the information corresponding to the device variables/parameters: e.g. CPU load, vendor name, etc. SNMP manager uses MIB to query a particular device and translate the information as required by the NMS. This shared information base between agent and manager in an SNMP architecture is called Management Information Base.
The MIB comprised of managed objects identified by a globally unique Object Identifier (OID).

	The OKD associated with Microsoft is 1.3.6.1.4.1.311 
	The OID in RFC1213 for "sysDescr" is .1.3.6.1.2.1.1.1

Workflow,
1. The SNMP agent runs on a device (like a router) and collects data (CPU load, memory usage, interface status).
2. The SNMP manager queries the agent using GET requests.
3. The agent responds with the requested data.
4. Devices can also send alerts to the manager using TRAP or INFORM messages (e.g., if a port goes down).
