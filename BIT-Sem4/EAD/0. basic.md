## 🏛️ **Big Picture: 3-Tier Architecture**

```
Presentation Layer       | Business Logic Layer       | Data Access Layer
-------------------------|-----------------------------|---------------------
JSP / HTML / JS          | JavaBeans (Service/Model)   | JPA Entities
Servlets (Controllers)   |                             | JPA + DB
```

---

### 🧩 **Layer Breakdown & Roles**

#### 1. 🖥️ **Presentation Layer (View/UI)**

- **JSP pages** display the content to the user.
- They can use **JavaBeans** to bind data for UI (like a `UserBean`).
- This layer is focused on how things look and what the user sees.

> Example: `user.getName()` is shown in a JSP after login.

#### 2. 🎯 **Business Logic Layer (Controller/Service Layer)**
- This is where **JavaBeans** are used to hold intermediate data (like `CartBean`, `LoginBean`).
- Servlets **control the flow**: they receive user actions, delegate to service classes or JavaBeans, and forward to JSPs.
- You may also have **service classes** (POJOs or Spring components) doing logic like login validation, calculations, etc.

> JavaBeans here **can be helpers, containers, or logic handlers**, but they **do not map to database tables**.

#### 3. 🗄️ **Data Access Layer**
- This is where **JPA Entities** live.
- `@Entity` classes are mapped to database tables (like `User`, `Product`, etc.).
- You use `EntityManager` to persist, find, update, and delete entities.
- This layer talks directly to the database.
---
### 🔁 **How They Work Together (Flow Example)**
**Scenario**: User logs in
1. **User submits login form** → `POST /login`
2. **Servlet** receives request → `LoginServlet`
3. Servlet creates a **LoginBean** (JavaBean) → stores email & password
4. LoginBean (or a service class) checks DB via **JPA**:
    - Uses `EntityManager.find(User.class, email)`
    - Compares passwords
5. If success → Servlet sets attributes and forwards to JSP
6. **JSP** uses the JavaBean or JPA entity to display `Welcome, ${user.name}`
---
### 🎯 Summary Table

|Component|Purpose|Type|Stores Data?|Talks to DB?|
|---|---|---|---|---|
|**JavaBean**|Carry or process data for view/controller|POJO|✅ Yes|❌ No|
|**JPA Entity**|Map to DB table|Annotated POJO|✅ Yes|✅ Yes|
|**Servlet**|Handle HTTP requests and control flow|Java class|✅ Temporarily|❌ No|
|**JSP**|Display UI using beans/entities|HTML+Java|❌ No|❌ No|

---
### 🧠 Summary

- **Servlet** = Java class that handles HTTP requests (backend logic).
- **JSP** = HTML page with Java, used to show output (frontend UI).
- **JavaBean** = Java object for holding and transferring data (model layer).

Together, they often implement the **MVC pattern**:
- **Model** → JavaBeans
- **View** → JSP
- **Controller** → Servlet
