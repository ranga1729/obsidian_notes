# Technical Specification (Architecture & Implementation)
**Multi-Tenant AI API Gateway Platform**

## 1. Technology Stack
* **Backend Services:** ASP.NET Core 10 (C#) for REST API & Session Gateway.
* **Frontend:** Next.js (TypeScript) 16+.
* **Primary Database:** PostgreSQL 18.
* **Cache/Session Store:** Redis 7+.
* **Secrets Management:** Azure Key Vault.
* **Vector Database:** Azure AI Search.
* **Document Storage:** Azure Blob Storage.
* **Orchestration & Infrastructure:** Kubernetes, Load Balancer (Nginx/Azure), SMTP/Azure Communication Services.

## 2. System Architecture

### 2.1 High-Level Architecture
The Platform consists of two independently deployable backend services sharing common infrastructure:
1. **REST API Service (Management Plane):** Handles user auth, project CRUD, config management, token issuance, document uploads, and analytics. 
2. **Session Gateway Service (Data Plane):** Handles real-time WebSocket/SSE connections, session state machine, LLM adapter translation, tool interception (RAG/MCP), and usage accumulation. Fully stateless in process memory (state in Redis).

### 2.2 System Constraints & Non-Functional Requirements
* **Security:** All data encrypted via TLS 1.2+. LLM/Tool credentials stored *exclusively* in Azure Key Vault (never DB/logs).
* **Privacy:** Conversation content (text, audio, tool payloads) MUST NOT be persisted to PostgreSQL.
* **Scalability:** Gateway nodes must be horizontally scalable. Redis handles all shared session state.
* **Extensibility:** Adding new LLMs requires only a new Adapter class and catalog insert (Adapter Pattern).
* **Tenant Isolation:** Every DB query must include `user_id` or `project_id`. RAG searches enforce `$filter=project_id eq '<id>'`.
* **SSRF Protection:** External MCP URLs are restricted (No RFC 1918 private IPs, loopbacks, or cloud metadata endpoints).

## 3. Session Gateway Mechanics

### 3.1 Connection & Authentication
Clients connect via WSS or SSE using an Ephemeral Token:
* **WSS:** `wss://<host>/ws?project_id=<id>&token=<token>`
* **SSE:** `GET https://<host>/sse?project_id=<id>` (Token in Auth header).
* Authentication is validated via atomic `Redis.GETDEL(token_hash)`.

### 3.2 Session State Machine & Dual Async Loop
* Sessions transition through strictly enforced states managed via Redis.
* **Active Session Loop:**
  * *Client -> Provider:* Reads inbound JSON/audio, validates schema, routes to adapter.
  * *Provider -> Client:* Reads normalized `LLMEvent` objects from the adapter. Intercepts gateway-resolved tools (RAG, MCP) before serializing and sending to the client.

### 3.3 Teardown
On closure, the gateway flushes usage counters to PostgreSQL, disconnects the provider, sends `session_ended`, and explicitly issues a Redis `DEL` for conversation history.

## 4. LLM Adapter Layer
All adapters implement `ILLMSessionAdapter`.
* **WS Bridge Adapters:** Maintain persistent WSS connections to LLMs (OpenAI Realtime, Gemini Live). Provider holds conversation state.
* **HTTP Orchestrator Adapters:** REST/SSE requests per turn (OpenAI Chat Completions, Gemini Generate). Platform maintains conversation history (assembled turns) in Redis for the session duration.

## 5. RAG (Retrieval-Augmented Generation) Architecture
* **Ingestion:** Uploaded docs stored in Azure Blob. Azure AI Search indexer chunks/embeds them using `text-embedding-3-small`.
* **Execution:** A builtin `search_internal_knowledge` tool is injected into the LLM. If invoked, the gateway intercepts it, queries the Vector DB (strictly filtered by `project_id`), and returns chunks to the LLM without client visibility.

## 6. MCP (Model Context Protocol) Architecture
* **Tool Discovery:** Gateway polls user-registered HTTPS MCP servers, caches schemas in Redis, and prefixes tool names (`mcp_<server_id>__<tool_name>`) to prevent collisions.
* **Execution:** LLM tool calls matching the prefix are intercepted, routed to the target MCP server, and results are returned to the LLM.

## 7. Authentication & Security
* **Access Tokens:** RS256-signed JWTs (15m TTL).
* **Refresh Tokens:** Random strings stored as HttpOnly, Secure cookies (7d TTL) with rotation.
* **API Keys:** Long-lived keys for backend-to-backend calls. Stored as HMAC-SHA256 hashes.
* **Ephemeral Tokens:** Short-lived (60s TTL), single-use tokens generated by the REST API for secure client connections.

## 8. Data Architecture
* **PostgreSQL:** Stores users, projects, configs, API key hashes, usage records, audit logs. No chat data.
* **Redis:** 
  * `session:{id}`: Metadata and state.
  * `session:{id}:history`: JSON turn history (auto-deleted at teardown).
  * `project:{id}:config`: Cached configurations.
  * Rate limit counters and Ephemeral Token TTLs.

## 9. Protocol Reference (Unified Client Protocol)
* **Client to Gateway:**
  * `text_input`: `{ "text": "..." }`
  * `audio_input`: `{ "audio": "<base64>", "sample_rate": 24000 }`
  * `tool_result`: `{ "tool_call_id": "...", "result": {...} }`
* **Gateway to Client:**
  * `text_delta` / `text_done` / `audio_delta` / `audio_done`
  * `tool_call`: `{ "name": "...", "arguments": {...} }`
  * `rag_search`: Informational event when RAG is triggered.
  * `error` / `session_ended`
