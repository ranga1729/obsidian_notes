#### Mental model(React --> Flutter)

| React concept | Flutter equivalent       |
| ------------- | ------------------------ |
| Component     | Widget                   |
| JSX           | Widget tree(Dart code)   |
| Props         | Constructor parameters   |
| State         | `StateWidget`            |
| setState      | `setState()`             |
| CSS           | Widget-based styling     |
| useEffect     | `initState()`            |
| div/span      | `Container, Row, Column` |
Everything in flutter is a widget. 

Flutter app entry point is,
```dart
void main() {
	runApp(const MyApp());
}
```
This is equivalent to react,
```ts
ReactDOM.createRoot(...).render(<App/>);
```
#### `MaterialApp` widget
This is the root widget for applications that follows Google's material design guidelines. 
It provides essential features like,
- Navigation : configure top-level `navigator` for screen management
- Theming
- Localization : support multiple languages
Ex:
```dart
import 'package:flutter/material.dart';

void main() {
	runApp(const MyApp());
}

class MyApp extends StatelessWidget {
	const MyApp({super.key});
	
	@override
	Widget build(BuildContext context) {
		return MaterialApp( //the root widget providing material design
			title: 'My Flutter App', //app title for the device's task manager
			debugShadowCheckedModBanner: false, // hides the debug banner
			theme: ThemeData(
				primarySwatch : Color.blue, //sets the app's primary color
				useMaterial: true, //enables material 3 design system
			),
			home: const HomeScreen(), //the initial screen of the app
		);
	}
}

Class HomeScreen extends StatelessWidget {
	const HomeScreen({super.key})
	
	@override
	Widget build(BuildContext context) {
		return Scaffold( //Provide the visual layout for the screen
			appBar: AppBar(
				title: const Text("Welcome Home"),
			),
			body: const Center(
				child: Text("Hello, Flutter!"),
			),
		);
	}
}
```

React equivalent,
```ts
function App() {
	return <HomeScreen />
}
```
### `StatelessWidget` 
This is similar to pure functional components. 
Ex: 
```dart
Class HomePage extends StatelessWidget{ 
	const HomePage({super.key});
	
	@override
	Widget build(BuildContext context) {
		return const Text("Hello Flutter");
	}
}
```
- No state.
- Rebuild when parent rebuilds.
#### Widget Tree (JSX --> nested widgets)
Similar to React JSX,
```html
<div>
	<h1>Hello</h1>
	<p>Welcom</p>
</div>
```
Flutter equivalent,
```dart
Column(
	Children: const [
		Text("Hello");
		Text("Welcom");
	],
)
```
- Flutter uses lists of widgets instead of children props.

#### `Scaffold`(Page layouts)
This widget provides a basic visual layout structure that implements the Material design guidelines. Acts as the backbone of the UI, offering pre-defined "slots" for common UI elements. 
Scaffold includes various properties,
- `appBar` : a horizontal bar displayed at the top of the screen used for branding, navigation, and actions. 
- `body` : the primary content area of the screen. Expands to fill the remaining available space not used by other components like the `appBar`.
- `floatingActionButton` : a circular button that floats above the UI. 
- `drawer` : A vertical panel that slides in from the side (usually the left) and is typically hidden on mobile devices, used for navigation links.
- `bottomNavigationBar` : A horizontal bar at the bottom for switching between different sections or tabs within the app.
- `bottomSheet` : A panel that slides up from the bottom of the screen to reveal additional content or options.
- `persistentFooterButton` : A list of buttons displayed at the bottom of the scaffold, persistently visible even if the body content scrolls.
- `backgroundColor` : Sets the background color for the entire scaffold.
- `resizeToAvoidBottomInset` : A property that, if set to `true`, automatically resizes the body to avoid the on-screen keyboard, ensuring focused widgets remain visible.

Ex:
```dart
Scaffold(
	appBar: AppBar(title: const Text("Home"));
	body: const Center(child: Text("Content"));
	floatingActionbutton: FloatingActionButton(
		onPress: () {},
		child: const Icon(Icon.add),
	),
);
```
#### `StatefulWidget`
Similar to React,
```ts
const [count, setCount] = useState<int>(0);
```

Flutter equivalent,
```dart
Class CounterPage extends StatefulWidget {
	const CounterPage({super.key});
	
	@override
	State<CounterPage> createState() => _CounterPageState();
}

class _CounterPageState extends State<CounterPage> {
	int count = 0;
	
	@override
	Widget build(BuildContext context) {
		return Column(
			children: [
				Text("Count: $count"),
				ElevatedButton(
					onPressed: () {
						setState(() {
							count++;
						});
					},
					child: const Text("Increment");
				),
			],
		);
	}
}
```
- `setState()` triggers rebuild, not DOM diffing. 
- UI = function of state
#### Constructor parameters
React's way,
```ts
<Profile name="John">
```

Flutter equivalent,
```dart
class Profile extends StatelessWidget {
	final String name;
	
	const Profile({super.key, required this.name});
	
	@override
	Widget build(BuildConext context) {
		return Text("Hello $name");
	}
}

//usage
Profile(name: "John")
```
#### Event handling
React's way,
```ts
<button onClick={handleClick}>Click</button>
```

Flutter's way,
```dart
ElevatedButton(
	onPressed: handleClick,
	child: const Text("Click")
);
```
#### List rendering (map --> ListView)
React's way,
```ts
{items.map(item => <li>{item}</li>)}
```
Flutter's way,
```dart
ListView(
	children: items.map((item) => Text(item)).toList(),
)
```
Flutter lazy rendering,
```dart
ListView.builder(
	itemCount: items.length,
	itemBuilder: (context, index) {
		return Text(items[index]);
	},
);
```
#### Navigation (React router --> Navigator)
```dart
Navigator.push(
	context,
	MaterialPageRoute(builder: (_) => const DetailsPage()),
);
```
Go back,
```dart
Navigator.pop(context);
```
#### Lifecycle (useEffect --> initState)
React's way,
```js
useEffect(() => {
	fetchData();
}, [])
```

Flutter's way,
```dart
@override
void initState() {
	super.initState();
	fetchData();
}
```
