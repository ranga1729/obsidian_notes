Fluent API is used to configure database models and relationships programmatically. 

The Fluent API is configured in `OnModelCreating` method of the `DbContext` class. 
```C#
public class ApplicationDbContext : DbContext
{
	public DbSet<Employee> Employees { get; set; }
	public DbSet<Department> Department { get; set; }
	
	protected override void OnModelCreating(ModelBuilder modelBuilder)
	{
		//Fluent API configurations go here
	}
}
```

****
#### Configure a Table and Column Names
```C#
protected override void OnModelCreating(ModelBuilder modelBuilder)
{
	modelBuilder.Entity<Employee>()
		.ToTable('tbl_Employees') //Custom table name
		.Property(e => e.Name)
		.HasColumnName('Emp_Name') //Custom column name
		.HasMaxLength(180) //Max length contraint
		.IsRequired(); //NOT NULL
}
```
#### Defining Primary Key
By default EF Core assumes a property named `Id` as the primary key.
But we can explicitly define it. 
```C#
modelBuilder.Entity<Employee>()
	.HasKey(e => e.EmployeeId); //custom primary key
```
#### Configuring Relationships
Support three relationships, 
1. one-to-one
```C#
// employee --> address
//Each employee has exactly one address.
modelBuilder.Entity<Employee>()
	.HasOne(e => e.Address)
	.WithOne(a => a.Employee)
	.HasForeignKey<Address>(a => a.EmployeeId);
```
2. one-to-many
```C#
//department --> employees
//A department can have multiple employees, but an employee belongs to only one department
modelBuilder.Entity<Employee>()
    .HasOne(e => e.Department) // One Employee has One Department
    .WithMany(d => d.Employees) // One Department has Many Employees
    .HasForeignKey(e => e.DepartmentId) // Foreign key in Employee table
    .OnDelete(DeleteBehavior.Cascade); // Cascade delete
```
3. many-to-many
```C#
//student <--> course
// A student can enroll in multiple courses, and a course can have multiple students.
modelBuilder.Entity<StudentCourse>()
    .HasKey(sc => new { sc.StudentId, sc.CourseId }); // Composite primary key
modelBuilder.Entity<StudentCourse>()
    .HasOne(sc => sc.Student)
    .WithMany(s => s.StudentCourses)
    .HasForeignKey(sc => sc.StudentId);
modelBuilder.Entity<StudentCourse>()
    .HasOne(sc => sc.Course)
    .WithMany(c => c.StudentCourses)
    .HasForeignKey(sc => sc.CourseId);
```
#### Configuring Indexes
```C#
modelBuilder.Entity<Employee>()
	.HasIndex(e => e.Email)
	.IsUnique(); //unique constraint
```
#### Configuring Default values for a column
```C#
modelBuilder.Entity<Employee>()
    .Property(e => e.IsActive)
    .HasDefaultValue(true);
```

****
### Relationships with Navigation Properties(Without Fluent API)
We can set relationships between tables using navigation properties, without using Fluent API.

Ex: 
```C#
public class Employee
{
    public int EmployeeId { get; set; }
    public string Name { get; set; }
    public int DepartmentId { get; set; } // Foreign Key
    public Department Department { get; set; } // Navigation Property
}
public class Department
{
    public int DepartmentId { get; set; }
    public string DepartmentName { get; set; }
    public ICollection<Employee> Employees { get; set; } // Navigation Property
}
```

> [!NOTE]
> **EF Core automatically detects** `DepartmentId` as the **foreign key** and sets up a **one-to-many** relationship.

- Here, EF Core assumes the foreign key should be named `DepartmentID`. If your database has a different column name(ex: `Dept_Id`), Fluent API is needed.
```C#
modelBuilder.Entity<Employee>()
    .HasOne(e => e.Department)
    .WithMany(d => d.Employees)
    .HasForeignKey(e => e.DeptId); // Custom FK name
```
