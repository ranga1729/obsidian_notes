EF Core follows convention-based configuration. 
It automatically infers 
	relationships,
	primary keys,
	table structures 
based on naming conventions and property types.
This reduce the need for Fluent API or annotations unless customization is required. 

##### 1. Primary key convention
EF Core automatically assumes that a property named `Id` or `<EntityName>Id`(ex: `DepartmentId`) is the **Primary key**.
```C#
public class Employee
{
	public int Id { get; set; } //PK(by convention)
}
```
If your primary key is not named `Id` or `<EntityName>Id`, you must configure it using Fluent API,
```C#
modelBuilder.Entity<Employee>
	.HasKey(e => e.EmployeeNumber)
```

##### 2. Foreign key convention
EF Core automatically detects foreign keys if, 
- A property follows the `<RelatedentityName>Id` naming pattern 
AND
- A navigation property exist.
```C#
public class Employee
{
    public int Id { get; set; }
    public string Name { get; set; }
    
    public int DepartmentId { get; set; }  // FK (by convention)
    public Department Department { get; set; }  // Navigation Property
}
```

If it doesn't follow `<RelatedentityName>Id` pattern,
```C#
public class Employee
{
    public int Id { get; set; }
    public int DeptCode { get; set; }  // Not following convention
    public Department Department { get; set; } // navigation property is still there.
}
// Fluent API required
modelBuilder.Entity<Employee>()
    .HasOne(e => e.Department)
    .WithMany(d => d.Employees)
    .HasForeignKey(e => e.DeptCode);
```
##### 3. One-to-Many relationship convention
EF Core assumes a one-to-many relationship, if entity has a collection navigation property.
```C#
public class Department
{
    public int Id { get; set; }
    public string Name { get; set; }
    public ICollection<Employee> Employees { get; set; } // One-to-Many
}
```
EF core assumes,
	One `Department` can have many `Employees`
	One `Employee` belongs to one `Department`
- If no `DepartmentId` exists in `Employee`, EF Core adds a **shadow property** automatically.
##### 4. One-to-One relationship convention
EF Core assumes a one-to-one relationship when,
- Both entities have navigation properties pointing to each other. 
- One them has a foreign key that is also the primary key.
```C#
public class Employee
{
	public int Id { get; set; } //PK
	public EmployeeAddress Address { get; set; } //one-to-one
}
public class EmployeeAddress
{
	public int Id { get; set; } //PK & FK
	public Employee Employee { get; set; }
}
```
- EF Core sets `EmployeeAddress.Id` as both PK & FK.
##### 5. Many-to-Many relationship convention
- EF automatically recognizes many-to-many relationship without a join entity.
```C#
public class Student
{
	public int Id { get; set; }
	public string Name { get; set; }
	public ICollection<Course> Courses { get; set; }
}

public class Course
{
	public int Id { get; set; }
	public string Title { get; set; }
	public ICollection<Student> Student { get; set; }
}
```
- EF Core automatically creates a hidden join table named `StudentCourse`
- If you want a custom join table, use Fluent API.
##### 6. Table & Column Name Convention
EF Core maps classes to tables and properties to columns automatically.
Ex: 
```C#
public class Employee
{
	public int Id { get; set; }
	public string FirstName { get; set; }
}
```
This above class generates this tables,
```mysql
CREATE TABLE Employees (
	Id INT PRIMARY KEY,
	FirstName VARCHAR(MAX)
)
```
##### 7. Default data Types
EF Core assign SQL data types based on C# property types,

| C# Type  | SQL Type(Default) |
| -------- | ----------------- |
| int      | INT               |
| string   | VARCHAR(MAX)      |
| bool     | BIT               |
| decimal  | DECIMAL(18,2)     |
| DataTime | DATETIME          |
*****
Summary,

|**Feature**|**Convention (Automatic)**|**Fluent API Required?**|
|---|---|---|
|**Primary Key (`Id` or `<EntityName>Id`)**|✅ Yes|❌ No|
|**Foreign Key (`<EntityName>Id`)**|✅ Yes|❌ No|
|**One-to-Many Relationship**|✅ Yes|❌ No|
|**One-to-One (FK = PK)**|✅ Yes|❌ No|
|**Many-to-Many (EF Core 5+)**|✅ Yes|❌ No|
|**Custom Foreign Key Name**|❌ No|✅ Yes|
|**Custom Table or Column Name**|❌ No|✅ Yes|
|**Cascade Delete Behavior**|❌ No|✅ Yes|
|**Custom Indexes**|❌ No|✅ Yes|
|**Default Values**|❌ No|✅ Yes|
