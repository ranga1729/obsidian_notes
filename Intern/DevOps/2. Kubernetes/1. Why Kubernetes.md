#### Microservices Architecture
![[Pasted image 20250430090414.png]]
A software design approach where an application is built as a collection of small, independent services, each responsible for a specific business function.

Key features,
- Modularity : Each microservice handles one function.
	Ex: User service, payment service
- Independent deployment : Services can be updated or scaled independently. 
- Technology flexibility : Different services can use different programming languages or databases.
- Resilience : A failure in one service doesn't crash the entire application.
- improved Scalability : Individual services can scale based on their needs.

It's commonly used with containers and orchestration tools.
*****
In a enterprises level application, there may be 10, 50, 100 or 1000s of containers.
With increasing number of containers and increasing complexity of the application, managing all these containers can become highly complex.

Managing means,
- Downtime management/accessibility management. (ex: Make down containers run again.)
- Manage scalability. (ex: Make couple of instances of a same service.)
- Backup & restore, Disaster recovery (ex: Database issues)

This the fundamental requirement of "Container Orchestration". 

Most widely used container orchestration tool is Kubernetes(K8)
