Dependency hell arise when managing project dependencies becomes overly complex or unmanageable. 

Reasons,
1. Conflicting versions
	Two or more packages requires different versions of the same dependency. 
	Ex: 
		package A needs `library-x@1.2`
		package A needs `library-x@2.0`
2. Deep dependency Trees
	Some tools or libraries depends on many other libraries. This creates a long chain of dependencies where a change or conflict deep down can break everything.
3. Incompatible Updates
	When one dependency gets updated, it might not be compatible with others still relying on the older version.
4. Environment Inconsistencies
	Work on one machine but not on another machine due the platform differences.

Solutions to Dependency hells,
1. Virtual Machines (ex: VMWare)
2. Containers (ex: Docker, Podman)

##### Virtual Machines
Hypervisor is the software that runs and manages multiple VMs on a host system. Each VM runs its own full operating system(Guest OS). VMs are isolated from one another and emulate entire machines. Each app runs on this Guest OSs has their own binaries and libraries(dependencies). 
Multiple OS increases the overhear. 
Great for running different OSes on the same hardware. 
##### Containers
Unlike the VMs have different Guest OSes, the computer we run our containers also has a Operating system but it's shared across all containers. 
Container engine(ex: Docker) responsible for managing and runs containers.
Containers include apps and their dependencies.

Containers doesn't require you to install separate OSes and it allows to run several container application on a shared OS.
Everything is managed by the container engine.

| Aspect          | Virtual Machines           | Containers                       |
| --------------- | -------------------------- | -------------------------------- |
| OS per instance | Yes (Guest OS for each)    | No (Shared host OS)              |
| Resource usage  | Heavier                    | Lighter                          |
| Boot time       | Slow (minutes)             | Fast (seconds)                   |
| Isolation       | Strong (full OS isolation) | Moderate (process-level)         |
| Use case        | Run multiple OS types      | Run multiple apps in the same OS |

#### What is container ?
A container is a lightweight, standalone, executable package of software that includes everything needed to run an application,
- The application code
- Runtime
- System tools
- Libraries
- Settings
Containers are often used to **deploy and scale applications** quickly across different environments (like development, testing, and production), without worrying about differences in infrastructure or operating systems.

Benefits,
- Portability : Runs everywhere.
- Scalability : Easily scale up/down depending on demand.
- Isolation : Apps don't interfere with each other.
- Speed : Start up in seconds.
- Efficiency : Use fewer resources than full VMs.

What can be done with Docker ?
1. Application Packaging : Bundle your app and it's dependencies into a single container. 
2. Multi-container application : Use tools like 'Docker Compose' to manage complex apps. (ex: Web apps with databases)
3. CI/CD Pipeline : Automate build, and deployment workflows.
4. Cloud deployment : Run containerizations seamlessly on cloud platforms. 
5. Testing and Debugging : Create isolated environment for testing without affecting the host system.
