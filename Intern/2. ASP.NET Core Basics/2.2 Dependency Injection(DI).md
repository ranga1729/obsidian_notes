- A design pattern.
- Used to achieve **"Inversion of Control(IoC)"**.
- Allows to decouple classes from their dependencies, making the code more modular, testable and maintainable.
![[Pasted image 20250309230841.png]]

**It's a way to provide the dependencies(ex: services, objects) that a class needs, rather than having the class create them itself. This is done by 'injecting' the dependency into the class, typically through its constructor, properties or methods.**

- DI is built into the ASP.NET Core. It provides a built-in **DI Container** that manages the creation and lifetime of dependencies. 

Key concepts,
1. **Dependency**
	A dependency is an object that another object relies on to perform its work. 
	Ex: If class A uses an instance of class B to function, B is a dependency of A.
	![[Pasted image 20250309230855.png]]
2. **Inversion of Control(IoC)**
	Instead of class creating its own dependency(using `new` keyword), the dependencies are provided to the class from an external source.(ex: DI container)
3. **DI Container**
	A framework that manages the creation and injection of dependencies in .NET.
	Built-in `Microsoft.Extensions.DependencyInjection` library is used commonly.
4. **Service lifetime**
	The DI container manages the lifetime of dependencies, ensuring they are created and disposed of appropriately.
	Common lifetime Types,
	1. **Transient** : A new instance is created every time the service in requested.
	2. **Scoped** : A new instance is created once per request(HTTP request)
	3. **Singleton** : A single instance is created and shared for the entire application lifetime. 

****

Steps of Dependency Injection,
1. **Define Dependency**
Typically defined as interfaces or abstract classes.
```C#
public interfce IMessageService
{
	void SendMessage(string message);
}

public class EmailService:IMessageSerivce
{
	public void SendMessage(string message)
	{
		Console.WriteLine($"Email send: {message}");
	}
}
```
2. **Register Dependency**
Register dependencies with the DI container, usually in the `Program` class.
```C#
public class Program
{
	public void ConfigureService(IServiceCollection services)
	{
		services.AddTransient<IMessageService, EmailService>();
	}
}
```
3. **Inject Dependencies**
Dependencies are injected into classes via constructors, methods or properties.
(Constructor injection is the most common way.)
```C#
public class NotificationService
{
	private readonly IMessageService _messageService;
	
	//constructor injection
	public NotificationService(IMessageService messageService)
	{
		_messageService = messageService;
	}
	public void Notify(string message)
	{
		_messageService.SendMessage(message);
	}
}
```
4. **Resolve Dependencies**
The DI container automatically resolves and injects the dependencies when a class is instantiated 
Ex: In ASP.NET Core, the framework handles this for controllers and services.

##### What happens when we request an instance of `NotificationService` ?
1. Somewhere in the application,  a class or a controller requests an instance of `NotificationService`, such as,
```C#
var notificationService = serviceProvider.GetService<NotificationService>();
```
The `serviceProvider`(built automatically by ASP.NET) is responsible for resolving dependencies.

2. The DI container inspect `NotificationService` and sees that is has a constructor dependency on `IMessageService`.
```C#
public NotificationService(IMessageService messageService)
```

3. The container check if `IMessageService` is registered and finds that `EmailService` is mapped to it. 
```C#
services.AddTransient<IMessageService, EmailService>();
```

4. The DI container then creates a new instance of `ÈmailService`
5. Pass this `EmailService` object into the constructor of `NotificationService`.
6. Returns a fully constructed `NotificationService` instance.


> [!NOTE] Important
> ```C#
> notificationService.Notify("Hello!");
> ```
> will internally call,
> ```C#
> _messageService.SendMessage("Hello!");
> ```

****
#### Benefits of Dependency injection in .NET,
1. Loose coupling
	Classes depends on abstraction(interfaces) rather than concrete implementations. 
	It makes the system more modular. 
2. Testability
	Dependencies can easily be mocked or replaced during the unit testing.
3. Maintainability
	Centralize dependency management makes it easier to changes implementations without modifying dependent classes.
4. Scalability
	Promotes better organization, separation of concerns, making the application easier to scale.

****
Full examples,
```C#
// Define an interface and its implementation
public interface IGreetingService
{
    string GetGreeting();
}

public class GreetingService : IGreetingService
{
    public string GetGreeting()
    {
        return "Hello, Dependency Injection!";
    }
}

// Register the service in Program.cs
public class Program
{
    public void ConfigureServices(IServiceCollection services)
    {
        services.AddTransient<IGreetingService, GreetingService>();
    }
}

// Inject the service into a controller
[ApiController]
[Route("[controller]")]
public class GreetingController : ControllerBase
{
    private readonly IGreetingService _greetingService;

    public GreetingController(IGreetingService greetingService)
    {
        _greetingService = greetingService;
    }

    [HttpGet]
    public string Get()
    {
        return _greetingService.GetGreeting();
    }
}
```
