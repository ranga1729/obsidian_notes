- A design pattern.
- Used to achieve **"Inversion of Control(IoC)"**.
- Allows to decouple classes from their dependencies, making the code more modular, testable and maintainable.
![[Pasted image 20250309230841.png]]

**It's a way to provide the dependencies(ex: services, objects) that a class needs, rather than having the class create them itself. This is done by 'injecting' the dependency into the class, typically through its constructor, properties or methods.**

- DI is built into the ASP.NET Core. It provides a built-in **DI Container** that manages the creation and lifetime of dependencies. 

Key concepts,
1. **Dependency**
	A dependency is an object that another object relies on to perform its work. 
	Ex: If class A uses an instance of class B to function, B is a dependency of A.
	![[Pasted image 20250309230855.png]]
2. **Inversion of Control(IoC)**
	Instead of class creating its own dependency(using `new` keyword), the dependencies are provided to the class from an external source.(ex: DI container)
3. **DI Container**
	A framework that manages the creation and injection of dependencies in .NET.
	Built-in `Microsoft.Extensions.DependencyInjection` library is used commonly.
4. **Service lifetime**
	The DI container manages the lifetime of dependencies, ensuring they are created and disposed of appropriately.
	Common lifetime Types,
	1. **Transient** : A new instance is created every time the service in requested.
	2. **Scoped** : A new instance is created once per request(HTTP request)
	3. **Singleton** : A single instance is created and shared for the entire application lifetime.
