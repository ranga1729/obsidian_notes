##### `ifconfig` (Interface Configuration)
Using this commands you can,
- View network interface details(ip addresses, MAC addresses, MTU sizes)
- Bring interfaces up/down(`ifconfig eth0 up`)
- Assign IP addresses manually
![[Pasted image 20250922103329.png]]
- `eth0` : Wired Ethernet interface
- `lo` : Loopback interface(uses for localhost communication)
- `wlan0`: Wireless interface

Breakdown the output,
`wlan0: flags=4163<UP,BROADCAST,RUNNING,MULTICAST> mtu 1500`
- `wlan0` is the name of the interface.
- `flag=4163` : a numeric bitmask representing interface status. The human-readable flags inside `< >`,
	`UP` : Interface is enabled
	`BROADCAST`: Support broadcast communication
	`RUNNING` : Carrier signal is detected(connected)
	`MULTICAST`: Support multicast
- `mtu 1500` : Maximum Transmission Unit = 1500 bytes per packet.

`inet 10.33.70.191 netmask 255.255.192.0 broadcast 10.33.127.255`
- `inet`: IPv4 address assigned by DHCP.
- `netmask`: Subnet mask(you are in 10.33.64.0/18 network)
- `boradcast`: Boradcast address of your subnet.

`inet6 fe80::7c5e:50c7:f2aa:ea2b prefixlen 64 scopeid 0x20<link>`
- `inet6` : IPv6 link-local address(automatically assigned)

`ether 98:22:ef:a2:29:a9` --> MAC address of your Wi-Fi card.
`txqueuelen 1000` --> Queue length
`RX packets808639 bytes 223080272 (212.7 MiB)` --> Amount of data received.
`TX packets 43820 bytes 13907695 (13.2 MiB)` --> Amount of data transmitted.
`Tx errors 0 dropped 29 overrun 0 carrier 0 collision 0` --> Major transmission errors.


> [!NOTE] Multicast vs Broadcast
> Broadcast : Sends a packet to all devices in the local network segment(subnet)
> 	Ex: ARP requests, DHCP discover messages
> Multicast : Sends a packet to a specific group of devices that have joined a multicast group. 
> 	Ex: Video streaming, IPTV, Conferencing, Routing protocols like OSPF 

> [!NOTE] TX Queue Length
> `txqueuelen` = Transmission Queue Length
> TX queue is a buffer where outgoing packets wait before being sent to the network card. 
> `txqueuelen 1000` means it can hold 1000 packets in the buffer before dropping new ones. 
> -
> If too many packets arrive at once, they queue up here. If the queue fills up, new packets will be dropped, causing network lag or re-transmissions.
> For high-throughput interfaces, you might increase this length to prevent packet loss under heavy load. 
##### Errors, Drops, Overruns

| Filed           | Meaning                                                            | Cause                                                                  |
| --------------- | ------------------------------------------------------------------ | ---------------------------------------------------------------------- |
| errors          | Packets with errors                                                | CRC errors, brad framing, corrupted packets, bad cables, driver issues |
| dropped         | Packets that were intentionally dropped by the kernel or interface | congestion, buffer overflow, firewall rules                            |
| overruns        | Packet lost because buffer could not be emptied fast enough        | The network card received packets faster than CPU/driver could handle. |
| frame(for RX)   | Framing errors(bad Ethernet frames)                                | Mismatched duplex settings, interference.                              |
| carrier(for TX) | Carrier-sense errors                                               | Cable unplugged, network card not detecting link properly.             |
| collisions      | Number of Ethernet collisions detected.                            | Mostly relevant in half duplex networks                                |
