# Intruders
Often referred to as a hacker or cracker. 
Classes of intruders,
- Masquerader 
- Misfeasor
- Clandestine user

Intruder behavior patterns, 
1. Hacker
	- Select the target using IP lookup tools such as `NSLookup`, `Dig`, ...
	- Map network for accessible services using tools such as `NMAP`. 
	- Identify potential vulnerabilities. 
	- Brute force passwords. 
	- Install remote administrator tools.
	- Wait for a admin to log on and capture his password. 
	- Use that password to access remainder of network.
2. Criminal enterprise
	- Act quickly and precisely to make their activities harder to detect. 
	- Exploit perimeter through vulnerable port. 
	- Use trojan horses to leave back doors for re-entry. 
	- Use sniffers to capture passwords. 
	- Do not stick around until noticed. 
	- Make few or no mistakes. 
3. Internal Threat
	- Create network accounts for themselves and their friends. 
	- Access account and applications they wouldn't normally use their daily jobs. 
	- Email former and prospective employers. 
	- Conduct furtive instant-messaging chats. 
	- Visiting websites catering to disgruntled employees
	- Performing large downloads and copying files.
	- Accessing the network during off-hours

#### Intrusion Techniques
Objectives of an intruder,
1. Gain access to a system
2. Increase the range of privileges accessible on a system

Most of the attacks use system or software vulnerabilities that allows users to execute code that opens a back door into the system. 

Intruders may try to get passwords. Two ways to protect them,
1. One-way function(password hashing. nor plaintext passwords stored)
2. Access control

Techniques used to guess password by hackers,
- Default passwords come with the system. 
- Exhaustively try all short passwords. 
- Try likely passwords. 
- Gather information about users such as full names, spouse names, children names, birthdays, phone numbers, social sec numbers, room numbers, license plates, pet names. 
- Use a trojan horse to bypass restrictions on access.
- Man-in-the-Middle attacks. 
# Intrusion Detection
If an intrusion is detected quickly, it must be ejected from the system before any damage can happen. 

Intrusion detection approaches, 
1. Statistical anomaly detection
	- **Threshold detection**: Define a specific numerical limit (a threshold) for a system metric such as CPU usage, the number of failed login attempts, or bandwidth consumption. If the activity metric crosses this predefined value (ex: more than 50 failed logins in one minute), the system triggers an alert.
	- **Profile based**: creates a baseline "normal" behavior profile for users, hosts, or network segments by observing activity over a period of time. The system calculates statistical distributions (such as mean, variance, or frequency) for normal operations. It then monitors live traffic; if the current activity deviates significantly from the established profile (e.g., a user accessing files at 3:00 AM who normally only works 9-5), it is flagged as an anomaly.
2. Rule-based
	- **Anomaly detection**: The system explicitly defines behaviors or sequences of events that are known to be anomalous or malicious. If the system encounters an event that matches a signature or rule describing an known attack vector (ex: a specific byte sequence associated with a buffer overflow exploit), it triggers an alert.
	- **Penetration identification**: Rather than looking for a single malicious packet, it monitors for a sequence of events such as unauthorized port scanning, followed by privilege escalation, and ending in lateral movement. It uses logic-based rules to reconstruct the "chain" of a penetration event.

#### Audit Records

Each audit log contains the following fields,
- Subject
- Action
- Object

- Resource-Usage
- Time-Stamp

#### Statistical Anomaly Detection
- Threshold analysis is ineffective for sophisticated attacks. 
- Profile-based anomaly detection focuses on characterizing the past behavior of individual users or related groups of users and then detecting significant deviations.
- The foundation of profile-based anomaly detection approach is an analysis of audit records.

How audit records provide input to the intrusion detection function,
1. Network admin must decide on a number of quantitative metrics that can be used to measure user behavior. An analysis of audit records over a period of time can be used to determine that activity profile of the average user.  
2. Current audit records are the input used to detect intrusion.

Examples of metrics useful for profile-based intrusion detection,  
- Counter
- Gauge
- Interval timer
- resource utilization
Using these details, we can run various tests to derive insights like,
- Mean and standard deviation
- Multivariate
- Markov process
- Time series
- Operational

#### Rule-Based Intrusion Detection
Detect intrusion by observing events in the system and applying a set of rules that lead to a decision regarding whether a given pattern is suspicious or is not. 
Heuristic rules that can be used for this. 
Ex:
- Users should not read/write files in other user's personal directories.
- Users who login after hours often access the same files they used earlier.  
- Users do not generally open disk devices directly but rely on higher-level operating system utilities.
- Users should not be logged in more than once to the same system.
- Users do not make copies of system programs.

#### The Base-Rate Fallacy
It's a statistical paradox where the high false-alarm rate of a system renders its alerts essentially meaningless, even if the system has a high detection accuracy.
It occurs because the **base rate** (the actual frequency of attacks occurring) is extremely low compared to the volume of normal traffic.

### Distributed Intrusion Detection 
A **Distributed Intrusion Detection System (DIDS)** is a security architecture that decentralizes the monitoring, analysis, and reporting functions across multiple geographically or logically separated network segments. Instead of relying on a single, centralized appliance to inspect all traffic, a DIDS distributes detection components throughout the infrastructure.

Components, 
- Sensors: Lightweight software agents or hardware probes deployed at various points in the network
- Analyzers(Detectors): components receive data from the sensors. Applying rules or statistical models to identify malicious patterns. In a distributed model, some analysis happens locally at the sensor (edge computing), while more complex correlation happens at higher nodes.
- Manager(Central Controller): Central node aggregates findings from various analyzers. provides a global view of the network security posture, coordinates responses, and enables centralized policy management.

Issues of Distributed Intrusion Detection System: 
1. Have to deal with different audit record formats. 
2. Raw audit data or summary data must be transmitted across the network. (integrity and confidentiality must be assured)

#### Honeypots
Honeypots are decoy systems that are designed to lure a potential attacker away from critical systems. These are designed to,
- Divert attacker from accessing critical systems
- Collect information about the attackers activity. 
- Encourage the attacker to stay on the system long enough for administrators to respond
These systems are filled with fabricated information designed to appear valuable but that a legitimate user of the system wouldn’t access. Thus, any access to the honeypot is suspect.

In addition to intrusion prevention, such a system would do these,
- Dropping malicious packets
- Blacklisting malicious sources
- Resetting malicious network connections
- Configuring firewalls to prevent future attacks

# Firewalls
A **firewall** is a network security device either hardware or software—that monitors and filters incoming and outgoing network traffic based on an organization's previously established security policies. It acts as a barrier between a trusted internal network (such as a home or office LAN) and an untrusted external network (typically the internet).

Design goals of Firewall,
1. Packet filtering: Inspects individual packets in isolation. All traffic from inside to outside and vise versa must pass through the firewall.
2. Stateful inspection: Firewall tracks the "state" of active network connections (e.g., TCP streams). It knows if a packet is part of an existing, established conversation or if it is an unsolicited attempt to open a new connection.
3. Application Layer filtering(proxy): The firewall inspects the actual data payload of the traffic (Layer 7 of the OSI model). It can understand specific application protocols, like HTTP or FTP, and identify if the commands within those protocols are malicious, even if the connection itself seems legitimate.

Core functions,
1. Access control
2. Logging and Auditing
3. Network Address Translation(NAT)
4. VPN Integration

Techniques used by firewalls for access controlling, 
1. Service control
2. Direction control
3. User control
4. Behavior control

Types of firewalls,
1. Packet Filtering firewalls
2. Stateful Inspection Firewalls
3. Application-Level Gateway
4. Circuit-Level Gateway
#### Bastion Host
A specialized computer on a network specifically designed to withstand attacks. It is often placed at the "base" of the network perimeter usually in a DMZ (Demilitarized Zone) to act as a gateway between the public internet and the internal private network.

It is the only point of contact from the outside world. All incoming traffic must pass through the bastion host, which is heavily hardened (all unnecessary services are removed, and security software is strictly configured) to minimize the attack surface.

If an intruder attempts to penetrate the network, they must first compromise the bastion host. Because it is highly restricted and monitored, the chances of a successful breach are minimized.
#### Host-based Firewall
A software module installed in an individual host. Available in many operating systems or can be provided as an add-on package.
#### Personal Firewall
A personal firewall controls the traffic between a personal computer or workstation on one side and the Internet or enterprise network on the other side.
#### Demilitarization Zone(DMZ)
![[Pasted image 20260601232517.png]]
**Demilitarized Zone (DMZ)** is a physical or logical subnetwork that acts as a buffer zone between an organization’s secure internal network and the untrusted external network, usually the internet. 

The primary goal of a DMZ is to allow an organization to provide public-facing services (like a web server or email server) while ensuring that an intruder who successfully compromises those services cannot gain direct access to the private, internal network.

How this works :
A network administrator places public-facing servers in the DMZ. These servers are accessible from the internet, but they are isolated from the internal network by security controls (typically firewalls).
- **The Outer Firewall:** Sits between the internet and the DMZ. It allows public traffic to reach the servers in the DMZ but blocks unauthorized traffic from entering the internal network.
- **The Inner Firewall:** Sits between the DMZ and the internal network. It provides a second layer of defense, ensuring that if a server inside the DMZ is compromised, the attacker still cannot reach the sensitive data (like employee records or financial databases) stored inside the internal network.

#### Distributed Firewalls
![[Pasted image 20260601234510.png]]
A network security architecture where the firewall functionality is pushed out from a centralized gateway and integrated directly into individual host endpoint, virtual machines or containers.

Rather than relying on one perimeter firewall to inspect all traffic, a distributed firewall places a "mini-firewall" at every node in the system. It involves stand-alone firewall devices plus host- based firewalls working together under a central administrative control. 

#### Unified Threat Management
Unified Threat Management (UTM) is a single device or a service which provides multiple security features and services on the network.
It protects the users of the network from numerous security threats. 
It is also known as Next-Generation Firewalls. 
It includes features such as anti-virus, anti-spam, content filtering, web filtering and so on. 

#### Data Leakage Prevention (DLP) 
It is the process of detection and prevention of data breaches and leakages. Companies used this mechanisms to protect and secure their valuable data.

#### Deep Packet Inspection (DPI) 
It can be a hardware or software system. It uses known intrusion signatures to detect abnormal network traffic.
