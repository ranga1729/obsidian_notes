# Intruders
Often referred to as a hacker or cracker. 
Classes of intruders,
- Masquerader 
- Misfeasor
- Clandestine user

Intruder behavior patterns, 
1. Hacker
	- Select the target using IP lookup tools such as `NSLookup`, `Dig`, ...
	- Map network for accessible services using tools such as `NMAP`. 
	- Identify potential vulnerabilities. 
	- Brute force passwords. 
	- Install remote administrator tools.
	- Wait for a admin to log on and capture his password. 
	- Use that password to access remainder of network.
2. Criminal enterprise
	- Act quickly and precisely to make their activities harder to detect. 
	- Exploit perimeter through vulnerable port. 
	- Use trojan horses to leave back doors for re-entry. 
	- Use sniffers to capture passwords. 
	- Do not stick around until noticed. 
	- Make few or no mistakes. 
3. Internal Threat
	- Create network accounts for themselves and their friends. 
	- Access account and applications they wouldn't normally use their daily jobs. 
	- Email former and prospective employers. 
	- Conduct furtive instant-messaging chats. 
	- Visiting websites catering to disgruntled employees
	- Performing large downloads and copying files.
	- Accessing the network during off-hours

#### Intrusion Techniques
Objectives of an intruder,
1. Gain access to a system
2. Increase the range of privileges accessible on a system

Most of the attacks use system or software vulnerabilities that allows users to execute code that opens a back door into the system. 

Intruders may try to get passwords. Two ways to protect them,
1. One-way function(password hashing. nor plaintext passwords stored)
2. Access control

Techniques used to guess password by hackers,
- Default passwords come with the system. 
- Exhaustively try all short passwords. 
- Try likely passwords. 
- Gather information about users such as full names, spouse names, children names, birthdays, phone numbers, social sec numbers, room numbers, license plates, pet names. 
- Use a trojan horse to bypass restrictions on access.
- Man-in-the-Middle attacks. 
# Intrusion Detection
If an intrusion is detected quickly, it must be ejected from the system before any damage can happen. 

Intrusion detection approaches, 
1. Statistical anomaly detection
	- **Threshold detection**: Define a specific numerical limit (a threshold) for a system metric such as CPU usage, the number of failed login attempts, or bandwidth consumption. If the activity metric crosses this predefined value (ex: more than 50 failed logins in one minute), the system triggers an alert.
	- **Profile based**: creates a baseline "normal" behavior profile for users, hosts, or network segments by observing activity over a period of time. The system calculates statistical distributions (such as mean, variance, or frequency) for normal operations. It then monitors live traffic; if the current activity deviates significantly from the established profile (e.g., a user accessing files at 3:00 AM who normally only works 9-5), it is flagged as an anomaly.
2. Rule-based
	- **Anomaly detection**: The system explicitly defines behaviors or sequences of events that are known to be anomalous or malicious. If the system encounters an event that matches a signature or rule describing an known attack vector (ex: a specific byte sequence associated with a buffer overflow exploit), it triggers an alert.
	- **Penetration identification**: Rather than looking for a single malicious packet, it monitors for a sequence of events such as unauthorized port scanning, followed by privilege escalation, and ending in lateral movement. It uses logic-based rules to reconstruct the "chain" of a penetration event.

#### Audit Records
Audit records are a fundamental source to identify intrusion entries.
Each audit log contains the following fields,
- Subject
- Action
- Object
- Exception-Condition
- Resource-Usage
- Time-Stamp

#### Statistical Anomaly Detection
- Threshold analysis is ineffective for sophisticated attacks. 
- Profile-based anomaly detection focuses on characterizing the past behavior of individual users or related groups of users and then detecting significant deviations.
