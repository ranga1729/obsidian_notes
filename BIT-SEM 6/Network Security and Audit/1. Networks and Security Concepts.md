## Computer Security Concepts
Pillars of computer security is,
- Confidentiality - Controlling access to information.
- Integrity - Preventing improper information modification/destruction.
- Availability - Ensuring timely and reliable access information. 
- Authenticity - Confidence in validity of information.
- Accountability - Ensuring that actions on a system can be uniquely traced to a specific entity(user, process, device, ...)

## The OSI Security Architecture
The **"OSI Security Architecture"** is a systematic framework used to provide security in a network environment, defined by the **"International Telecommunication Union(ITU)"*** and originally called **"X.800 Security Architecture"** for the OSI model. 


The architecture is built around three pillars,
1. Security Attacks - Actions compromise security of information owned by an organization. 
	Two types,
	- Passive Attacks - Monitoring or eavesdropping on transmission to obtain information without alerting. (ex: Traffic analysis)
	- Active Attacks - Modification of data streams or creation of false streams. (ex: DoS, Data modification, replay attacks)
2. Security Services - A processing or a communication service provided by a system to give specific kind of protection to resources. X.800 defines five categories of services,
	- Authentication : Ensure the communicating entity if who it claims to be.
	- Access control : Limit and control the access to host systems 
	- Data confidentiality : Protect data from unauthorized disclosures
	- Data integrity : Ensure no data modification took place
	- Non-repudiation : Prevents either sender or receiver from denying a transmitted message
3. Security Mechanism - Technical methods or processes designed to detect, prevent or recover from a security attack. Categories,
	- Specific security mechanisms - ex: encryption, digital signatures, traffic padding.
	- Pervasive security mechanism - ex: trusted functionalities(Security levels assigned to hardware or software), security audit trails, event detection. 

**Specific Security Mechanisms :**
Incorporated into the appropriate protocol layer to provide specific security services.
1. Traffic padding - Insert dummy into communication streams to mask data patterns.
2. Routing control - Control the physical/logical paths that data packets take between sender and receiver. 
3. Notarization - Use of a trusted third-party to validate communication/data security. 

**Pervasive Security Mechanisms :**
Mechanism that are not specific to any particular OSI security service or protocol layer. 
1. Trusted Functionality - Mechanisms perceived to be correct with respect to some criteria(ex: established security policies)
2. Security Label - Labeling resources with their names and security  attributes. 
3. Event Detection - Detecting security related events. 
4. Security Audit Trails - Independent review and examination of system records and activities.
5. Security Recovery

## Fundamental Security Design Principle
The National Centers of Academic Excellence in Information Assurance/Cyber Defense list these principles,
- Economy of Mechanism
- Fail-safe defaults
- Complete mediation
- Open design
- Separation of privilege
- Least privilege
- Least Common mechanism
- Psychological acceptability
- Isolation, Encapsulation
- Modularity
- Layering
- Least astonishment

1. Economy of Mechanisms : Security mechanisms(both software and hardware) should be as small and simple as possible.
2. Fail-safe defaults : Access decisions should be based on permission rather than exclusion.
3. Complete mediation : Every access must be checked against the access control mechanism/policies even for users who have been previously authenticated.(Don't use cache) 
4. Open design: Design of the security mechanism should be open rather than secret. 
5. Separation of privilege: Requires multiple conditions to be met before access is granted. 
6. Least privilege: Users, systems, programs are granted only the minimum level of access necessary to perform their specific tasks. 
7. Least common mechanism: Minimizing the amount of shared resources/mechanisms used by different users, processes, or components. 
8. Psychological acceptability: Security mechanisms should not interfere unduly with the work of users, while at the same time facilitating security purposes. 
9. Isolation: Public access systems should be isolated from critical resources. 
10. Encapsulation: Wrapping data and methods within a single unit to restrict direct access.
11. Modularity: Practice of braking down complex security systems into smaller, independent, and interchangeable components. 
12. Layering: Use of multiple, overlapping protection approaches addressing the people, technology, and operational aspects of information systems.
13. Least astonishment: The system should be intuitive, predictable, and matched the user's expectations. 
## Attack surfaces
Attack surface : Reachable and exploitable vulnerabilities in a system.
Ex:
- Open port in a web and servers
- Services available on inside of a firewall
- Code that processing incoming data, email, XML, office docs and industry specific custom data exchange formats. 
- Interfaces, SQL and web forms
- An employee with access to sensitive information vulnerable to a social engineering attack. 

Attack surface categories,
1. Network attack surfaces
	Vulnerabilities on the network.
	ex: network protocol vulnerabilities, DoS attacks, intruder attacks, communication disruptions
2. Software attack surface
	Vulnerabilities in applications, utility, OS
3. Human attack surface
	Created by personnel of outsiders.
	ex: social engineering attacks, human errors, trusted insiders

## Attack Trees
Attack tree is a branching, hierarchical data structure represents a set of potential techniques for exploiting security vulnerabilities.

Node - Goal of the attack
Branches - Ways that an attacker could reach that goal are iteratively and incrementally represented as branches.
Sub-nodes - subgoals(each sub-goal may have its own set of further subgoals).
Leaf nodes - Different ways to initiate an attack.
Each node other than a leaf is either an AND node or an OR node.

## A Model for Network Security
This is a fundamental network security model designed to protect messages transmitted between two parties.  The model involves a **sender** transmitting a message to a recipient through an insecure information channel. To ensure confidentiality and integrity, a **security-related transformation** (such as encryption) is applied to the message using **secret information** (like keys)
![[Pasted image 20260514170622.png]]
This model shows there are four basic tasks in designing a security service,
1. Create the Code: Design a strong "security-related transformation" (like encryption) that an opponent cannot break.
2. Make the Key: Generate the "secret information" (the keys) needed to make the code work.
3. Share the Key: Figure out a safe way to get that secret information to both the sender and the recipient(often using a "Trusted third party")
4. Set the Rules: Establish a "protocol" (a clear set of steps) so both parties know exactly how to use the code and the key together to keep the message safe.
## Standards
Organizations involved in the development of security standards,

	A US federal agency.
