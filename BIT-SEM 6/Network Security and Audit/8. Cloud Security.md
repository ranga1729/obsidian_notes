Essential characteristics of cloud computing,
1. Broad network access 
	Capabilities are available over the network. 
2. Rapid elasticity
	Ability to expand and reduce resources according to specific service requirement.
3. Measured service
	Resource usage can be monitored, controlled, and reported, providing transparency for both the provider and consumer of the utilized service.
4. On-demand self-service
	A consumer can unilaterally provision computing capabilities, such as server time and network storage, as needed automatically without requiring human interaction with each service provider.
5. Resource pooling
	The provider's computing resources are pooled to serve multiple consumers using a multi-tenant model, with different physical and virtual resources dynamically assigned and re-assigned according to consumer demand.

Service models as defined by NIST,
1. Software as a Service(SaaS)
	The capability provided to the consumer is a provider's application running on cloud. 
	SaaS saves the complexity of software installation, maintenance, upgrades, and patches.
2. Platform as a Service(PaaS)
	The capability provided to the consumer is to deploy their own application to the cloud.
	PaaS often provides middleware-style services. 
3. Infrastructure as a Service(IaaS)
	The capability provided to the consumer is to provision processing, storage, networks, and other fundamental computing resources where the consumer is able to deploy and run arbitrary software. 


Deployment models, 
1. Public cloud
	The cloud infrastructure is made available to the general public. 
	The provider is responsible both for the cloud infrastructure and for the control of data. 
2. Private cloud
	The cloud infrastructure is operated solely for an organization.
	The provider is responsible only for the infrastructure.
3. Community cloud
	The cloud infrastructure is shared by several organizations and supports a specific community that has shared concerns (ex: mission, security requirements, policy, and compliance considerations).
	May be managed by the organization or a third party.
	May be on-premises or off premises. 
4. Hybrid cloud
	The cloud infrastructure is a composition of two or more clouds (private, community, or public) that remain unique entities but are bound together by standardized or proprietary technology that enables data and application portability (ex: cloud bursting for load balancing between clouds)

## Risks of Cloud Computing
Cloud specific risks, 
1. Abuse of cloud resources
	Counter measures,
	- Stricter initial registration and validation processes
	- Enhanced billing and monitoring
	- Comprehensive monitoring of customer network traffic
	- Monitoring public blacklist
2. Insecure interfaces and APIs
	Countermeasures,
	- Analyze the security model of the CP interface
	- Implement strong authentication and access control with encryption
	- Understanding dependency chains associated with APIs. 
3. Malicious insiders
	Countermeasures,
	- Enforce strict supply chain management
	- Conduct comprehensive supplier assessment. 
	- Maintain transparency in overall security practices
	- Implement security breach notifications. 
4. Shared technology issues
	Countermeasures,
	- Implement security best practices
	- Monitor the environment for changes
	- Strong authentication and access control
	- Enforce SLAs for patching and vulnerability remediation.
	- Conduct vulnerability scanning configuration audits. 
5. Data loss or leakage
	Countermeasures,
	- Implement strong API access control.
	- Encrypt and protect integrity of data in transit
	- Analyze data protection at both design and run time.
	- Implement strong key generation, storage and management, and destruction practices
6. Account or service hijacking
	Countermeasures,
	- Prohibit the sharing of account credentials between users and services.
	- Leverage two-factor authentication techniques
	- Employ proactive monitoring to detect unauthorized activity.
	- Understand CP security policies and SLAs
7. Unknown risk profile
	Countermeasures,
	- Disclosure of applicable logs and data.
	- Partial/full disclosure of infrastructure details (e.g., patch levels and firewalls).
	- Monitoring and alerting on necessary information.

- Data must be secured while at rest, in transit and in use and access to the data must be controlled. 
- For data at rest, the best security measure is encrypting the database.

How to acquire data from an encrypted database ?
![[Pasted image 20260609101921.png]]
- Metadata : Local copy of schemas or cryptographic keys
- Encrypt/Decrypt Module : Handles cryptographic operations locally.
- Query processor : Intercepts and rewrites database queries.

Query flow,
1. The user issues a standard SQL-like plaintext query targeting logical database schemas. 
	Ex: `SELECT * FROM users WHERE age > 30;`
2. This query is intercepted by the query processor.
3. With the help of metadata, the query processor transform the plaintext query into an encrypted variant. 
	Table and column names are mapped to their anonymized or encrypted counterparts.
	Literal values or constants in predicates (ex: `30`) are encrypted or randomized. 
4. The resulting transformed query is sent to the cloud server. 
5. The cloud's Query executor evaluates the transformed query directly against the Encrypted database. 
	Because the data and the query constants are matching cryptographic representations, the cloud server can perform indexing, filtering, or joins without decrypting the underlying data. 
6. The server collects the matching rows which are entirely ciphertext and sends the Encrypted result back to the query processor. 
7. The query processor decrypts the encrypted result. 

#### Security as a Service(SecaaS)
A package of security services offered by a service provider.
Typically includes, 
- Authentication,
- antivirus
- anti-malware/spyware
- intrusion detection 
- security event management

In the context of cloud, SecaaS is a SaaS offering of a cloud service provider. 

Categories of SecaaS,
- Identity and access management
- Data loss prevention
- Web security
- Email security
- Security assessment
- Intrusion management
- Security information and event management
- Encryption
- Business continuity and disaster recovery
- Network security
