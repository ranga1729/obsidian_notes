If we have to maintain a dedicated communication line to securely access a certain site/resource,
- Expensive investment
- Maintenance cost
- Upgrade cost
- Not scalable
- Not flexible for short range site-to-site connectivity
- Not suitable for temporary requirements

Solution is: VPNs

A Virtual Private Network (VPN) is a technology that establishes a secure, encrypted tunnel over an open network, such as the public internet. It functions by routing your device's network traffic through a remote server operated by the VPN provider.

Usage of VPN in networking,
1. Remote access: accessing organization's resources remotely
2. Sit-to-Site access
	- Intranet based: connecting to different location(branches) of the same organization.
	- Extranet based: connecting between two different organizations.

Minimum requirements for a secure VPN connection,
1. Access to communication should be only for the defined users
2. Communication  should be private, not necessarily encrypted. (ex: MPLS)
3. Communication should be abstracted from physical hardware. 
	Channel is virtual. Connectivity doesn't change when physical layer changes. 


> [!NOTE] MPLS(Multiprotocol Label Switching)
> A telecommunications routing technique that directs data along predetermined paths using labels rather than long network addresses.
> Because of its speed and reliability, it is widely used by internet service providers (ISPs) and large enterprises to build secure, high-performance wide area networks (WANs).

Practical usage scenarios of VPNs,
1. To access cooperate resources. (ex: working while traveling)
2. To access private cooperate services form a remote location.
3. Controlled/Private Access needed from many locations by different parties. 
4. Long distance where leased lines are not feasible. 
5. Infrastructure requirements such as extended LANs (PROD to DR) : e.g. Oracle DB deployments

Technologies and Protocols used in VPNs,
1. MPLS: Multi-Protocol Label Switching (no security)
2. GRE Tunnel: Generic Routing Encapsulation (no security)
3. PPTP: Point-to-Point Tunnelling Protocol (secure but considered vulnerable now, Use GRE for encapsulation)
4. L2TP: Layer 2 Tunnelling Protocol (no security) Use GRE for encapsulation and no security unless IPSec is incorporated
5. IPSecurity (secure and de facto protocol for secure VPN implementations)
6. TLS (SSL VPN) - Transport Layer Security VPNs (secure)

#### 1. MPLS(Multi-Protocol Label Switching)
A routing technique used to speed up and shape network traffic flows. Instead of routers analyzing the destination IP address of every packet at each "hop" to determine the next path, MPLS assigns a short, fixed-length **label** to data packets.

Workflow,
1. Label Assignment
	When a packet enters the MPLS network, the ingress router analyzes its destination and assigns it a label based on a predetermined path, known as a **"Label Switched Path"(LSP)**.
2. Label Switching
	At each subsequent router along the path, the device reads only the label, looks up the pre-calculated next hop in a **"Label Forwarding Information Base"(LFIB)**, swaps the current label for a new one, and forwards the packet.

Because the path is pre-determined and the routers perform simple label swapping rather than complex IP routing table lookups, the data transmission is significantly faster and more predictable.

Characteristics,
- Protocol independent
- Increased Quality of Service(QoS) : network admins can prioritize specific types of traffic
- Not secure
#### 2. GRE Tunneling(Generic Routing Encapsulation)
A tunneling protocol developed by Cisco that can encapsulate a wide variety of network layer protocols inside virtual point-to-point links over an IP network.
GRE works by wrapping a data packet inside an additional IP header. This creates a "tunnel" that allows two isolated private networks to communicate as if they were directly connected, even if they are separated by an intermediate public or private network (like the internet).

Characteristics,
- Protocol agnostic
- Point-to-point communication
- No encryption
- Less secure
#### 3. PPTP(Point-to-Point Tunneling Protocol)
an obsolete method for implementing virtual private networks. Developed by a consortium led by Microsoft in the 1990s, it functions by creating a tunnel for PPP (Point-to-Point Protocol) packets to be encapsulated within IP datagrams for transmission across an IP network.

Workflow,
1. Control connection: A TCP connection (on port 1723) is established between the PPTP client and the PPTP server to manage the tunnel session and handle authentication.
2. Encapsulation: The data payload is encapsulated using the Generic Routing Encapsulation (GRE) protocol
3. Authentication: typically utilizes PPP authentication protocols, such as MS-CHAPv2, to verify user credentials.

Characteristics,
- Introduced my Microsoft
- Supported by many OSs. 
- Authentication is done by MS-CHAP
- Keys to encrypt payload is communicated during the authentication process
- Secure but vulnerable.
- Use GRE for encapsulation
- Point-to-Point connectivity 
- Works only on IP networks
- A data link layer protocol
#### 4. L2TP(Layer 2 Tunneling Protocol)
a tunneling protocol used to support virtual private networks (VPNs) by enabling the transmission of Layer 2 data across a Layer 3 (IP) network. It was developed as a successor to earlier protocols (like PPTP) by combining features from Cisco’s L2F and Microsoft’s PPTP.

Workflow,
1. Session establishment: The L2TP control plane uses a series of messages to establish a tunnel between two endpoints
2. Encapsulation: The data is wrapped in a PPP frame, then encapsulated into an L2TP header, and finally placed inside a UDP datagram
3. Transport: The packet is sent across the IP network to the destination endpoint, where it is decapsulated.

Characteristic,
- No native security. Need to combine with IPSec if encryption and authentication is required. 
- A data link layer protocol
- Double encapsulation when used with IPSec. (first by L2TP and then IPSec ESP header)
- Firewall compatible. 

## VPN vs Secure VPN
At its core, a VPN is simply a tunneling mechanism. Its primary function is to create a virtual point-to-point link between two endpoints across a shared network (the internet).

If a VPN protocol only handles tunneling (like base-level GRE or L2TP without IPsec), it provides network connectivity and "private" addressing, but it **does not provide data confidentiality**. Data sent through a basic VPN can be intercepted and read by anyone who captures the traffic.

A "Secure VPN" is a VPN that integrates **cryptographic security protocols** to ensure the data passing through the tunnel is indecipherable to third parties.
A true secure VPN must provide, 
- Encryption
- Authentication
- Integrity

Example protocols,
- PPTP
- IPSec
- SSL/TLS VPN
- SSH tunneling


> [!NOTE] A point to understand
> **VPN (Virtual Private Network)** is best understood as a **functional architecture** or a category of network implementation rather than a single specific protocol.
> VPN acts as an umbrella term for a system that fulfills two primary requirements, 
> - Virtualization: Creating a logical path across a physical network (the internet) that mimics a direct, private physical connection.
> - Private Addressing: Encapsulating data packets so they can travel across a public infrastructure while maintaining their original internal routing information.
> 
> Protocols like **PPTP**, **L2TP**, **OpenVPN**, and **WireGuard** are the specific "engines" used to achieve the VPN goal. They are not the VPN itself, but rather the tools that implement the tunneling and (in modern cases) the security features required for the connection.


#### IPSec
A framework of open standards used to secure internet protocol (IP) communications by authenticating and encrypting each IP packet in a communication session. Unlike a simple tunneling protocol, IPsec provides a comprehensive security suite for network traffic.

IPsec operates at the Network Layer (Layer 3) of the OSI model and utilizes two main headers to provide security:
- Authentication Header(AH): Provides connectionless integrity and data origin authentication for the entire IP packet, but it **does not** provide encryption.
- Encapsulation Security Header(ESP): Provides encryption for the payload, ensuring data confidentiality. It also provides authentication and integrity for the payload.

When IPsec is implemented in a firewall or router, it provides strong security that can be applied to all traffic crossing the perimeter.

IPSec can assure these,
- A router advertisement (a new router advertises its presence) comes from an authorized router.
- A neighbor advertisement (a router seeks to establish or maintain a neighbor relationship with a router in another routing domain) comes from an authorized router.
- A redirect message comes from the router to which the initial IP packet was sent.
- A routing update is not forged.

IPSec services,
- Access control
- Connectionless integrity
- Data origin authentication
- Rejection of replayed packets 
- Confidentiality(encryption)
- Limited traffic flow confidentiality

Both transport and Tunnel modes support authentication(AH) and encapsulation security header(ESP). 

##### 1. Transport Mode
Used for end-to-end communication between two hosts.
Only the payload of the IP packet is encrypted. 
The original IP header remains visible which allows intermediate routers to see the source and destination IP addresses. 
##### 2. Tunnel Mode
Used to protect communication between site to-site / network-to-network.
the entire original IP packet including the original header is encrypted and encapsulated within a completely new IP packet.

IPSec policy is determined primarily by the interaction of two databases, 
1. Security Association Database(SAD)
2. Security Policy Database(SPD)

#### Security Association(SA) in IPSec
A Security Association is a **logical, unidirectional contract** established between two devices (peers) that defines how they will communicate securely. Before any encrypted data can be sent, both devices must agree on a set of parameters, which are stored in the SA.
(if the connection is bi-directional, two association must have been established.)

An SA holds these technical configurations that both endpoints use for communication,
1. Security protocol(IPSec Protocol mode) : Whether the connection will use AH (Authentication Header) or ESP (Encapsulating Security Payload).
2. Encryption Algorithm(ESP Info) : The specific cipher to be used for confidentiality (e.g., AES-256-GCM or ChaCha20).
3. Authentication Algorithm(AH info) : The method used to verify data integrity (e.g., HMAC-SHA256).
4. Cryptographic keys : The session keys used for encryption and decryption.
5. Security Parameter Index(SPI) : A unique 32-bit value attached to the packet header that tells the receiving device which SA to use to decrypt that specific incoming packet
6. Lifetime : The duration or amount of data after which the keys must be refreshed to maintain security (known as "Rekeying").
7. Sequence number counter
8. Sequence counter overflow


A security association is uniquely identified by three parameters, 
- Security Parameter Index(SPI)
- IP Destination Address
- Security Protocol Identifier

We don't configure SAs manually. they are created dynamically created using the **"Internet Key Exchange(IKE)"** protocol. 
![[Pasted image 20260601155326.png]]
IKE protocol works in two phases,
1. IKE Phase 1 : The peers authenticate each other and create a secure channel (the ISAKMP SA) to protect the negotiation of the actual data tunnel.
2. IKE Phase 2 : The peers negotiate the parameters for the actual data traffic (the IPsec SA) using the secure channel created in Phase 1.

Without the Security Association, the receiving router would have no way of knowing how to interpret the encrypted packets it receives, as it would not have the correct decryption keys or algorithm mappings.

**These SA details are stored in the Security Association Database(SAD).** 

##### Security Policy Database(SPD)
The Security Policy Database(SPD) act as the "instruction manual" for an IPSec-enabled devices. While the Security Association (SA) stores the _how_ (the active cryptographic rules), the SPD stores the _what_ and the _why_ (the administrative policies).

The SPD is a table configured by the network administrator that dictates what traffic must be protected, what traffic can pass in the clear, and what traffic must be blocked. It sits at the top of the IPsec processing hierarchy—before a packet is even considered for encryption, the system checks the SPD.

When a packet leaves or enters a device, the kernel checks the SPD to determine the **IPsec policy** for that specific traffic flow. The SPD entries typically contain criteria such as:
- Remote IP Address
- Local IP Address
- Next Layer Protocol
- Name
- Local and remote ports

For every packet, the SPD enforces one of the three decisions,
1. PROTECT : The traffic must be encrypted/authenticated. The device will then look for an existing SA (in the SAD) or trigger IKE to create one.
2. BYPASS : The traffic is allowed to pass through the network without any IPsec processing (cleartext).
3. DISCARD : The traffic is unauthorized and is immediately dropped.

The interaction flow,
1. Policy Lookup(SPD) : An outgoing packet arrives. The system searches the **SPD** to see if a policy exists for this packet.
2. Match Found: If the policy says "PROTECT," the system looks for a corresponding **SA** in the **SAD** (Security Association Database).
3. Actions: 
	IF an SA exist: The system uses the keys and algorithms defined in that SA to encrypt the packet.
	IF no SA exist: The system initiates the IKE negotiation to create a new SA, which is then added to the SAD.

### Internet Key Exchange(IKE)
This is the control protocol used in IPsec to set up the **Security Association (SA)**. Its primary job is to perform mutual authentication between two endpoints and establish the shared cryptographic keys used to encrypt and decrypt traffic.

IKE operates in two phases,
1. IKE Phase 1(The secure channel) : The peers negotiate how to secure the IKE communication itself. They agree on encryption algorithms, hashing methods, and use the **Diffie-Hellman (DH)** protocol to securely generate a shared secret over an insecure network. This creates a secure, bidirectional management tunnel (the ISAKMP SA)
2. IKE Phase 2(The data tunnel) : Using the secure channel created in Phase 1, the peers negotiate the specific parameters for the **IPsec tunnel** (the data tunnel). This includes defining which traffic to protect and which encryption keys to use for the actual data payload.

IPSec architecture document mandates support for two types of key management,
1. Manual
	The administrator manually enters the encryption/authentication keys and SPI values into the Security Policy Database (SPD) and Security Association Database (SAD) on both ends. **No IKE is involved**
2. Automated 
	The system uses **IKE (Internet Key Exchange)** to perform the handshake, negotiate parameters (ISAKMP/Oakley), and dynamically generate keys.

**IKE (Internet Key Exchange)** is the protocol suite that **includes** ISAKMP and Oakley.
- **ISAKMP (Internet Security Association and Key Management Protocol):** Provides the framework for authentication and key exchange (the "how").
- **Oakley:** Provides the key exchange mechanism using the Diffie-Hellman algorithm (the "what").
**IKE:** The combination of these two, providing the complete automated key management solution for IPsec.
