## View
View is the building block of UI components. It occupies a rectangular area on the screen.
Its entirely responsible for drawing itself and handling user interaction events like clicks, touches and key presses.

Every visual elements whether its a piece of 
- Display text(`TextView`) or a  Input field(`EditText`)
- Clickable button(`Button`), menu, other controls
- Scrollable (`ScrollView`, `RecyclerView`)
- An image(`ImageView`) 
- Group views (`ConstraintLayout` and `LinearLayout`)
is a direct subclass of the base `View` class. (`class.view.View`). 
![[Pasted image 20260526204130.png]]


> [!NOTE] ViewGroups
> A `ViewGroup` is a special subclass of `View` that acts as an invisible container designed to hold and arrange other child Views and ViewGroups. Examples include `LinearLayout`, `ConstraintLayout`, and `FrameLayout`.

Attributes,
1. `layout_width`, `layout_height`: Spatial constraint of the view's rectangular bounding box. 
	1. `match_parent`
	2. `wrap_content`
2. `id` : Unique Id
3. `background` : Sets a background(solid color/gradient/drawable asset image)
4. `visibility` : Three values
	1. visible
	2. invisible - Occupies the space but hidden
	3. gone - Occupies 0 space and completely hidden
5. `layout_margin` : Set margin
6. `padding` : set padding

Ex:
```xml
<TextView
	android:id="@+id/show_count"
	android:layout_width="match_parent" 
	android:layout_height="wrap_content"
	android:text="John Doe"
	android:textSize="18sp" 
	android:textColor="#212121"
	android:textStyle="bold"
	android:background="#F5F5F5" 
	android:padding="16dp" 
	android:layout_marginTop="8dp" 
	android:visibility="visible"
/>
```

> [!NOTE] `android:id="@+id/submitButton"`
> Assigns a unique structural integer identifier to the View node within the compiled `R.java` class. This allows you to reference and manipulate the specific View inside your Kotlin or Java code.
> The `+` symbol instructs the resource compiler to generate a brand new resource ID tracking reference

How to create a View in Kotlin code ?
To instantiate a View directly in Kotlin code rather than XML, you must initialize the specific View class by passing it an operating system **`Context`**. An Activity is a direct subclass of `Context`, so when writing code inside an Activity, you can pass **`this`** as the context parameter.

Ex:
```kotlin
// com/example/myapp/DetailActivity.kt
package com.example.myapp
import android.graphics.Color
import android.os.Bundle
import android.view.Gravity
import android.view.View
import android.widget.LinearLayout
import android.widget.TextView
import androidx.appcompat.app.AppCompatActivity

class DetailActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        // 1. Instantiate the ViewGroup container (LinearLayout)
        val rootLayout = LinearLayout(this).apply {
            orientation = LinearLayout.VERTICAL
            gravity = Gravity.CENTER
            setBackgroundColor(Color.parseColor("#F5F5F5")) // Light grey background
        }
        // 2. Instantiate the Atomic View (TextView)
        val titleTextView = TextView(this).apply {
            id = View.generateViewId() // Generate a unique ID programmatically
            text = "Welcome to the Programmatic Detail Activity!"
            textSize = 24f // Sets font size in SP (Scalable Pixels)
            setTextColor(Color.parseColor("#212121")) // Dark charcoal text
            textAlignment = View.TEXT_ALIGNMENT_CENTER  
            // Set padding inside the TextView (converting raw pixels to DP requires resources)
            val paddingInPx = (16 * resources.displayMetrics.density).toInt()
            setPadding(paddingInPx, paddingInPx, paddingInPx, paddingInPx)
        }
        // 3. Define Layout Parameters for the TextView
        // This instructs the parent LinearLayout how to measure and place this child View
        val textLayoutParams = LinearLayout.LayoutParams(
            LinearLayout.LayoutParams.MATCH_PARENT, // Width attribute
            LinearLayout.LayoutParams.WRAP_CONTENT  // Height attribute
        ).apply {
            // Set margins outside the TextView boundary
            val marginInPx = (8 * resources.displayMetrics.density).toInt()
            setMargins(marginInPx, marginInPx, marginInPx, marginInPx)
        }
        // 4. Inject the TextView into the LinearLayout container with its layout rules
        rootLayout.addView(titleTextView, textLayoutParams)
        // 5. Render the programmatic rootLayout directly onto the screen window surface
        setContentView(rootLayout)
    }
}
```

## Context
Context is an interface to global information about an application environment. 
Whenever your code needs to perform an action that goes beyond pure computation (like math or manipulating strings) and requires interacting with the outside world, it will require a `Context` instance.

Context is responsible for three primary operations, 
1. Resource and Asset Access
	Ex: `getString(R.string.app_name)`
2. Inter-component Communication
3. System Service and Storage Inspection

Not all context instances are identical.
Context types, 
1. Context Wrapper : A proxy class that delegates all of its framework calls to a base, underlying context. It allows the Android system to modify behavior without altering the original context. 
2. Activity Context : A direct subclass of `ContextWrapper`. It is strictly bound to the **lifecycle of that specific screen**. It contains configuration information regarding the current window, user interface themes, and display metrics.
3. Application Context : An isolated instance bound to the **lifecycle of the entire application process**. It is obtained by calling `applicationContext` inside an activity.
Ex:
```kotlin
class MyBackgroundManager private constructor(context: Context) {
	private val appContext = context.applicationContext
}
```

### ViewGroup and View Hierarchy
A ViewGroup is a specialized subclass of `View` that acts as an invincible container. Its primary responsibility is to hold, position, and manage other child Views. 

The **"View Hierarchy"** is the resulting tree structure generated by nesting multiple Views inside `ViewGroups`. When an Activity renders a screen, it starts at the top node (the Root) and travels down the branch nodes to measure and draw every element.
```text
[Root ViewGroup] (e.g., LinearLayout) 
	├── [Child View] (e.g., TextView) 
	├── [Child View] (e.g., ImageView) 
	└── [Nested ViewGroup] (e.g., FrameLayout) 
		├── [Sub-Child View] (e.g., Button) 
		└── [Sub-Child View] (e.g., Button)
```

`ViewGroup` contains child `Views`. 

### Layouts
![[Pasted image 20260527005731.png]]
`Layouts` are specific types of `Viewgroups`. 
It contain child `Views`. 

Common layouts,
1. `LinearLayout`
	arrange children in a single direction, horizontal or vertical using `android:orientation` attribute. 
2. `ConstraintLayout`
	Position views relative to other sibling views or the parent container using flexible anchor point. 
3. `FrameLayout`
	Acts as a stack or a placeholder block. It blocks out an area on the screen to display a single item. If you add multiple child views to a `FrameLayout`, they will stack directly on top of each other like a deck of cards, pinned to the top-left corner by default.
4. `RelativeLayout` - legacy
	Positions child elements relative to each other (e.g., "place this button below that text view") or relative to the parent edges. Entirely replaced by `ConstraintLayout`. 

## Class hierarchy vs Layout hierarchy
Class hierarchy
	How views inherit object properties with inheritance. 
	Its a static, compile-time object model defined by the Android framework, dictates what methods and properties it inherits.
	Ex: A `Button` is a `TextView`, which is a `View`. A `Linearlayout` is a `ViewGroup` which is a `View`.
Layout hierarchy: 
	Where an object lives spatially on the screen. 
	Its a dynamic, runtime tree structure defined inside your XML layout file which dictates where an object lives spatially on the screen.
	Ex: A `LinearLayout` container(Parent) has a child `Button` and has a child `TextView`

## Adapter
![[Pasted image 20260602170446.png]]
Adapter is a design pattern implemented as a bridge component that connects data source to a UI `AdapterView`.
Its primary responsibility is to convert individual data objects into interactive visual View objects that can be rendered on the screen.

Core responsibilities,
- Data Binding - Iterate through data collections and binds specific data fields to the corresponding UI widgets. 
- View Creation
- Performance Optimization(view recycling)

#### Action Bar
![[Pasted image 20260602181329.png]]
The `ActionBar` (traditionally known as the App Bar) is a dedicated structural element located at the top of an application screen. 
It serves as a consistent visual anchor that provides 
- branding
- user identity
- navigation
- access to key actions

To use this,
- Legacy - get an instance of `ActionBar` by calling `getActionBar()`
- Modern - get a `Toolbar` widget. 
#### Dialogs
![[Pasted image 20260602212455.png]]
A dialog is a small window that prompts the user to make a decision or enter additional information. A dialog does not fill the screen and is normally used for modal events that require users to take an action before they can proceed.

Types of dialogs, 
1. `AlterDialog` : High-priority warnings, confirmation prompts
2. `DatePickerDialog` or `TimePickerDialog` : System-optimized interfaces for selecting distinct dates, calendar schedules, or times.
3. Custom Dialogs by `DialogFragment` or Custom Layout. 

How to create a Dialog ?
You need to extend the `DialogFragment` and create an `AlertDialog` in the `onCreateDialog()` callback method. 

Ex:
![[Pasted image 20260602215008.png]]
```kotlin
class StartGameDialogFragemnt: DialogFragement() {
	override fun onCreateDialog(savedInstanceState: Bundle?) : Dialog {
		return activity?.let {
			val builder = AlertDialog.Builder(it)
			builder.setMessage("start game")
				.setPositiveButton("Start" {
					dialog, id id -> // start the game
				}
				.setNegativeButton("cancel") {
					dialog, id -> // cancel the dialog
				}
			//create the AlertDialog object and return it.
			builder.create()
		} ?: throw IllegalStateException("Activity can not be null")
	}
}
```

`AlertDialog` is the only dialog design you most often use. It has a,
1. Title - optional.
2. Content Area - display the message of another custom layout.
3. Action Buttons - no more than 3 action buttons.
