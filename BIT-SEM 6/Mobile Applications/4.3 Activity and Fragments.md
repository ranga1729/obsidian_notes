Activities and Fragments are the core foundational blocks used to build a user interface(UI) and manage user interaction flows. 

**Activity(The Window):** 
Represents a single, independent screen with a user interface.
Acts as the absolute entry point for user interactions and serves as the windows container that hosts your UI elements. 

**Fragment(The Modular Pane)**
Represents a modular, reusable piece of a user interface that lives strictly inside a host activity. Can not exist independently, Its behavior and lifecycle are directly dependent on the Activity hosting it. 

**How to Add a new Activity ?**
Steps,
1. Create the user interface layout(`activity_detail.xml`)
Create a new XML file inside your `res/layout` directory. This defines the visual structure of your new screen.
```xml
<?xml version="1.0" encoding="utf-8"?>
<LinearLayout xmlns:android="http://schemas.android.com/apk/res/android"
    android:layout_width="match_match"
    android:layout_height="match_parent"
    android:orientation="vertical"
    android:gravity="center"
    android:padding="16dp"
>
    <TextView
        android:id="@+id/titleTextView"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="Welcome to the Detail Activity!"
        android:textSize="24sp"
        android:textStyle="bold" 
    />
</LinearLayout>
```
2. Create the Activity Class(`DetailActivity.kt`)
Create a corresponding Kotlin class that extends `AppCompatActivity`. This class handles the initialization logic and lifecycle of the screen.
```kotlin
// com/example/myapp/DetailActivity.kt
package com.example.myapp
import android.os.Bundle
import androidx.appcompat.app.AppCompatActivity

class DetailActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
	    super.onCreate(savedInstanceState)
	    // Inflate and bind the XML layout created in Step 1 to this Activity
	    setContentView(R.layout.activity_detail)
    }
}
```
3. Register the Activity in the manifest(`AndroidManifest.xml`)
The Android OS can not launch an Activity unless it is declared in the manifest file.
```xml
<manifest xmlns:android="http://schemas.android.com/apk/res/android" package="com.example.myapp">
    <application
        android:allowBackup="true"
        android:icon="@mipmap/ic_launcher"
        android:label="@string/app_name"
        android:theme="@style/Theme.AppCompat"
    >
        <activity
            android:name=".MainActivity"
            android:exported="true">
            <intent-filter>
                <action android:name="android.intent.action.MAIN" />
                <category android:name="android.category.LAUNCHER" />
            </intent-filter>
        </activity>

        <activity
            android:name=".DetailActivity"
            android:exported="false"
            android:label="Detail Screen" 
        />
    </application>
</manifest>
```
4. Launch the New Activity from your main screen
To navigate from your existing screen (e.g., `MainActivity`) to your new `DetailActivity`, create an explicit **Intent** and execute it using `startActivity()`.
```kotlin
// Inside MainActivity.kt (e.g., inside a button click listener)
fun navigateToDetail() {
    // Construct an explicit Intent pointing directly to DetailActivity
    val intent = Intent(this, DetailActivity::class.java)
    // Request the OS to launch the target Activity
    startActivity(intent)
}
```

## Activity Lifecycle
![[59d40f71d715436_960.jpg]]
Activities are managed as activity stacks. 
When a new activity is started, it is usually placed on the top of the current stack and becomes the running activity, the previous activity always remain below in the stack, and will not come to the foreground again until the new activity exists. 
![[Pasted image 20260526141111.png]]

States of an activity,
- Activity is in the **foreground**, it is active and running. User is interacting with it. Highest position of the activity stack. 
- Activity has **lost focus** due to an non-full-sized or transparent activity has focus on top of the activity. The activity is still alive, visible to the user and maintain the state. 
- Activity is **completely obscured by another activity**. Its stopped or hidden. No longer visible to the user but still maintain the state. 
- The system **drop** the activity from memory. Its destroyed. 

![[Pasted image 20260526150204.png]]
These above host activity transitions through these foundational sequential hooks,
1. `onCreate()` : Triggered when the system first create the activity. Initializes the core logic, setup view binding, inflate the base XML layout using `setContentView()`.
2. `onStart()` : Triggered when the activity visible to the user on screen.
3. `onPause()` : Triggered when a minor event de-focus the screen. The activity is partially obscured but visible. 
4. `onResume()` : Triggered when the activity becomes to the foreground again. User can interact with it again.
5. `onStop()` : Triggered when the activity is no longer visible to the user.(ex: new screen has launched over it or user hit the home button). We can release heavy resources here. 
6. `onDestroy()` : The final callback before the process is completely destroyed by the system or finish by code execution. 
#### Three Key Loops
![[Pasted image 20260526150625.png]]
Refers to the nested lifecycle an activity goes through. 
1. **The Entire Lifetime**
	Duration: From `onCreate()` to `onDestroy()`
	Purpose: The total lifespan of the activity. Setup "global" state in `onCreate()` and release all remaining resources in `onDestroy()`.
2. **The Visible Lifetime**
	Duration: From `onStart()` to `onStop()`
	Purpose: The time the user can see the Activity on-screen. Maintain resources that are needed to display the app to the user such as registering `BroadcastReceivers`.
3. **The Foreground Lifetime**
	Duration: From `onResume()` to `onPause()`
	Purpose: The time the Activity is at the top of the screen and actively has user input focus.
