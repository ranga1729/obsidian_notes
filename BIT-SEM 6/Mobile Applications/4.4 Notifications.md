Notifications function as standalone system UI elements decoupled from your application's active lifecycle.

Two main types,
1. Local Notifications(Triggered internally)
2. Remote/Push Notifications(Triggered by a cloud server)

## The Global Architecture
To deliver a notification from a server to a locked background device, Android routes all external traffic through a centralized gateway: **Firebase Cloud Messaging (FCM)**.
Workflows
1. Token Registration: When the app boots, the client SDK communicates with FCM(Firebase Clouse Messaging) to request a unique identifier called a "Registration Token".
2. Token Upload: Your Kotlin app uploads this token yo your backend database server. This token acts as the physical address of that specific device.
3. Payload Dispatch: When an event occurs (e.g., a friend sends a chat message), your backend server fires an HTTP POST payload containing the data and target token to FCM.
4. System Broadcast: FCM wakes up a persistent, low-power system socket maintained natively by Android on the target hardware. The Android OS receives the raw payload packet. ## Notification Channels(API 26+) - Pub/Sub model
Android enforces a categorization system called **Channels**. Every notification must belong to a channel. Users can selectively turn off whole channels (e.g., disabling "Promotional Ads" while keeping "Order Updates" turned on) without deleting your app.

Ex: Create a notification channel
```kotlin
// Run this early (e.g., in Application.onCreate()) to register the channel with the OS
fun createNotificationChannel(context: Context) {
    if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.O) {
        val name = "Order Tracking"
        val descriptionText = "Real-time updates regarding shipping status"
        val importance = NotificationManager.IMPORTANCE_HIGH
        
        val channel = NotificationChannel("ORDER_CHANNEL_ID", name, importance).apply {
            description = descriptionText
        }
        
        // Register the channel with the system
        val notificationManager: NotificationManager =
            context.getSystemService(Context.NOTIFICATION_SERVICE) as NotificationManager
        notificationManager.createNotificationChannel(channel)
    }
}
```

### Notification Compact Builder (`NotificationCompact.Builder`)
Because Android is highly fragmented across varying operating system versions, developers utilize `NotificationCompat` to build the UI uniformly.
```kotlin
// PendingIntent allows the Android System UI to open your app when clicked
val intent = Intent(context, MainActivity::class.java).apply {
	flags = Intent.FLAG_ACTIVITY_NEW_TASK or Intent.FLAG_ACTIVITY_CLEAR_TASK
}
// Note: FLAG_IMMUTABLE is a mandatory platform security requirement
val pendingIntent: PendingIntent = PendingIntent.getActivity(
    context, 0, intent, PendingIntent.FLAG_IMMUTABLE
)

val builder = NotificationCompat.Builder(context, "ORDER_CHANNEL_ID")
	// Must be a white transparent alpha image
    .setSmallIcon(R.drawable.ic_delivery_truck) 
    .setContentTitle("Package Delivered")
    .setContentText("Your driver dropped off your package at the front door.")
    // For heads-up display on older versions
    .setPriority(NotificationCompat.PRIORITY_HIGH) 
    .setContentIntent(pendingIntent) // Tap behavior
    .setAutoCancel(true) // Automatically clears when clicked
```

## Tap Action and Action Buttons
![[Pasted image 20260602224129.png]]
Every notification must respond when it it tapped, usually. launching an `Activity` in your app. 
But in native Android development, when a user taps a notification, the app itself is often not even running in memory. Therefore, you cannot use standard Kotlin click listeners (like `setOnClickListener`).

Instead, notification tap actions are powered by the Android OS using an architectural mechanism called **`PendingIntents`**.

## `PendingIntent`
This is a wrapper around a standard Android `Intent`. 
It acts as a token that you hand over to the Android System UI (`NotificationManager`). By doing this, you grant the OS explicit permission to execute the contained Intent on behalf of your application, using your app's security permissions, even if your app process has been killed.

How to implement a tap action,
1. Create a standard intent explicitly targeting the component (usually an `Activity`) you want to launch.
```kotlin
val intent = Intent(context, DetailActivity::class.java).apply {
    // Pass destination data (e.g., which deep link or item ID to open)
    putExtra("ITEM_ID", "order_12345")
    // Clear the activity stack so pressing back behaves correctly
    flags = Intent.FLAG_ACTIVITY_NEW_TASK or Intent.FLAG_ACTIVITY_CLEAR_TASK
}
```
2. Wrap it in a `PendingIntent`
Convert the intent into a `PendingIntent` using `getActivity()`
```kotlin
val pendingIntent: PendingIntent = PendingIntent.getActivity(
    context,
    0, // Unique request code for this specific transaction
    intent,
    PendingIntent.FLAG_IMMUTABLE // Security requirement for API 31+
)
```
3. Attach it to the Notification
Pass the `PendingIntent` to the `setContentIntent()` method of your `NotificationCompat.Builder`. You should also call `setAutoCancel(true)` so the notification automatically vanishes from the system tray once clicked.
```kotlin
val builder = NotificationCompat.Builder(context, "CHANNEL_ID")
    .setSmallIcon(R.drawable.ic_notification)
    .setContentTitle("Order Shipped")
    .setContentText("Tap to track your delivery.")
    .setContentIntent(pendingIntent) // <--- Attaches the tap action
    .setAutoCancel(true)             // <--- Dismisses notification on tap
```

Methods defined by `PendingIntent`, 
1. `PendingIntent.getActivity()`
	Retrieves a `PendingIntent` that, when triggered, starts an `Activity` in the foreground. It brings a user interface to the front of the screen, interrupting whatever application the user is currently looking at.
	
	**Primary Use Case:** UI-driven interactions. Opening a specific detail screen when a user clicks a status bar notification, or launching the application from an interactive home-screen app widget.

2. `PendingIntent.getBroadcast()`
	Retrieves a `PendingIntent` that, when triggered, performs a system-wide broadcast to a `BroadcastReceiver`. This is entirely silent and invisible to the user. It does not open a window. The targeting `BroadcastReceiver` wakes up, executes its `onReceive()` block on the main thread for a maximum of 10 seconds, and immediately goes back to sleep.
	
	**Primary Use Case:** Low-overhead, short-lived background tasks. 
	Ex:
	- Include an alarm clock firing via `AlarmManager` at a specific time,
	- Clicking a "Mark as Read" action button directly inside a notification banner.

3. `PendingIntent.getService()`
	Retrieves a `PendingIntent` that, when triggered, starts a background or foreground `Service`. Like broadcasts, this does not display an Activity window. However, unlike broadcasts, a `Service` is designed to stay alive in the background for extended periods to process heavy operations (such as streaming audio or tracking continuous GPS location coordinates).
	
	**Primary Use Case:** Long-running background operations that require a persistent process lifecycle. 
	Ex: 
	- Media playback control buttons (Play/Pause/Skip) embedded within a media notification player, 
	- Initiating a heavy data synchronization sync task via an alarm.

## Importance Level
Importance levels determine how interruptive a notification is.
This dictates following properties,
- Notification sound
- Vibration
- Status bar showing up
- Force a "heads-up" banner to slide down 

Four user-facing importance levels,
1. `IMPORTANCE_NONE` 
	Functionally equivalent to the user blocking notifications for that specific category entirely.
2. `IMPORTANCE_HIGH` - Urgent
	- Triggers an alert sound or vibration. I
	- Immediately drops a "heads-up" banner across the top of the user's current screen (overlapping whatever app they are using). 
	- Places an icon in the status bar.
	Use cases: Immediate, real-time communications that require instant action.
		Incoming VoIP or vide calls
		Instant messaging alert
		Turn-by-turn GPS navigation prompts
		Alarms or emergency warning
3. `IMPORTANCE_DEFAULT` - High
	- Triggers the system alert sound or vibration
	- Places an icon in the status bar, 
	(does **not** peek over the screen with a heads-up banner. It lists normally in the pull-down notification shade.)
	Use cases: Important updates that the user needs to know about, but that don't warrant interrupting an active game or video they are watching.
		Calendar event reminder
		Package delivery tracking alerts
		Order status updates
4. `IMPORTANCE_LOW` - Medium
	- Completely silent. 
	- Place an icon in the status bar and appears in the notification shade.
	 (It does not make a sound, it does not vibrate, and it does not show a heads-up banner.)
	Use cases: Informational content that is relevant but lacks any time-sensitivity.
		Social media connection request or updates
		Daily weather forecast. 
		Background data synchronization notices
5. `IMPORTANCE_MIN` - Low/Silent
	- Completely silent and completely invisible on the surface. (no sound/vibration)
	- Does not show an icon in the status bar. 
	The only way the user will ever see it is if they explicitly swipe down to open their notification shade, where it is often collapsed at the very bottom.
	Use case: Non-essential background noise or contextual suggestions.
		Nearby promotional marketing offers
		App updates or change logs
		non-critical subscription expiration warnings

| Constant             | Sound/Vibration? | Heads-up banner? | Status bar icon? |
| -------------------- | ---------------- | ---------------- | ---------------- |
| `IMPORTANCE_NONE`    | No               | No               | No               |
| `IMPORTANCE_HIGH`    | Yes              | Yes              | Yes              |
| `IMPORTANCE_DEFAULT` | Yes              | No               | Yes              |
| `IMPORTANCE_LOW`     | No               | No               | Yes              |
| `IMPORTANCE_MIN`     | No               | No               | No               |

Ex:
```kotlin
val builder = NotificationCompat.Builder(context, "CRITICAL_ALERTS")
    .setSmallIcon(R.drawable.ic_alert)
    .setContentTitle("Security Breach")
    .setContentText("A new login was detected from an unrecognized device.")
    
    // For Android 8.0+: Governed by the channel importance set during creation.
    // For Android 7.1 and lower: Handled by this fallback line:
    .setPriority(NotificationCompat.PRIORITY_HIGH)
```
