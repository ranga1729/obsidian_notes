## Versioning
Critical for upgrade an maintenance strategy. 
```groovy
android {
    namespace 'com.example.myapp'
    compileSdk 34
    defaultConfig {
        applicationId "com.example.myapp"
        minSdk 24
        targetSdk 34
        // --- RELEASE VERSION DETAILS ---
        // Incremented with every single Google Play upload (e.g., 1, 2, 3...)
        versionCode 1 
        // The user-facing version string shown on the Play Store (e.g., "1.2.0")
        versionName "1.0.0"
        testInstrumentationRunner "androidx.test.runner.AndroidJUnitRunner"
    }
    buildTypes {
        release {
            minifyEnabled true
            proguardFiles getDefaultProguardFile('proguard-android-optimize.txt'), 'proguard-rules.pro'
        }
    }
}
```

- The Android system uses the `versionCode` value to protect against downgrades.
- Prevents users from installing an APK with a lower `versionCode` than the version currently installed on a device.
- The first version of an app is released with `vesionCode` set to 1. Whether the next release is major or minor release, the version number must be monotonically increased.

- Version name is consist of three values,
	`<major>`.`<minor>`.`<point>`
	Ex: `versionName 1.0.0`

## Signing the App
APK signing is a mandatory security mechanism in Android that cryptographically verifies the identity of the author and ensures that the application binary has not been altered or corrupted since it was built.

The Android operating system will refuse to install any APK or Android App Bundle (AAB) that is not signed with a valid certificate.

usage of singing,
1. Application identity and trust : The signature establishes a cryptographic link between the developer and the application code.
2. Code integrity : The signing process generates cryptographic hashes of all the files inside the APK package. If an attacker decompiles the APK, injects malicious code, and attempts to repackage it, the file hashes will no longer match the signature block, causing Android's package manager to reject the installation.
3. Application upgrade continuity : Android allows one APK to overwrite another during an app update only if the package names match **and** both binaries are signed with the exact same certificate.
4. Sandbox and permission security : Android enforces a user-id (UID) isolation boundary between different applications. If two apps are built by the same developer and require shared access to data or custom permissions, they can explicitly request a shared user ID—but Android will only grant this if both applications are verified with the identical signing certificate.

## Uploading the App
Prerequisites,
- Enroll in Play App singing
- Ensure the app meets google play's size requirements. 
- Upload to the Play Console. 

Different ways to share the app internally for testing, 
- Firebase app distribution
	Allows developers to deploy and distribute to list of users.
	Useful for Continuous Integration systems.  
- Play console's internal app sharing tool
	Faster to deploy compared to alpha or beta tracks. 
	Provides access to services like Subscriptions, In-App purchases, and ads
	Undergoes Play Console signing and shrinking, providing a close representation of what end-users receive

#### Updating the App
- Increase the version code in the base module for updates.
- Build and update a new app bundle
- Google Play generates updated APKs with new version codes and serves them to users as needed.

Steps of publishing the app,
1. Create a Google Play Developer account (one time registration fee)
2. Setup a Google Play Console account
3. Create a store listing (add app title, description and graphics)
4. Add content rating (fill the questionnaire)
5. Set up pricing & distribution (free or paid, countries, devices categories)
6. Roll out your app (choose release track - alpha, beta or production)

## Google AdMob
A mobile advertising platform by Google.
Helps app developers monetize their apps through in-app advertising.
Provides insights into user behavior to enhance app marketing and monetization strategies.

How it works ?
- AdMob displays ads within the app. 
- Developers get paid whenever users interact with ads.  
- It leverages Google's vast advertising network for diverse, high-quality ads. 

Steps of integrating app with AdMob,
- Signup for an AdMob account
- Add your app to the AdMob console. 
- Install the Google Mobile Ads SDK. 
- Configure ad units and place them in your app.

Ad types,
- Banner ads : Standard, rectangular ads that can be placed in various locations within your app
- Interstitial ads : Full-screen ads that appear at natural breaks or transition points in your app
- Rewarded ads : Ads that reward users for watching short videos or interacting with playable ads
- Native ads : Ads that match the look and feel of your app for a seamless user experience

AdMob metrics,
- Impression : Number of times an ad is displayed in your app
- Clicks : Number of times users click on the ads
- CTR(Click Through Rate) : The ratio of users who click on an ad to the number of total users who view the ad
- eCPM(Effective Cost Per Mille) : The estimated earnings per thousand ad impressions
