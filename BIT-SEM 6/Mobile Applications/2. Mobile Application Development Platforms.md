## Android Development Platform
The **Android Open System Platform(AOSP)** is publicly available and it provides a complete implementation of the Android platform. 
Two levels of compatibility for devices implementing AOSP,
1. AOSP compatibility
2. Android Compatibility 

AOSP architecture, 
![[Pasted image 20260224224413.png]]

The software stack for AOSP contains several layers,
1. Android App layer
	Android API is used to create apps. 
2. Privileged apps
	Created using Android APIs + system APIs
	Must be preinstalled as privileged apps. 
3. Device manufacturer app layer
	Created using a android APIs + system APIs + direct access to the android framework implementation. 
	Such apps must be pre-installed on the device.
	Gets updates with system software updates. 
4. System API
	System APIs = Android APIs available only to partners and Original Equipment Manufacturers(OEMs)
	These are marked with `@SystemApi` annotation in the source code. 
5. Android API
	Publicly available API for third-party android app developers
6. Android Framework
	A group of java classes, interfaces and other precompiled code used to build apps. 
	Only a portion of the code is publicly available & other portion of only for OEMs. 
7. System Services
	Modular, focused components.
	ex: System server, SurfaceFlinger, MediaService
	These functionalities are exposed by the Android Framework API communicates with system services to access the underlying hardware. 
8. Android Runtime(ART)
	A java runtime environment provided by AOSP. 
	ART performs the translation of the app's bytecode into processor-specific instructions and the instructions are executed by the device runtime environment.
9. Hardware Abstraction Layer(HAL)
	A standard interface. 
	HAL let's developers implement functionality without affecting or modifying the higher level systems. 
10. Kernel
	Used to communicate to the underlying hardware on a device like any other OS kernel .

## The Linux Kernel
![[Pasted image 20260225191242.png]]
The Android Runtime(ART) relies on the Linux kernel for underlying functionalities like threading and memory management. 
Benefits of Android using a Linux kernel, 
- Getting Linux key security features. 
- Allow device manufacturers to develop hardware drivers for a well-known kernel. 
****
## Hardware Abstraction Layer(HAL)
![[Pasted image 20260225191352.png]]
Provides standard interface that exposes device hardware capabilities to the higher-level Java API framework.
HAL has multiple library modules which are relevant to specific hardware components like camera, Bluetooth, Audio,...
When a framework API makes a call to access device hardware, the Android system loads that specific library module for that hardware component. 
****
## Android Runtime(ART)
![[Pasted image 20260225192040.png]]
This is an application runtime environment used by the Android operating system.
Performs the translation of the application's byte code into native instructions. 
ART is written to run multiple virtual machines on low-memory devices by executing DEX files.
	Devices running on Android version 5.0(API level 21) or higher, each app runs in it own process and with it's own instance of the Android Runtime. 

> [!NOTE] DEX
> A bytecode format designed specially for Android and is optimized for minimal memory footprint. 
> 

****
## Native C/C++ Libraries
![[Pasted image 20260225194508.png]]
- ART and HAL are built from native code which requires native C/C++ libraries. 
- The android platform provides Java framework APIs to expose the functionality of some these native libraries. 
Ex: Access OpenGL ES through the android framework's Java OpenGL API to support drawing and manipulating 2D/3D graphics. 
*****
## Java API Framework
Android OS is available through APIs written in the java language. 
These APIs form the building blocks you need to create Android apps by simplifying the reuse of core, modular system components and services.

Example system components and services,
- A rich and extensible view system to build app UIs
- A resource manager providing access to non-code resources such as localized strings, graphics, and layout files. 
- A notification manager allows all apps to to display custom alerts on the status bar. 
- A activity manager that manages the lifecycle of apps and provides a common navigation back stack.
- Content providers that enable apps to access data from other apps.

## iPhone OS development Platform
iOS is a proprietary mobile OS by Apple Inc. 
It supports,
- Objective-C
- C
- C++
- Swift
It's based on the Macintosh OS X.

### iOS layered architecture
![[Pasted image 20260413014333.png]]
##### 1. Core OS layer
Components,
- Core Bluetooth framework
- Accelerator Framework
- External Accessary Framework
- Security Service framework
- Local Authentication framework
##### 2. Core service layer
Components,
- Address book framework: Provide programmatic access to the contact database.
- Cloud Kit framework: Medium for moving data between your app and iCloud.
- Code data framework: Technology for managing the data model of a Model View Controller app.
- Core Foundation framework: Interfaces that gives fundamental data management and service features for iOS apps
- Core location framework: Gives location and heading information to apps
- Core motion framework: Using this core motion framework Accelerometer based information can be accessed
- Foundation Framework
- Healthkit Framework: Handles health related information of users
- Homekit framework: Controlling connected devices in a user's home.
- Social framework: Simple interface for accessing the user's social media account.
- Storekit framework: Gives support for the buying of content and services from inside your iOS apps, a feature known as In-App Purchase

##### 3. Media layer
Components,
- UIKit graphics: Support for designing images and used for animating the content of your views.'
- Core graphic framework: The native drawing engine for iOS apps. It supports for custom 2D vector and image-based rendering.
- Core animation: optimizes the animation experience of your apps
- Core images: support for controlling video and motionless images in a nondestructive way
- OpenGL ES and GLKit: manages advanced 2D and 3D rendering by hardware accelerated interfaces
- Metal: It permits very high performance for your sophisticated graphics rendering and computation works

Audio Framework,
- Media Player framework: gives simple use to a user’s iTunes library and support for playing playlists
- AV foundation: an Objective C interface. It handles recording and playback of audio and video
- OpenAL: an industry standard technology for providing audio

Video Framework,
- AV Kit: provides interface for presenting video
- AV Foundation: gives advanced video playback and recording capability. 
- Core Media: describes the low level interfaces and data types for operating media

##### 4. Cocoa Touch layer
- Eventkit Framework: provides view controllers for showing the standard system interfaces and enables seeing and altering calendar related events
- Gamekit Framework: allows users share their game related information online
- iAd Framework: deliver banner-based advertisements
- MapKit Framework: Provides a scrollable map
- PushKit framework: provides registration support for VoIP apps
- Twitter Framework: generating tweets and support for creating URLs to access the Twitter service
- UIKit Framework: provides infrastructure for graphical, event-driven apps

### Factors to consider when choosing a platform
- Target audience(their preferences and key interests)
- Cost of development
- Device support required
- Application business model (ex: intent, monetization options, relationship with users)
- Technical features
- Third-party integrations
