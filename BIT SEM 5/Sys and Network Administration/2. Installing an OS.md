Linux distributions use a system manager daemon called `systemd` to streamline the boot process by,
	adding dependency management,
	support for concurrent startup process,
	logging...

> [!NOTE] System manager daemon
> A system manager daemon is a background process in an operating system that controls and supervises other system services and processes. 
> They handle,
> - Starting applications at boot
> - Monitoring system health
> - Providing functionality for other programs

### Linux Boot Process
During the bootstrapping(boot up), the kernel is loaded into memory and begins to execute. 
Admins can modify bootstrap configs by editing config files for the system startup scripts or by changing the arguments the boot loader passes to the kernel. 
![[Pasted image 20250827205645.png]]

1. Load BIOS/UEFI from NVRAM
	- The firmware(BIOS on old systems, UEFI on modern systems) is loaded from non-volatile memory(NVRAM).
	- It initializes system hardware and prepares the environment for the OS to load. 
2. Probe for hardware
	- BIOS/UEFI detects connected hardware. (CPU, RAM, Storage devices, network cards)
	- This is a part of the "POST(Power-On Self-Test)"
3. Select boot device
	- Based on the boot order configuration, the firmware decides from where to load the OS.
	- Ex: HDD/SSD, USB, CD/DVD or PXE(for network boot)
4. Identify EFI system partition
	- If UEFI is used, it looks for the EFI System Partition(ESP) on the selected disk.
	- This partition contains the bootloader and necessary boot files. 
5. Load Boot loader
	- The boot loader(commonly GRUB in linux) is loaded.
	- It provides a menu to choose which OS/kernel to boot (useful for dual-boot setups or multiple kernel versions).
6. Determine which kernel to boot
	- GRUB loads the kernel image chosen by the user (or the default one if no input is given).
	- Along with the kernel, the **initramfs (initial RAM filesystem)** is also loaded → it contains drivers and tools needed for mounting the root filesystem.
7. Load kernel
	- The Linux kernel is decompressed and initialized.
	- Kernel sets up memory management, device drivers, and mounts the root filesystem.
8. Instantiate kernel data structures
	- Kernel sets up **internal data structures** for managing processes, memory, I/O, etc.
	- At this point, the system is moving from firmware control to OS control.
9. Start `init`/`systemd` as PID 1
	- The kernel launches the **first user-space process**, usually `systemd` (modern Linux) or `init` (older systems).
	- This process has PID 1 and is responsible for starting all other processes.
10. Execute Startup Scripts
	- `systemd`(or `init`) runs initialization scripts/services.
	- Ex: networking, logging daemons, mount file systems, start GUI login manager. 
11. Running System
	- Finally, the system reaches its target state:
		1. `multi-user.target` (text console login)
		2. `graphical.target` (desktop login screen)

Main four phases are,
1. **Firmware phase (BIOS/UEFI) →** hardware checks + boot device selection.
2. **Bootloader phase (GRUB) →** load and choose kernel.
3. **Kernel phase →** load kernel + initramfs, setup core OS functions.
4. **User space (systemd/init) →** start services & login, leading to running system
#### BIOS vs UEFI
BIOS (Basic Input Output System)
- Older standard. 
- Stored on a chip in the motherboard. Runs in 16-bit real mode so it can only use limited memory(1mb).
- Runs a POST(Power-On Self-Test) to check hardware(CPU, memory,...) before booting. 
- Uses the MBR(Master Boot Record) partitioning scheme. 
- Provide only CLI support.
- Support disks up to 2TB and maximum of 4 primary partitions.
- Slower boot process compared to UEFI.
UEFI (Unified Extensible Firmware Interface)
- Modern replacement for BIOS. 
- More flexible and powerful. 
- Uses the GPT(GUID Partition Table) scheme. 
- Supports disks larger than 2TB. Allows up to 128 partitions.
- Runs in 32-bit or 64-bit mode allowing memory usage and advanced features. 
- Provides a graphical user interface(GUI) with mouse support. 
- Faster than BIOS boot time. 
- Support secure boot which helps prevent malware and unauthorized OS loading.
- Allows run pre-boot applications(diagnostics, network tools)
#### Boot Loaders
A boot loader is a small program that runs right after the system firmware(BIOS/UEFI) finishes its job. 
It's main role is to load the OS kernel into memory and hand over control to it. 

Why a boot loader ?
- Firmware can only handle very basic hardware initialization.
- The OS kernel is too complex and stored on disk.
Due to these reasons, boot loaders act as a bridge between firmware and the OS. 

Types of boot loaders, 
1. Single-stage
	Firmware directly loads the kernel into memory.
	Often used in embedded systems.
2. Multi-stage
	Step 1: Small loader in the MBR or UEFI
	Step 2: Loads the full boot loader
	Step 3: Loads the OS kernel

Ex: 
1. GRUB(GRand Unified Bootloader) : Common in linux systems, supports multiple OSes. 
2. Windows Boot Manager(bootmgr) : Used by windows systems.
3. LILO(Linux Loader) : Older linux boot loader. Replaced by GRUB.

#### GRUB
![[Pasted image 20250828114548.png]]
GRUB stands for **"GRand Unified Bootloader."**
A multi-stage boot loader developed by GNU project and the default boot loader of most of the linux distros.

> [!NOTE] GNU Project
> The GNU project is a free software, mass collaboration project to develop a completely free and Unix-like OS. 
> GNU is recursively acronym for "GNU's Not Unix".
> Goal is to provide users with the free to run, study and modify software. 
> Outputs: GNU Compiler Collection(GCC), GNU Emacs.

When you power on your system,
1. BIOS/UEFI runs. 
	Initializes hardware. 
	Finds a bootable device.
2. Stage 1 : Initial Grub Loader
	Located in the MBR(for BIOS) or EFI system partition(for UEFI).
	Small code enough to find and load stage 1.5 or stage 2.
3. Stage 1.5 : (Optional. Only used in BIOS systems, not in UEFI systems.)
	Stored right after the MBR.
	Adds filesystem drivers(ext4, NTFS)
	Allows grub to read from disk partitions.
4. Stage 2 : Full GRUB
	Main grub program.
	Loads the config file `grub.cfg`
	Displays the GRUB menu(OS/Kernel choices)
	Let's you edit boot parameters.
5. Kernel Loading
	After selection, GRUB loads the chosen OS kernel into memory.
	Also loads an `initramfs`(Initial RAM filesystem) if needed. 
	Passes control from the kernel to the OS. 

In BIOS systems, GRUB installed in the MBR(first 512 bytes) + rest of the code in the disk sector.
In UEFI systems, GRUB installed in the EFI system partition(ESP) as an `.efi` binary. 

#### GRUB Configs
![[Pasted image 20250828114428.png]]
GRUB config file is called, `grub.cfg` and it's kept in,
```sh
/boot/grub 
#or
/boot/grub2
```
We don't edit this file directly. Instead we edit the file at,
```sh
/etc/default/grub
```
After editing that file, we run,
```sh
sudo update-grub #(debain/ubuntu)
#or
grub-mkconfig -o /boot/grub/grub.cfg #(arch/fedora)
```
This command will translate your configurations into a proper `grub.cfg` file. 

Common GRUB config options,
1. `GRUB_BACKGROUND="/boot/grub/mywall.png"`
	Set a custom background image for the GRUB.
	Format must be readable by GRUB(JPEG, PNG, TGA).
2. `GRUB_CMDLINE_LINUX`
	Appends kernel parameters to linux boot entries.
	Used for troubleshooting or hardware control. 
	Ex: `GRUB_CMDLINE_LINUX="quite splash"`
		quite : hides boot messages
		splash : show splash screen
3. `GRUB_DEFAULT`
	Control which menu entry boot by default.
	Ex: `GRUB_DEFAULT=0`
	Values,
		0 : first menu entry
		1 : second menu entry
		2>3 : submenu navigation(3rd entry of the 2nd submenu)
		'saved': boots the last chosen entry
4. `GRUB_DISABLE_RECOVERY`
	Prevents the generation of recovery mode entries.
	Useful for simplifying menus (e.g., hiding advanced recovery options).
	Ex: `GRUB_DISABLE_RECOVERY="true"`
5. `GRUB_PRELOAD_MODULES`
	Defines a list of GRUB modules to load as early as possible.
	Useful when specific features(like LVM, RAID, cryptodisk) are required for booting.
	Ex: `GRUB_PRELOAD_MODULES="lvm cryptodisk part_gpt part_msdos"`
6. `GRUB_TIMEOUT`
	Number of seconds GRUB waits before auto-booting the default entry.
	Ex: `GRUB_TIMEOUT=5`
	Special values,
		0 : boot immediately, no menu.
		-1 : wait forever until user selects an entry.


GRUB supports a command-line interface for editing config file on the fly at boot time. Shell can be opened by pressing `c` in the GRUB menu. 
Ex: 
1. `help`
	Displays interactive help for available GRUB commands. 
2. `linux`
	Loads the linux kernel into memory. 
	You must specify the kernel file and the root file system.
```sh
linux /boot/vmlinuz-5.15.0 root=/dev/sda1 ro quiet splash
```
3. `boot`
	Starts the boot process using the kernel and `initrd` that were previously loaded.
```shell
linux /vmlinuz root=/dev/sda1 ro
initrd /initrd.img
boot
```
4. `reboot`
	Reboot the system immediately.
5. `search`
	Finds devices or partitions by file, filesystems label or UUID.
	Useful if you don't know which drive GRUB is seeing as `(hd0,1)`
```sh
search --file /vmlinuz
search --lable rootfs
search --fs-uuid 1234-ABCD
```
6. `usb`
	Tests and initialize USB support in GRUB. 
	Useful if you are booting from a USB stick and GRUB hasn't detected it yet. 
```sh
usb --init
```

Example: If you GRUB config is broken, you can manually boot linux,
```shell
set root=(hd0,1)
linux /boot/vmlinuz-5.15.0 root=/dev/sda1 ro
initrd /boot/initrd.img-5.15.0
boot
```
	1. Sets the root partition.
	2. Loads the kernel.
	3. Loads initram file system.
	4. Boots the OS.

#### System Management Daemons
![[Pasted image 20250828125157.png]]
A daemon is a background process in Unix/Linux systems that runs without direct user interaction. They typically starts at boot and continues running until shutdown and handles system-level services. (logging, scheduling, networking...)

System Management Daemons are special daemons responsible for managing core system services and resources. They keep the system stable, monitor process and ensure essential services are always available. 
Most of these daemons are part of the kernel implementation and they are not configurable and they don't require admin attention. 

![[Pasted image 20250828125348.png]]
System Management Daemons usually have low process ids(PID). 
Basically these are background processes. 

Examples of Common System Management Daemons
1. `init` (SysVinit)
	The classic Unix/linux init daemons(before `systemd`)
	Responsible for starting all other daemons and processes at boot. 
	Has the PID 1 and it make sure the system runs the right complement of services and daemons at any given time. 
	Init just run the scripts and commands that have been designed for execution in particular context.
	Responsibilities of `init`,
	- Setting the name of the computer
	- Setting the time zone
	- Checking disks with `fsck`
	- Removing old files from the `/tmp` directory.
	- Configuring network interfaces. 
	- Configuring packet filters. 
	- Starting up other daemons and network services. 
2. `Upstart`
	Event-based replacement for SysVinit. Used in older ubuntu versions.
3. `systemd`
	Modern `init` system and service manager.
	Manages system startup, services, sockets, devices, timers, etc..
	Replaced older systems like SysVinit and Upstart. 
	Systemd is a collection of programs, daemons, libraries , technologies and kernel components.
	It manages processes in parallel including network connections(networkd), kernel log entries(journald), and logins(logind).
	`systemctl` is an all-purpose command for investigating the status of systemd and making changes to its configuration.
4. `launchd`
	Apple's system management daemon. 
	Handles service startup and resource management in macOS.
5. Windows doesn't use the term daemons, but has services. (Ex: `services.exe`, `svhost.exe`) which serves the same role. 

#### Reboot and shutdown procedures
1. `halt`
	Perform essential duties required for shutting down the system. 
		- Logs the shutdown.
		- Kills non-essential processes.
		- Flushes cached filesystem blocks to disk.
		- Halts the kernel. 
	If ACPI(Power management) is enabled, the machine may power off. 
	Else, the system just halts and stays powered on(Screen frozen).
```sh
sudo halt
halt -p #halt and power off
halt -f #force immediate halt without contacting systemd/init
```
2. `reboot`
	Reboot the system.
	Similar to halt, but it triggers restart and gracefully stops services and unmount file system before rebooting. 
```sh
sudo reboot
reboot -f #force reboot immediately
```
3. `shutdown`
	The preferred, more flexible wat to halt or reboot. 
	Allows scheduling of shutdowns and sending warning to logged-in users. 
```sh
sudo shutdown [OPTIONS] [TIME] [MESSAGE]
sudo shutdown -r now #reboot immediately
sudo shutdown +10 "System shudown in 10 mins" 
sudo shutdown -c #Cancel sheduled shutdown
```
#### Drivers and the Kernel
The kernel hides the complexity of the system's hardware underneath. 
It provides and API for application programmers.
This well defined interface provide functionalities such as,
- Management and abstraction of hardware devices
- Process and threads(and ways to communicate among them)
- Management of memory(virtual memory and memory space protection)
- I/O facilities(filesystems, network interfaces, serial interfaces, etc)
- Housekeeping functions(startup, shutdown, timers, multitasking)

A device driver is an abstraction layer that manages the system's interaction with a particular type of hardware so that the rest of the kernel doesn't need to know it's specifics. 
The driver translates between the hardware commands understood by the device and a programming interface defined (and used) by the kernel.
