DNS(Domain Name System) server translates human-readable domain names into IP addresses so computers can find each other on a network. 
##### DNS Zone tree
![[Pasted image 20251222101103.png]]
The DNS namespace is organized as a hierarchical tree structure and its called a DNS zone tree. In order,
- The root(**.**) is the top.
- Top Level Domains(TLDs) like `.com, .org, .lk .uk`
	Two types,
	1. Country code domains(ccTLDs) - ex: `.lk, .uk`
	2. Generic top-level domains(gTLDs) - ex: `.com, .org`
- Second Level Domain like `google.com`
- Subdomains like `mail.google.com`
Instead of one server managing the entire tree, it break down into sub-trees and delegated across many servers. A DNS zone is a portion(sub-tree) of this DNS tree that is managed by a specific DNS server.  

1. **Forward zone**
	Maps domain names into IP addresses. 
	Ex: `www.example.com` --> `93.184.217.34`
	Used when,
	- Browsers load websites
	- Application connect to servers
	- Clients locate services
2. **Reverse zone**
	Maps IP addresses into domain names.
	Implemented using special domains,
	- `in-addr.arpa`(for IPv4)
	- `ip6.arpa`(for IPv6)
	Ex: `93.184.217.34` --> `www.example.com`
	Used when,
	- Logging and auditing(identify hosts by name)
	- Security checks(email servers use reverse DNS to detect spam)
	- Network troubleshooting and monitoring. 
##### DNS resolving process : 
![[Pasted image 20251222101533.png]]
Ex: Resolve `www.google.com` by a browser. 
1. Browser cache check.
	Your browser check its own DNS cache. 
	- If it know the IP -> done
	- If not -> continue
2. OS/local DNS cache
	The OS check its OS DNS caches and hosts file(if configured).
	- If found -> return the IP to the browser
	- Else -> continue
3. Query send to the **Recursive Resolver**
	The OS sends the query to a recursive DNS resolver.
	Its usually provides by,
	- ISP
	- enterprise DNS server
	- Public DNS(Google: `8.8.8.8`, Cloudflare: `1.1.1.1`)
4. Recursive resolver check its cache.
	- If cached -> return result immediately
	- If not -> begin iterative querying
5. Query to root DNS server
	query is similar to : `Where I can find .com ?`
	Root server doesn't know the IP. 
	It responses with referral to a `.com` TLD(top-level-domain) server. 
6. Query to TLD server
	Resolver asks the `.com` TLD server : `Where I can find google.com ?`
	TLD server responds with **authoritative name servers** for google.com
7. Query to authoritative DNS server
	`What is the IP of www.google.com ?`
	It responds with,
	- `A` record (IPv4) or
	- `AAAA` record (IPv6) 
	This is the final answer. 
8. Response cache
	The resolver stores the answer in cache with a TTL and sends the IP back to the client(OS/Browser)
9. Browser connects to the serves using a TCP/QUICK connection and loads the website. 

Delegation is in order,
- Root server
- TLD
- Authoritative domain servers
- Delegation of authority to subdomain servers
#### DNS Database
A DNS database is the collection of DNS data that a DNS server uses to answer queries. 
These databases are stored as,
- Zone files(in server like BIND)
- Internally in DNS server storage(Windows DNS, managed DNS services)
Each database corresponds to a DNS zone and contains resource records(RRs). 

A DNS database stores mappings such as,
- Domain name -> IP
- IP -> domain name
- Mail server for a domain
- Name server for a zone
- Service discovery information
All of these stored as a resource record. 
#### DNS Resource Record(RR)
A single entry in the DNS database. 
It follows a standard format,
```xml
<NAME> <TTL> <CLASS> <TYPE> <RDATA>
```
1. NAME
	Domain name the record applies to.
	ex: `www.google.com`
2. TTL(Time To Live)
	How long(in seconds) the record can be cached.
	Ex: `3600`
3. CLASS
	Almost always `IN` stands for (Internet).
	
4. TYPE
	Defines what kind of record it is,
	- `A` - IPv4 address
	- `AAAA` - IPv6 address
	- `MX` - Mail server
	- `NS` - Name server
	- `CNAME` - Alias
	- `PTR` - Reverse lookup
	- `SOA` - Start of Authority
5. RDATA
	The actual data, depends on the records TYPE. 
Ex:
A record
```txt
www.example.com   3600   IN   A   93.184.216.34
```
AAAA record
```txt
www.example.com   3600   IN   AAAA   2606:2800:220:1:248:1893:25c8:1946
```
MX record
```txt
www.example.com   3600   IN   MX   10 mail.example.com.
```
NS record
```txt
www.example.com   3600   IN   NS   ns1.example.com.
```
PTR record (reverse DNS)
```txt
34.216.184.93.in-addr.arpa.   3600   IN   PTR   www.example.com.
```
SOA(Start Of Authority) - a special record type compared to others
```txt
example.com  IN  SOA  ns1.example.com.  admin.example.com. (
	2025122101 ; Serial
	7200 ; Refresh
	3600 ; Retry
	1209600 ; Expire
	3600
) ; Minimum TTL
```
This defines zone authority, zone versioning and replication behavior.

Special characters in a resource record,
1. `;` - comments
	Everything after `;` on a line is a comment. 
```
www.example.com.  IN A 192.0.2.1 ; Web server
```
2. `@` - Zone origin(current domain)
	Represent the root of the current zone
	Defined by `$ORIGIN`
```
$ORIGIN example.com.
@   IN SOA ns1.example.com. admin.example.com.
@   IN MX 10 mail.example.com.
```
3. `( )` - Multi-line grouping
	Used to split long records across multiple lines. 
	Improves readability. Common on SOA records. 
	See the SOA example above. 
4. `*` - Wildcard
	Matches any subdomain not explicitly defined. 
```
*  .example.com.  IN  A  192.0.2.10
```
	This matches a.example.com, test.example.com
	But this doesn't match to example.com or existing explicit records.

#### Email & Security Related DNS Records
these are usually stored as **TXT records**.  
1. SPF(Sender Policy Framework)
	Prevents email spoofing by defining which servers can send mail for a domain. 
	Mail server checks SPF record of sender domain. If sender IP isn't allowed, message may be rejected or marked spam. 
Ex:
```
example.com. IN TXT "v=spf1 ip4:192.0.2.10 include:_spf.google.com -all"
```
	Allowed : listed IPs + Google
	-all : reject everything else
2. DKIM(DomainKeys Identifies Mail)
	ensure email integrity and authenticity. 
	Outgoing mail is digitally signed. Receiving server verifies signature using DKIM public key in DNS. 
Ex:
```
selector1._domainkey.example.com. IN TXT (
  "v=DKIM1; k=rsa; p=MIIBIjANBgkq..."
)
```
3. DMARC(Domain-based Message Authentication, Reporting & Conformance)
	Tells receiving servers what do if SPF of DKIM fails. 
	Builds on SPF + DKIM. Defines policy + reporting. 
Ex:
```
_dmarc.example.com. IN TXT "v=DMARC1; p=reject; rua=mailto:dmarc@example.com"
```
	Policies,
		none : monitor only
		quarantine : spam folder
		reject : block
4. DNSSEC(DNS Security Extension)
	Protects DNS from spoofing and cache poising. 
	It digitally signs DNS records and allows resolvers to verify authenticity.
	Key DNSSEC record types,
	- DNSKEY - public key for the zone
	- RRSIG - Digital signature of records 
	- DS - Links child zone to parent(chain of trust)
	- NSEC/NSEC3 - Proof of non-existence
Ex:
```
example.com. IN DNSKEY 257 3 13 AwEAAc...
```

#### DNS debugging tools
1. `nslookup`
	A basic DNS query and troubleshooting tools. 
	Has two modes : Interactive and non-interactive
	Suitable for quick, simple lookup. 
2. `dig`(Domain Information Groper)
	Advanced DNS diagnostic tool. 
	It shows detailed DNS responses, including flags, TTL, and authority sections. 
	Commonly used by sysadmins since its script-friendly, precise and reliable. 
	Use it when you need deep technical insight into how DNS resolution work. 
3. `host`
	Fast, human readable DNS lookup.
	It resolves names into IP address with minimal output. 
	Ideal for clean, concise result without extra details. 
4. `drill
	Part of the IDNS library, designed to be a modern alternative for `dig` and commonly used for DNSSEC(DNS Security Extensions) debugging. 
	Ideal for DNSSEC or Advanced DNS validations. 
5. `delv`(Domain Entity Lookup & Validation)
	A DNSSEC validation tool which performs the cryptographic validation to ensure the data hasn't been tampered with.
	Best for: Verifying that a DNS record is authentic and signed correctly.
##### BIND(Berkeley Internet Name Domain)
the most widely used DNS software on Unix systems. 
Implements DNS systems and allow a machine to act as a DNS server. 

with BIND, a server can function as,
- Authoritative DNS server
- Recursive(caching) DNS resolver
- Forwarding DNS server

BIND distribution has 4 major components, 
- A name server daemon called "named" - answer queries.
- A resolver library - queries DNS servers on behalf of users
- CLI - run tools like nslookup, dig, host.
- A program to remotely control "named" called `rndc`
