 HTTP (HyperText Transfer Protocol) is an application-layer communication protocol used for transferring data on the Web between a client (usually a browser) and a server.

It follows the reqest-response model,
```
Client requests a resource → Server responds with data
```

#### URLs
- Uniform Resource Locators. 
- an identifier that specifies how and where to access a resource.

Example Request,
```http
GET /index.html HTTP/1.1
Host: example.com
User-Agent: Chrome
```
The first line of a request specifies an action for the server to perform.
It consists of
- a request method
- a path on which to perform the action
- and the HTTP version to use.

Example response,
```http
HTTP/1.1 200 OK
Content-Type: text/html
<html>...</html>
```
Has a three digit numeric status code. (The phrase that follows it is a helpful English translation that software ignores.) 
The first digit in the code determines its class

**Headers**
- Headers specify metadata about a request or response
	Ex: 
	whether to allow compression, 
	what types of content are accepted, expected, or provided; 
	how intermediate caches should handle the data
- Headers are separated from the message body by a blank line.
- For requests, the body can include parameters (for POST or PUT requests) or the contents of a file to upload.
- For responses, the message body is the payload of the resource being requested (e.g., HTML, image data, or query results)

#### Components of a web app

- Most sites use web servers either to proxy HTTP connections to application servers or to serve static content directly.
Features provided by web servers include:
- Virtual hosts, allowing many sites to coexist peacefully within a single server
- Handling of TLS connections
- Configurable logging that tracks requests and responses
- HTTP basic authentication
- Routing to different downstream systems according to requested URLs
- Execution of dynamic content through application servers
#### Load Balancers
Load balancer is a system that manage the number of requests based on a defined algorithm to make sure no server is get overloaded.
- Load balancers do not process requests but merely route them to other systems.
- If one of the servers experiences a problem, the health check mechanism on the load balancer detects the problem and removes the errant system from the server pool until it becomes healthy again.
- it can easily be removed

Common load balancing algorithms,
- Round robin - requests are distributed among the active servers in a fixed rotation order
- Load equalization - new requests go to the downstream server that’s currently handling the smallest number of connections or requests
- Partitioning - selects a server according to a hash of the client’s IP address.
#### Caches
Caches live between clients and web servers and store the results of the most frequent requests, sometimes in memory.
Types,
- Browser caches
- Proxy cache
- Reverse proxy cache
