Single Sign-On (SSO) is an authentication mechanism that allows a user to log in once and then access multiple related applications or services without logging in again.
![[Pasted image 20251227010721.png]]
Workflow,
1. User tries to access an application
    Ex: Email, Learning Portal, or HR system.
2. Application redirects the user to a central Identity Provider (IdP)  
    Ex: Google, Microsoft Entra ID (Azure AD), Okta, Keycloak, etc.
3. User authenticates once  
    Using password, MFA, biometrics, etc.
4. Identity Provider issues a trusted token  
    The token proves the user’s identity (e.g., SAML assertion, OAuth token, OpenID Connect ID token).
5. Application accepts the token and grants access  
    No additional login is required.
6. User accesses other applications  
    Those apps trust the same Identity Provider → no re-login needed.
#### LDAP(Lightweight Directory Access Protocol)
LDAP is a protocol used to **access and manage directory services** over a network. 
A directory service is a specialized database optimized for,
- Reading/searching(fast lookups)
- Hierarchical data
- Centralized identity information

LDAP data is stored as a tree called the Directory Information Tree(DIT).
```bash
dc=university,dc=edu
 ├── ou=students
 │    └── uid=2021cs001
 ├── ou=staff
 │    └── uid=prof001
 └── ou=groups
      └── cn=cs-department
```
![[Pasted image 20251227012244.png]]
Each entty,
- Has a "Distinguished Name"(DN)
- Contains attributes(uid, cn, mail, memberOf, etc)
![[Pasted image 20251227012821.png]]

LDAP often work behind the scene in an SSO system.
```mathematica
User → Application → Identity Provider (IdP) → LDAP Directory
```
