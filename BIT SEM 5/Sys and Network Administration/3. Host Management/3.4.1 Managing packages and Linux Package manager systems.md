A package manager is a tool that automates the process of installing, upgrading, configuring and removing software on a linux system. 

Traditionally Unix/linux software was shared as **source code archives**, usually as `gzipped` tarballs(`.tar.gz` or `tgz` files)
You have to unpack, configure, compile and install them manually. 

This was time consuming, error-prone and required development tools. 
Packaging systems were developed as a solution for this. 

A package contains,
- Pre-compiled binaries
- Metadata(version, description, maintainer info)
- Dependency information
- Configuration templates

A package manager uses this package information to install software with one command(ex: `apt install <package-name>` or  `yum install <package-name>`), automatically handles dependencies and keep the system clean and updated. 

There are two major package families in linux, 
1. **Debain-based (.deb)**
- Used by any debain based distros(ex: Ubuntu, linux mint, Kali)
- Package ends with `.deb` extension. 
- Tools,
	1. `dpkg` : low-level package manager tool(works with `.deb` file directly)
	2. `APT`(Advanced package manager) : high-level package manager built on top of `dpkg`. Handles dependencies, online repositories, updates.  
Ex: 
```sh
sudo apt update
sudo apt install firefox

sudo dpkg -i package.deb #install
sudo dpkg -r package-name #remove
dpkg -l #list all installed packages
```

2. **Red Hat-based (.rpm)**
- Used by Red Hat, Fedora, Cent OS, openSUSE. 
- Packages end with `.rpm` extension.
- Tools,
	1. `rpm` : low-level package tool(works with `.rpm` files directly)
	2. `yum`(older)/ `dnf`(modern) : high-level managers that fetch from repos and resolve dependencies.  
```sh
sudo dnf install firefox
```
