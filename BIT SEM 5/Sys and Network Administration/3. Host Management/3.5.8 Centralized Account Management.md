In medium to large organizations with hundreds of server or users, managing them individually becomes a nightmare. 
centralized account management solves this by keeping one central user database that all systems refer for authentication and authorization. 

How it works,
Instead of each server having its own `/etc/passwd`, they all consult a central directory service over the network(like LDAP or Active Directory).

Ex: 
- When a user logins to the any Linux server, PAM can be configured to query the LDAP server instead of local files. 

Benefits,
- One place to manage all users and passwords.
- Consistent access policies across systems. 
- Better security and auditing.

#### LDAP(Lightweight Directory Access Protocol)
LDAP is a protocol for accessing and maintaining distributed directory information service, similar to a read-optimized database designed to storing hierarchical information such as users, groups, devices and policies. 

Common examples,
- OpenLDAP
- Microsoft Active Directory(uses LDAP as a part of its protocol suite)
- 389 Directory Server(by Red Hat)
- Apache Directory Server
#### Active Directory(AD)
Microsoft Active Directory(AD) is a directory service built on LDAP and Kerberos. It's the standard identify and access management(IAM) system in Windows environments. 

> [!NOTE] Kerberos
> Kerberos is ==a network authentication protocol that uses secret-key cryptography to provide strong authentication for client/server applications over an insecure network==. It issues "tickets" to allow users to prove their identity to services without sending passwords over the network, which is widely implemented in operating systems like Windows and Linux.

Core components, 
- Domain Controller(DC) : The central server that stores user accounts, passwords, and policies.
- Domains : Logical groupings of users, computers and resources. 
- Organizational Units(OUs) : Subdivisions inside a domain for structuring users and policies. 
- Group Policy : Mechanism for centrally managing configuration and security settings.
#### Application-Level Single Sign-On(SSO)
Single Sign-On(SSO) allows users to log in once and gain access to multiple applications without re-entering their passwords. 

How it works,
1. Identity Provider(IdP) : stores and verifies user credentials. (ex: Google, Okta, Azure, AD)
2. Service Provider(SP) : the applications that users want to access(ex: Gmail, Slack, Jira)
3. The IdP authenticates the user and issues a token or assertion that SPs trust. 

Ex:
- User visits `myapp.com` --> Redirect to Google(IdP)
- Google authenticates the user.
- Google sends an ID token(JWT) back to `myapp.com`.
- The app verifies it --> user is logged in. 

Common SSO technologies,
1. SAML 2.0 : XML based, used by enterprises like Google workspace, Salesforce
2. OAuth 2.0 : Authentication framework. 
3. OpenID Connect(OIDC) : Built on OAuth 2.0. Modern authentication for web/mobile apps. 
4. Kerberos : Tickets based SSO used in AD environments. 

#### Identity Management Systems(IdM/IAM)
An Identity and Access Management(IAM) or Identity Management(IdM) system is a complete framework for managing digital identities across an organization. 

It includes, 
- Authentication(verifying identity)
- Authorization(what users can do)
- Provisioning(creating and deleting accounts)
- Auditing and compliance

Ex:
- FreeIPA(Open source IAM)
- Red Hat Identity Management
- Azure Active directory(AAD)
- Okta, Auth0, Keycloak

IdM/IAM = LDAP + Kerberos + Policies + SSO
Identity Management Systems build on LDAP and add,
- Kerberos for secure authentication
- SSO for seamless access
- Role-based access control(RBAC)
- Certificate-based authentication
- Web management tools
