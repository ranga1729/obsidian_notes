**Root user** is the superuser in Linux with full control over the system.

Ways to manage login as root,
1. Direct login as root
	Not recommended. Many systems has disabled direct root login by default. 
2. `su` - switch user
	Used to temporarily switch to root or another user. 
3. `sudo` - privilege escalation
	Runs specific commands with root privileges without switching users. 
	Safer than `su`.
```sh
sudo su //change to root
```
#### Shell and Terminal
![[Pasted image 20250903121231.png]]
In Linux, a shell is a command-line interpreter that provides a user interface to the OS. It acts as an intermediary, translating user commands into instructions that the linux kernel can understand and execute. 
	Ex: Bash(Bourne Again SHell), Zsh, Fish, Ksk, Tsch
A terminal is a graphical program that provides a window where users can interact with the shell.
(The shell is a program running within that terminal window.)
#### Shell types
You shell(ex: bash) decides which config files to load depending on it's type,
1. Login shell
	- Used to run profile files.
	- Start when you log into a system for the first time. 
	- Allows users to type username and their password.
	- First reads `/etc/profile` for system wide settings like (PATH, locale, ...)
	- Then reads first found among,
		`~/.bash_profile`
		`~/.bash_login`
		`~/.profile`
		Typically users put environment variables, PATH modifications and startup programs here. 
2. Non-login shell
	- Used to run interactive tweaks. 
	- Any shell star after you logged in. 
	- Reads `~/.bashrc` (Contains aliases, functions and prompt settings)

Many distros chain login shells and non-login shells to keep the consistent. 
#### `sudo` command
`/etc/sudoers` file defines,
- which users can run `sudo`
- which commands they allows to run
- on which machine(important for server farms)
```sh
sudo cat /etc/sudoers
```
![[Pasted image 20250903132253.png]]
When `sudo` is executed, it asks for your own password and keeps the session for 5 mins. (this timeout is configured in the above file).

![[Pasted image 20250903141118.png]]
- `Host_Alias` define groups of machines. 
	`CS` group has computer `tigger`, `anchor`, `pipe`, `moet` and `sigi`
- `Cmnd_Alisa` define commands and absolute paths to the executables.
	`DUMP` : backup/restore command
	`WATCHDOG` : process and control command
	`SHELL` : interactive shell commands
- Permissions
	Users `mark` and `ed` can run any command on hosts from `PHYSICS` groups.(`eprince`, `pprince`, `icarus`)
	User `herb` can run `/usr/sbin/tcpdump` on `CS` hosts and run the command alias `DUMP` on `PHYSICS` hosts, but only as the operator, not as the root.
	User `lynda` can run any command on any hosts as any user, except the `SHELL` command alias.(prevent the root shell)
	Usergroup `wheel` can run all commands on all hosts, except on `PHYSICS` machines but allow to run `WATCHDOG` command alias  without password. 

Every sudo command is  logged in `/var/log/auth.log`(debain).

- User
- Command
- From which directory
- On which machine
#### Advantages of `sudo`
- Command logging.
- User can perform commands without having unlimited root access.
- The real root password can kept secret. 
- `sudo` is faster than `su`
- Privileges can be revoked without changing the root password. 
- A list of users with root privileges is maintained. 
- A single file can control access for an entire network. 
#### Disadvantages of `sudo`
- If a normal user is listed in `/etc/sudoers`, they can run root-level commands. (a single point of failures). That personal account is now as powerful as too, just gated by their own password. 
- Logging bypass with shell escapes or sudo shells

1. Shell escapes
Some programs allow you to drop into shell from inside them. 
Ex: 
	If a sudoer is allowed to run `less` as root, inside `less`, you can type `!bash` which starts a root shell. 
	Now you are root, but the logs only say you ran `less`. 
	Sudo logging doesn't record hidden commands. 
```sh
sudo less /etc/shadow
```

2. Using `sudo sh` or `sudo su`
If a sudoer is allowed to run `sudo su` or `sudo sh`, they can immediately open a full root shell.
From there, any further command won't appear in sudo logs. 

The root account can be disabled. 
Ex: Ubuntu ships with the root account locked and all admin access funneled through `sudo` or a GUI equivalent. 
#### System Accounts(Pseudo-users)
On linux, every process is run under some user account. (Identified by `UID`)
Not all accounts represent real human users, some are system accounts created by software packages for security reasons. 

| UID    | User type                              |
| ------ | -------------------------------------- |
| 0      | root                                   |
| 1-9    | reserved for internal/system proceses  |
| 10-100 | pseudo-users or system service account |
Pseudo-user examples,
- `daemon`
- `bin`
- `www-data`(for apache/nginx servers)
- `mysql`(for MySQL database)
- `postfix`(for mail software)

These accounts exists for that services can run under limited privileges. 
Normal human user logins gets a shell(`/bin/bash`). 
But system accounts don's get interactive logins, instead they get a special shell from `/etc/passwd`.
- `/bin/false` -> immediately exits without doing anything.
- `/bin/nologin` -> prints a message _“This account is not available”_ and exits.

**Reason:**
Attackers sometime try log in using password alternatives like SSH keys. 
Even if such a login succeeds, if the account shell is set to above mentioned two, they can not get an interactive shell sessions.
