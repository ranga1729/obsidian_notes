##### Linux Storage Management Layers
![[Pasted image 20251205220954.png]]
Linux storage management involves layered stack for flexibility, all working under the kernel's system management to provide structured data access from applications down to hardware. 

Layers,
1. The Physical storage layer : Actual hardware installed. 
	Ex: Disks, SSDs, NVMe drivers
	Usually appear as `/dev/sda`, `/dev/sdb`, `/dev/nvme01`
2. The Partition layer : The traditional method of dividing a physical disk into isolated sections/partitions. 
	Ex: `/dev/sda1`, `/dev/sda2`, `/dev/sdb1`
3. The Aggregating & Redundancy layer(RAID - Redundant Array of Independent Disks) : Combines multiple devices(or partitions) into a single logical unit to achieve either performance(striping), redundancy(mirroring/parity) or both.
	Ex: After combining devices/partitions, the result is a new "device" like `/dev/md0`
4. The Logical Volume Management(LVM) layer : 
	Volume Groups(VG) - A pool/big container of storage that consist of multiple physical disks, partitions or RAID arrays or raw spaces. 
	Logical Volumes(LV) - Virtual partition carved out of the volume group. Unlike physical partitions, LVs can be resized, mirrored, or snapshotted while the system is running.
5. The Presentation layer : 
	Access data through mounted file systems via standard system calls.

### Disk Partitioning 
Common disk partitioning schemas,
1. MBR
2. GPT

**MBR(Master Boot Record)**
- Older partitioning standard.
- Stored in the first sector of the disk. 
- Support up to 2TB
- Allows maximum 4 primary partitions. 
- Used with legacy BIOS.
- Less fault tolerant.

**GPT(GUID Partition Table)**
- Modern partitioning standard
- Part of the UEFI specification
- Support large disks(over 9ZB in theory)
- Allows 128+ partitions
- Stores multiple copies of partition data
- Uses CRC checksum for data integrity

- Linux used **GParted**(GNOME Partition Editor) a free & open source graphical tool for managing disk partitions.

### Logical Volume Management(LVM)
LVM is a flexible disk management system that lets you manage storage dynamically that traditional partitioning.
Instead of fixed-size partitions, LVM lets you resize, combine and manage disks easily even when the system is running.

Hierarchy,
1. Physical Volume(PV)
	A physical storage device prepared for LVM, initialized using LVM metadata.
	It can be an entire disk(ex: `/dev/sdb`) or a disk partition(ex: `/dev/sdeb1`).
	Purpose: Provides raw storage blocks to LVM.
2. Volume Group(VG)
	A storage pool created by one or more physical volumes. 
	Purpose: Acts like a virtual disk.
Ex: 
	PVs : `/dev/sdb1` and `/dev/sdc1`
	VG : `vg_data` (combined capacity of `sdb1` and `sdc1`)
3. Logical Volume
	A virtual partition created from a Volume Group. 
	This where we create file systems and mount them.
	can be resized easily. 
Ex: Acts like a regular partition (`/dev/vg_data/lv_home`)

Steps of configuring LVMs,
1. Creating and initializing physical volumes. 
2. Adding the physical volumes to a volume group.
3. Creating logical volumes on the volume groups.
LVM Commands,

| Entity          | Operation | Command   |
| --------------- | --------- | --------- |
| Physical Volume | Create    | pvcreate  |
|                 | Inspect   | pvdisplay |
|                 | Modify    | pvchange  |
|                 | Check     | pvck      |
| Volume group    | Create    | vgcreate  |
|                 | Modify    | vgchange  |
|                 | Extend    | vgextend  |
|                 | Inspect   | vgdisplay |
|                 | Check     | vgck      |
|                 | Enable    | vgscan    |
| Logical Volume  | Create    | lvcreate  |
|                 | Modify    | lvchange  |
|                 | Resize    | lvresize  |
|                 | Inspect   | lvdisplay |

Key advantages of LVMs,
- Move logical volumes among different physical devices. 
- Grow and shrink logical volumes on the fly. 
- snapshot support(useful for backups)
- Support mirroring or stripping
- replaces on-line drives without interrupting services.

### Redundant Arrays of Inexpensive Disks
RAID is a storage technology that combine multiple physical disks into a single logical unit to improve performance and reliability by replicating data across multiple drives. 

RAID can be,
1. Software RAID(common in linux via `mdadm`)
2. Hardware RAID

With RAID, multiple disks are organized so data is,
- Striped(split across disks)
- Mirrored(copied to another disks)
- Parity-protected(error recovery data stored)

RAID Levels,
1. RAID 0 - Stripping(Performance)
	![[Pasted image 20251220171216.png]]
	Data split across multiple disks without redundancy.
	Fast read/write
	If one disk fails --> all data lost
	Minimum disk = 2
	Use case : High performance, non-critical data
2. RAID 1 - Mirroring(Redundancy)
	![[Pasted image 20251220171307.png]]
	One data copied to two disks.
	Slower writes, fast reads
	Survive failure of one disk
	Minimum disks = 2
	Use case : Critical system or OS disks
3. RAID 5 - Striping + Parity
	![[Pasted image 20251220171933.png]]
	Data and parity distributed across disks.(p indicates parity disk at each row) 
	Can survive one disk failure. 
	Good balance of speed and redundancy.
	Minimum disks = 3
	Use case : File servers, general storage
4. RAID 6 - Double Parity
	![[Pasted image 20251220172419.png]]
	Similar to RAID 5 but with two parity block(p, q at each row)
	Survive two disk failures. 
	Slower writes that RAID 5. 
	Minimum disk = 4
	Use case : Large storage arrays
5. RAID 10 (1 + 0) - Mirroring + Stripping
	![[Pasted image 20251220172231.png]]
	A combination of RAID 1 + RAID 0
	High performance and redundancy.
	Survive multiple failures
	Minimum disks = 4
	Use case : Databases, high-performance systems

- Linux uses `mdadm` as a software to maintain a RAID. Managed at OS level. 

##### RAID vs Backup
RAID doesn't protect against, 
	Accidental deletions.
	File corruptions.
	Malware.
Therefore, RAID is not a backup.

#### Traditional Linux File System Management 
These are the common terminology in file systems, 
- File - a collection of data
- Directory - a container for file
- Inode - stores metadata about a file(permissions, owner, size, pointers to data blocks)
- Block - the smallest unit of storage on disk. 
- Superblock - contains metadata about the entire file system
- Mount point - directory where a filesystem is attached. 
##### File Polymorphism
Means that Linux can work with many different filesystem types in a uniform way.
Ex: 
	ext4, XFS, FAT32, NTFS
##### Filesystem formatting - `mkfs`
Before a disk or partition can store files, it must be **formatted** with a filesystem.
The command `mkfs`(make file system) writes filesystem structures(superblock, inodes, etc) to the disk. 
Ex:
```bash
mkfs.ext4 /dev/sda1
```
##### Check and repair filesystems - `fsck`, `tune2fs`
- `fsck` (file system check)
Scan filesystem for error and repairs them.
Usually run at boot or manually when problems occur. 
Ex: 
```bash
fsck /dev/sda1
```
- `tune2fs`
Used specifically for ext4/ext3/3xt4.
Adjust filesystem parameters(check intervals, reserved blocks, labels)
Ex:
```bash
tune2fs -l /dev/sda1
```
##### Filesystem mounting - `mount`
Mounting attaches a filesystem to the Linux directory tree.
Ex:
```bash
mount /dev/sda1/ /mnt/data
```
After mounting,
- Files become accessible through `/mnt/data`
- Without mounting, the OS cannot access the data. 
##### Setup for automatic mounting - `fstab`
The file `/etc/fstab` defines which file systems are mounted automatically at boot.
Each entry specifies,
- Device
- Mount point
- Filesystem type
- Mount options
Ex entry:
```bash
/dev/sda1 /home ext4 defualts 0 2
```
##### Swapping recommendations - `mkswap`, `swapon`
Swap is disk space used as virtual memory when RAM is insufficient. 
- `mkswap`
Formats a partition or file as swap space.
Ex:
```bash
mkswap /dev/sda2
```
- `swapon`
Active swap space
Ex:
```bash
swapon /dev/sda2
```
Swap helps prevent crashes when memory is exhausted, but it’s slower than RAM.

#### Next Generation File Systems
Designed to overcome the limitation of traditional linux file systems(ext4, XFS)
They combine **file system + volume management** and focus on **data integrity, scalability, and easy administration**.

Issues with traditional file systems,
- Rely on external tools(LVM, sfck)
- Have limited protections against silent data corruption.
- Do not manage storage as a whole

ZFS and BTRFS aims to,
- detect and repair data corruption
- Manage disks , volumes and snapshots natively. 
- scale to very large storage systems.

#### ZFS (Zettabyte File System)
![[Pasted image 20251220180616.png]]
Developed by sun Microsystems. 
Combines filesystems + RAID + volume manager.
Known for strong data integrity guarantees.

Features, 
- Storage pool(zpool) : Collection of physical disks
- Datasets : Filesystems created inside a pool
- Copy-on-Write : Data is never overwritten in place
- End-to-end checksumming and self-healing : detect silent corruption and repairs corrupted data using redundancy.
- Snapshots & cloning 
- Built in RAID
- No `fsck` required.
Advantages,
- Extremely reliable.
- Excellent for servers, backups, NAS
- Minimal risk of corruption
Disadvantages,
- High memory usage
#### BTRFS(B-tree File system)
Native linux next gen filesystem 
Designed as a replacement for ext4.

Key concepts, 
- Sub-volumes : logical file system units
- Copy-on-write
- checksum for data and metadata
- Integrated volume management
Features,
- snapshots and rollbacks
- online resizing
- Built-in RAID
- Compression
- send/receive for backup
Advantages,
- Lightweight compared to ZFS
- Native to linux
- Ideal for desktop and servers
Disadvantages,
- RAID 5/6 is unstable
- Less mature than ZFS
- Slightly weaker integrity model than ZFS
