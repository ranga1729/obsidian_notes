The basic purpose of a file system is to represent and organize the system's storage resources.

For an Operating System, the file system is consist of four major components, 
1. Namespace
	Linux organizes file into a single hierarchical directory(rooted at `/`).
	Every object(file, directory, device, socket, etc...) has a path as its name in this namespace. 
2. API
	Linux expose system calls like `open()`, `read()`, `write()`, `close()`, `stat()`, `mmap()`, `ioctl()`, etc...
	These calls are how programs navigate and manipulate files in the file system.
3. Security model
	Linux uses a **permission model**.
	Controls who can read, write, or execute and how resources are shared/hidden. 
	Each file has an owner, group, and mode bits(`rwx`).
	Extended Access Control Lists(ACLs) and SELinux/AppArmor can add more fine-grained rules. 
4. Implementation
	Different file systems(`ext4`, `XFS`, `Btrfs`, `ZFS`, `FAT`, `NTFS`, etc...) provide the actual on-disk structure. 
	The linux **VFS**(Virtual File System) layer abstract these differences, so applications use the same API regardless of underlying file system.
	The kernel handles mapping logical operations to the block devices and disk hardware. 
#### Pathnames
A pathname specifies the location of a file or directory in the filesystem hierarchy.  
Two types,
1. Absolute pathname
	Start from the rood directory(`/`)
	Always point to the same file not matter the current working directory. 
Ex: `/home/alex/docs/report.txt`
2. Relative pathname
	Start from the current working directory(CWD) of a process. 
Ex: If CWD = `/home/alex` then `docs/report.txt` -> `/home/alex/docs/report.txt`

Special symbols in pathnames,
- `.` : Current directory
- `..` : Parent directory
- `~` : User's home directory
#### Mounting and Unmounting
In windows, drives are assigned a letter like `C:`, `D:`. 
But Linux has a single directory tree rooted at `/`. To access another file system(ex: new partition, external USB, network drive), you must **mount** it into the tree. 

1. List the drive list and pick the drive you want to mount
List all block devices and their mount point. A new entry like `/dev/sdb1` will appear when you plug in a USB drive.
```sh
lsblk
```
![[Pasted image 20250917120409.png]]

Provide detailed information about all disk partitions on your system. 
```sh
sudo fdisk -l 
```
![[Pasted image 20250917120012.png]]

2. Crete a mount point
Create a directory where the USB drive's contents will be accessible. 
Ex: 
```sh
sudo mkdir /mnt/usb
```

3. Mount the drive to the mount point
Attaches a filesystem to an existing directory(called the mount point) in the namespace.
```sh
sudo mount /dev/sdb1 /mnt/usb
```
- `/dev/sdb1` : device(USB partition)
- `/mnt/usb` : mount point(content of the USB is accessible here)

4. Unmounting
Detach the filesystem from the directory tree. After unmounting, this directory becomes an empty directory again.  
```sh
unmount /mnt/usb
```

Rules,
- You must mount before using a filesystem. 
- You must unmount before removing a device. 
#### Organization of the file system
![[Pasted image 20250917122501.png]]
- `/` → root of everything
- `/bin` → essential binaries (e.g., `ls`, `cp`, `mv`)
- `/sbin` → system binaries (e.g., `mount`, `ifconfig`)
- `/etc` → configuration files
- `/home` → user home directories
- `/var` → variable data (logs, spools, caches)
- `/tmp` → temporary files
- `/usr` → user utilities, libraries, documentation
- `/lib` → shared libraries
- `/boot` → boot loader files, kernel images
- `/dev` → device files (e.g., `/dev/sda`, `/dev/null`)
- `/proc` & `/sys` → pseudo filesystems exposing kernel info
