ACLs are an extension of the traditional Unix file permission system which allows to assign fine-grained permission to file and directories beyond the standard owner-group-other model. 

Usual linux permissions,
```sh
-rw-r----- 1 alice devs  1234 Sep 18 09:00 report.txt
```
- `alice` is the owner.
- `devs` is the group.
- User can read & write. 
- Group can only read.
- Others don't have any access. 

**Fundamental question**
What is you want to give `bob`(not in the `devs` group) read access without changing the group or ownership ?

****
#### POSIX
POSIX = Portable Operating System Interface
It's a standard(defined by IEEE) that describes how Unix-like operating systems should behave to ensure that software written for on Unix-like system(Linux, BSD. macOS, Solaris) can run with little modification. 

POSIX covers, 
- System calls(ex: `fork()`, `exec()`)
- File system behavior(permissions, paths, links)
- Shell Utilities(ex: `ls`, `grep`, `chmod`)

**POSIX ACLs**
This is the standard way of handling ACLs in Unix-like systems. 
It defines limited permission set(`r, w, x`) and permission can be given to,
- A user(owner or specific users)
- A group(primary or additional groups)
- Others(everyone else)
Widely supported in Linux filesystems like `ext3/ext4`, `XFS`, `btrfs`, `ReiserFS`. 
Managed with `getfacl`/`setfacl`.

When a process tries to access a file, linux checks,
1. Owner permission : If the process of the file owner
2. ACL entries for specific user/groups
3. Group class permission(including ACL groups)
4. Other permissions(if no match above)

POSIX ACL inheritance,
- For directories, you can define default ACLs.
- New files created inside inherit those ACLs automatically. 

POSIX ACLs = Standard Unix permissions and ACLs. 

#### NFSv4
NFS = Network File System
This protocol originally developed by Sun Microsystems to allow computers to share files over a network as if they were local. 
Widely used in enterprise environments(ex: Linux servers, storage systems).

NFSv4 is the 4th version of this protocol. Compared to previous versions this new version,
- Adds stronger security and performance improvements.
- Includes its own ACL system : **NFSv4 ACLs**.

NFSv4 ACLs,
- Much more detailed than POSIX ACLs.
- Inspired by **Windows NTFS ACLs**. 
- Support complex inheritance rules for directories. 
- Permission bits include things beyond `rwx` such as
	`DELETE` : delete file
	`APPEND_DATA` : add data to a file
	`READ_ATTRIBUTES` : read metadata
	`WRITE_METADATA` : modify metadata
	`READ_ACL`/`WIRTE_ACL` : view/change ACLs
- In NFSv4 you can assign permission not just to users/groups, but also to special entities(similar to windows ACLs) like,
	- everyone
	- authenticated users
- NFSv4 access determination is similar to POSIX but checks more detailed permission bits. 
	Ex: process might be allowed to read attributes but not read data. 
- Directories can pass ACLs to new files similar to POSIX but NFSv4 ACLs have inheritance flags that control how and when inheritance happens. 
- NFSv4 is using special tolls (`nfsv4_getfacl` and `nfsv4_setfacl`) instead of standard POSIX `getfacl`/`setfacl`. 
- NFSv4 ACLs can also coexist with POSIX permissions but they don't map perfectly. Sometimes mismatch can happen. 
	Ex: A file looks `r--` in POSIX mode but allows more under NFSv4 ACLs.
- To setup NFSv4 ACLs, you must explicitly enable and configure it in the NFS server. Then clients can use it across the network. 

Linux chose to follow the POSIX standard for ACLs, to ensure compatibility across Unix-like systems. This helps linux behave in a consistent and predictable way across file systems(`ext4`, `XFS`, `btrfs`, etc...) as long as the filesystem support ACLs. 

Linux doesn't implement NFSv4 ACLs natively inside local filesystems. But linux can still mount NFSv4 shares from other systems that use NFSv4 ACLs. 
So you can work with NFSv4 ACLs across the network, but they are not built into linux's local filesystems.

****
ACLs are more powerful and complicated than regular file permission control system. Unlike standard file permissions(which always define only three entries) ACLs are flexible in a way that multiple specific users or groups can each have their own custom permissions. 
Ex: `user:bob:rw-` , `user:carol:r--` , `group:devs:rw-`

Tools used,
- `getfacl` : View ACLs of a file/directory
- `setfacl` : Set or modify ACLs
These commands can be used everywhere without regard to the underlying filesystem type. 

Ex:
`report.txt` is owned by `alice` and `devs` group. 
You want to allow bob to red it,
```sh
setfacl -m u:bob:r report.txt
```
Check permissions with
```sh
getfacl report.txt
```

You can set ACLs on a directory so new files created inside inherit those permissions.
Ex:
```sh
setfacl -d -m u:bob:rw project/
```
##### The Mask
ACLs include a mask entry, which acts like a 'maximum permission filer' for all named users and groups. 
Ex: If the mask if `r--`, even if you grant `rw-` to someone, they will only effectively get `r--`.
