A log message includes few properties including,
1. A time stamp
2. Type
3. Severity
4. Process name
5. Process ID(PID)

Log management is the process of,
- Collecting logs form various sources,
- Providing a interface for querying, analyzing, filtering and monitoring messages,
- Managing the expiration of messages

Most of the application write their logs into `/var/log` directory.

### 1. System Journal
The `system journal` is a centralized built-in logging system. 

`system journal` stores logs from,
- System services(ex: network manager)
- User processes
- Kernel logs
- boot logs
- hardware events

Journal files are at,
```sh
/var/log/journal
```

To view logs in the system journal, `journalctl` command can be used. 

1. To view logs from the current boot
```sh
journalctl -b
```
2. Show logs for a specific service
```sh
journalctl -u ssh.service
```

Sources which `journalctl` indexes messages from,
1. `/dev/log` UNIX socket : Software that submit messages according to `syslog` convention
2. `/dev/kmsg` : Linux kernel
3. `/run/systemd/journal/stdout` : Service software that writes log messages to standard output
4. `/run/systemd/journal/socket` : Service software that submits messages through the systemd journal API. 
5. Audit messages from the kernel's audit daemon

The default journal configuration file is,
```sh
/etc/systemd/journald.conf
```
Since this file is not intended to be edited directly, you can customize this directory,
```sh
/etc/systemd/journald.conf.d
```
### 2. Syslog
Syslog is one of the oldest and most widely-used **logging standard** in Unix/Linux systems.
It defines how system messages are formatted, categorized and transmitted both locally and across networks. 

Syslog is,
1. A protocol : Defines how messages are structured and transmitted(RFC 5424)
2. A logging architecture : Specifies facilities, severity levels and message formats. 
3. A service(daemon) : A program that receives logs and writes them to files.

Content of Syslog includes,
- Timestamp
- System's hostname
- Name of the process and its PID in square bracket
- Message payload

To open Syslog,
```sh
cat /var/log/messages
```
### 3. Kernel and Boot-time logging
For kernel logging at boot time, kernel log entries are stored in an internal buffer on limited size. 
The buffer is large enough to accommodate messages about all the kernel's boot-time activities. 
When the system is up and running, a user process access the kernel's log buffer and dispose of its content. 

To open the kernel log,
```sh
dmesg
```

### 4. Management and Rotation of Log Files
##### logrotate
logrotate is the standard linux utility that automatically manages log files to they don't grow endlessly and fill up your disk.
Tasks carried out by logrotate,
1. Create fresh empty log files and rename current log file.
2. Compressing older rotated logs.
3. Removes log older than a certain of rotations/days.
4. Email logs to admins. 
5. Run custom scripts before/after rotation

logrotate standard config file is `/etc/logrotate.conf`. 
Handling logging data from several servers can be challenging. Tools to handle this job in large scale,
- The ELK stack
- Graylog
- Splunk
##### Logging policies
Considerations to prepare logging strategies, 
- Number of systems/applications to include
- Type of infrastructure available
- How long logs must be retained
- Type of events to log

Following information must be captured,
- Username/user ID
- Event success/failure
- Source address for network events
- Date and time
- Sensitive data added/altered/removed
- Event details

Best practices,
- Log server's storage must be carefully managed.
- Limit shell access to centralized log servers to trusted sys admins
