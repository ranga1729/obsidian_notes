PAM = Pluggable Authentication Module
PAM is a framework used by Linux and UNIX systems to handle authentication in a flexible and modular way. 
![[Pasted image 20251023161805.png]]
PAM acts as a middle layer between linux application and the system's authentication methods. 

Without PAM, each service(like `login`, `su`, `sudo`, `ssh`) has to implement its own authentication code. 
This is inconsistent, hard to maintain and difficult to update system-wide security policies.

With PAM, authentication logic is centralized and modular.
All applications use the same authentication framework, and admins can change policies by editing simple configuration files without modifying the application themselves. 

How it works,
1. A service(like `login`, `sudo`, `ssh`) asks PAM to authenticate a user. 
2. PAM checks its config files in `/etc/pam.d` or `/etc/pam.conf`.
3. PAM executes a stack of modules(shared libraries) according to that configuration. 
4. These modules perform various checks(passwords, biometrics, 2FA, etc).
5. PAM returns success or failure to the application.

PAM configuration files,
- `/etc/pam.conf` : A single system-wide file(rarely used now)
- `/etc/pam.d` : A directory containing individual config files for each service.
Ex:
```sh
/etc/pam.d/login
/etc/pam.d/sshd
/etc/pam.d/sudo
/etc/pam.d/passwd
```
Each file defines the authentication process for that specific service. 

Using PAM, an organization can expands its authentication method beyond passwords to options such Kerberos, OTPs, ID dongles, fingerprint readers or other biometrics.
