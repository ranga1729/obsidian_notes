Random forest is a ensemble learning algorithm consist of multiple decision trees. Each tree gives a vote and the final output is decided by the majority label for a classification task. 

Since our CT scan images 28x28, every image is represented as a vector of 784 features. These features are divided among 11 labels(organ names).
![[Gemini_Generated_Image_blt8azblt8azblt8.png]]
Each pixel of these images are features. 
When the image is flattened into a vector, we get 784 features per image. 
For each pixel, we calculate the pixel intensity. 
Ex: a normalized number between 0(black) to 255(white)

Feature 1 = pixel at row 1, col 1
Feature 2 = pixel at row 1, col 2
...
Feature 784 = pixel at row 28, col 27
Feature 784 = pixel at row 28, col 28

Each tree of the forest, uses a bootstrapped sample of the training images. 
Ex: 
	Tree 1 : 10 brain, 15 livers, 3 hearts
	Tree 2 : 5 lungs,10 livers, 7 hearts
	...
At each split, the tree considers only a random subset of feature(pixels) instead of looking at all 784 pixels. Then it will choose which pixel gives the best split between labels.  
Ex:
	Tree 1 : is looking at random 20 pixels. 
	Then it identifies the 87th pixels shows the best pixel intensity difference between the labels it was originally received(brain, liver, heart)

Here's an example of how tree 1 would split. 
![[Pasted image 20250919063722.png]]

This process applies to all images and random forest creates multiple trees similar to the above example. 
When a new image comes in,
1. Flatten to 784 pixels and feed into the forest.
2. New image checks against all decision trees inside the forest. In each tree, it follows the branches until reaching a leaf node. The leaf node contains a class prediction(ex: "Brain")
3. Each tree votes their own prediction. 
	Tree 1 : "Brain"
	Tree 2 : "Liver"
	Tree 3 : "Brain"
4. Total votes are analyzed and the final prediction is the class with the most votes. 
	Brain: 3, Heart: 1
	Majority vote: Brain

Why this model is the best solution for CT Scan image classification ?
1. Since each tree only looks at a random subset of features at each split, its goof for handling high-dimensional data like 28x28 CT images(784 features).
2. Since random forest averages across many tree, it reduces the influence of noisy pixels. Good for handling artifacts often with noise like medical images.
3. Random forest can train well in smaller datasets like medical images while Deep learning(CNN) usually requires large datasets to learn.
4. Random forest reduces variance and produces more stable predictions since it combines many trees rather than depending on one decision tree. Valuable for area like medicine where stable, reliable predictions are critical. 
#### Evaluation strategy
Metrics for evaluate the model performance.
1. Accuracy of the training set
	Proportion of correctly classified images plays a crucial part in training. 
	We must maintain a good balance between labels. 
	Ex: If there are significant amount of more brains than hearts, training would be useless. 
2. Precision (per class)
	Ex: Out of all images predicted as "Liver" how many were actually liver  ?
3. Recall
	Ex: Out of all actual "Liver" images, how many did the model correctly detected ?
4. F1 Score(per class)
	Harmonic mean of precision & recall.
	Good to evaluate the balance between false positive and false negative.

Using a test set, we can compute the accuracy, precision, recall and F1 per class.
For a better visualization, we can use a confusion matrix to understand common error.
	Ex: often confusion between Liver and Kidney

```python
def build_node(data, available_features):
    # Randomly select subset of features
    random_features = randomly_select(available_features, sqrt(total_features))
    
    # Find best split among random features
    best_feature = None
    best_threshold = None
    best_info_gain = 0
    
    for feature in random_features:
        for threshold in possible_thresholds:
            info_gain = calculate_information_gain(data, feature, threshold)
            if info_gain > best_info_gain:
                best_feature = feature
                best_threshold = threshold
                best_info_gain = info_gain
    
    # Split data based on best feature/threshold
    left_data = data[data[best_feature] <= best_threshold]
    right_data = data[data[best_feature] > best_threshold]
    
    # Recursively build child nodes
    left_child = build_node(left_data, available_features)
    right_child = build_node(right_data, available_features)
```

### Pseudocodes
1. Training the model
```text
Input: 
  - Dataset D = {(image1, label1), (image2, label2), ..., (imageN, labelN)}
  - Number of trees T
  - Max features per split F
  - Max depth per tree (optional)

Output:
  - Trained Random Forest model 'RF'

Procedure TrainRandomForest(D, T, F):
  Initialize empty list RF_trees

  For i = 1 to T:
      # Step 1: Bootstrap sampling
      D_i = random sample of D with replacement

      # Step 2: Train a decision tree on D_i
      tree = TrainDecisionTree(D_i, max_features=F, max_depth)
      
      # Step 3: Add tree to the forest
      RF_trees.append(tree)

  Return RF_trees as RF
```
- `TraindecisionTree` splits nodes using random subset of features at each node and stops when max depth is reached or nodes are pure.
- Each tree learns different pixel patterns due to random bootstrapping + feature randomness.

2. Predicting a new image
```text
Input:
  - New image x
  - Trained Random Forest RF = [tree1, tree2, ..., treeT]

Output:
  - Predicted class label y_pred

Procedure PredictRandomForest(RF, x):
  Initialize empty list of votes

  For each tree in RF:
      label = PredictDecisionTree(tree, x)  # follow splits down to a leaf
      votes.append(label)

  # Step 2: Majority voting
  y_pred = most common label in votes

  Return y_pred
```
- `PreduictDecisionTree` checks the pixel values for x at each split until a leaf is reached.
- each tree "votes" independently. The majority vote decides the final organ.
