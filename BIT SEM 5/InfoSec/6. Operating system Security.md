#### 6.1 System Sec Planning
- Strategies to prevent targeted cyber intrusions, 
	- White-list approved applications. 
	- Patch third party applications and the OS vulnerabilities.
	- Restrict admin privileges.
	- Create a "defense-in-depth" system.

- Considerations during the system security planning,
	- The purpose of the system
	- type of information store
	- applications and services provided
	- categories of users 
	- user privileges
	- type of information user access
	- user authentication mechanism
	- file of databases servers requirements
	- administers of the system
	- additional security measures (ex: host firewalls, anti-virus, malware protections, logging)

#### 6.2 OS Hardening
OS hardening is the process of securing an OS by reducing its attack surface. 
when an OS is installed, it often configured for maximum compatibility and ease of use. Hardening involves tightening the security of an OS. 

Basic steps to secure an OS,
1. Install and patch the OS. 
2. Harden and and configure the OS to address security needs by
	- Removing unnecessary services, applications and protocols
	- Configure users, groups and permissions
	- Configure resource controls
3. Install and configure additional security controls
	Ex: firewall, intrusion detection systems(IDS)
4. Test the system

#### 6.3 Application Security
- Software provide remote access or services if often a concern here. 
- Some applications may include default data/scripts or user accounts. These should be reviewed. 
- Carefully grant permissions required by applications. 
- Use secure networks and encryptions. 
#### 6.4 Security Maintenance
- Includes,
	- Monitoring and analyzing logging info.
	- Performing regular backups. 
	- Recover from security compromises.
	- Regular testing. 
	- Patch and update all software.

- Logging is a reactive control that inform you about the bad things happened. The range of logging must be determined during the system planning.
- Automated analysis can be run on logging data. 
- Backups is the process of copying data at regular intervals and it allows the recovery of lost of corrupted data over a short time periods. (few hours to weeks)
- Archive is the process of retaining copies of data over extended period of time.(months to years) Useful in legal and operations requirements. 
- Policy related to backups and archives must be determined during the system planning. 
#### 6.5 Linux/Unix Security
- Application config files are usually a text files in linux systems. 
- Unix systems implement discretionary access control to all file system resources. (including devices, processes, memory)
- Access is specified as "granting read/write/execute permissions" to each owner, group and others for each resource. 
	`chmod`
- Best practices: 
	- minimize the number of `setuid` root programs. 
	- some network accessible services doesn't require the full file-system access. restrict them using `chrooting`. 
#### 6.6 Windows Security
- "windows updates" and automatic updates for third-party applications must be enabled. 
- Users and groups in windows are defined with a Security ID`(SID)`.
	SID may be controlled by a central Active Directory(AD) using LDAP protocol.
- Windows implements discretionary access controls to system resources such as files, shared memory and named pipes.
- The access control list has a number of entries that may grant or deny access rights to a specific SID. (SID represent a user or a group)
- Windows support mandatory **"integrity controls"** labeled as low, medium, high or system. 
	![[Pasted image 20251228015910.png]]
- Whenever data is written to an object, the system ensures that the subject's integrity is equal or higher that the object's level. 
- Windows define privileges a well.(system wide)
	![[Pasted image 20251228015740.png]]
- Windows config info is in the registry. Its a database of keys and values that read by applications. 
- Windows support encryption features as well including BitLocker using AES.
