Bluetooth is a short-range wireless technology(IEEE 802.15.1) designed for exchanging data between fixed and mobile devices, forming a Personal Area Network(PAN).

This works on mainly two layers.
#### 1. **The Radio Layer(PHY)**
- Frequency Band: Operates in globally unlicensed 2.4 GHz Industrial, Scientific and Medical(ISM) band(2.400 - 2.4835 GHz), the same range used by Wi-Fi.
	![[Pasted image 20251106090224.png]]
- Frequency Hopping Spread Spectrum(FHSS): To minimize interference and improve the robustness of the transmission, Bluetooth uses Adaptive Frequency Hopping(AFH). It constantly switches between 79(classic) or 40(LE) channels 1 MHz apart, up to 1,600 times per second.
- Topology: Bluetooth network is an ad-hoc network consisting of one master devices and up to seven Active Slave devices, called a "Piconet". A device can be slave in multiple piconets, forming a "Scatternet".

#### 2. The Protocol Stack
The Bluetooth layer protocol is a layered architecture. 

| Layer                                               | Protocol     |                                                                                                                                                                                              |
| --------------------------------------------------- | ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Link Manager Protocol(LMP)                          | Classic & LE | Responsible for link setup, security control, authentication, encryption, key management and power control.                                                                                  |
| Logical Link control and Adaptation Protocol(L2CAP) | Classic & LE | Provide multiplexing(allow multiple high-level protocols to share one link) and segmentation/reassembly. Vulnerable to Bluesmacking DoS attacks if oversized packets are send to this layer. |
| service Discovery Protocol(SDP)                     | Classic Only | Allow a device to discover services available on other Bluetooth devices. A common target for unauthorized service enumeration.                                                              |
| Generic Attribute Profile(GATT)                     | BLE Only     | Defines how data is organized and exchanged. All BLE connections involve a client(requests data) and a server(hold the data in attributes)                                                   |
| RFCOMM                                              | Classic Only | Emulates a serial cable connection, allowing older applications to use Bluetooth. Often exploited due to its wide use and legacy design.                                                                                                           |

#### Bluetooth Versions
Modern bluetooth 
specification introduced two fundamentally different technologies,
1. Classic(BR/EDR)
2. Low Energy(LE)

| Feature     | Classic(BR/EDR)                                                 | Low Energy(LE)                                                  |
| ----------- | --------------------------------------------------------------- | --------------------------------------------------------------- |
| Primary use | Continuous data streaming(Audio/Voice, File transfer, Headsets) | Periodic small data burts(Sensors, Beacons, Wearables, Iot)     |
| Power       | Higher(Radio is always on)                                      | Very low(Radio is off most of the times, wakes for short burst) |
| Topology    | Piconet(Master & 7 slaves)                                      | Star, Broadcast, Mesh                                           |
| Security    | 68/128-bit encryption                                           | AES-CCM 128-bit encryption                                      |
#### Common vulnerabilities
1. Bluesnarfing
Covertly retrieving information(contacts, messages) from an unpatched or older Bluetooth devices without the owner's permission.
**Mitigation**:
- Use Secure Simple Pairing(SSP/SC)
- Keep firmware updated
- Use non-discovery mode

2. Bluejacking
Sending unsolicited messages(business cards/spam) to nearby discoverable devices. 
**Mitigation:**
- Set the device to non-discoverable mode when not pairing

2. Bluedubbing
Gaining complete remote control over a target device via a security flaw.
**Mitigation:**
- Fixed by Secure Simple Pairing

2. DoS(Bluesmacking)
Overwhelming the devices Bluetooth stack(ex: L2CAP layer) with oversized or malformed packets to cause a crash or denial of service. 
**Mitigation:**
- Proper protocol implementation by device manufacture and OS/firmware patching

2. Passive Eavesdropping
Intercepting data transmitted between two devices. Can be achieved if the pairing/bonding process is weak or if the attacker is present during the initial key exchange.
**Mitigation:**
- Use secure connections which employ stronger key exchange to prevent key derivation.

2. Impersonation/MITM Attacks
The attacker impersonates a trusted device to intercept communication or trick a victim into connecting to a malicious device. _This is what vulnerabilities like **BIAS** (Bluetooth Impersonation Attack) exploit._ 
**Mitigation:**
- Using authenticated/secure connections

### Pairing and Trust
Bluetooth security revolves around pairing(creating a shared secrete key) and authentication(verifying identity). 
1. Bonding : Two devices which authenticated create and store a Link Key(a shared secret key) so they don't have to re-authenticate completely for future connections. 
2. Authentication : Verifies a device's identity using the link key. Modern version use cryptographic key agreement protocols.
3. Encryption : All data sent between bonded devices is encrypted using a stream cipher(**E0** for classic, **AES-CCM 128-bit** for LE).
4. Secure Simple Pairing(SSP)/Secure Connection(SC) : Critical for simplifying and securing the pairing process by using more robust Elliptic Curve Diffie-Hellman (ECDH) key exchange to provide protection against **Man-in-the-Middle (MITM)** attacks during pairing.
