#### Basics of Wi-Fi Technology
WiFi is based on IEEE `802.11` protocols. 
Ex: `802.11a/b/g/n/ac/ax`
This defines the architecture and MAC and Physical layer specifications for wireless LANs(WLANs). 
WiFi uses high-frequency radio waves, mainly 2.4 GHz and 5 GHz bands. 
(Newer WiFi 6E uses 6 GHz). 

Terminology,
- **AP**(Access Point) : A device that acts as a connection between wireless medium and distributed system.
- **SSID**(Service Set Identifier) : The network name for a a particular WLAN. All access points and devices on a specific WLAN must use the same SSID to communicate. 
- **BSSID**(Basic Service Set Identifier) : The unique mac address of the AP.
- **PDU**(Protocol Data Unit) : A generic term for a unit of data exchanged between peer network layers/protocols. 
	![[Pasted image 20250905105747.png]]
- **SDU**(Service Data Unit) : A unit of data that has been passed down from an upper OSI layer to a lower layer, but not yet been encapsulated into a PDU by the lower layer. 
#### Security Protocols
WiFi security mainly uses encryption protocols,
1. **WEP**(Wired Equivalent Privacy)
	Uses `RC4` stream cipher with Initialization Vectors(IVs).
	Very weak. Crackable in minutes with tools like `aircrack-ng`
2. **WPA**(WiFi Protected Access)
	Introduced `TKIP`(Temporal Key Integrity Protocol)
	Still weak and breakable. But better than WEP.
3. **WPA2**
	Uses `AES-CCMP` encryption.
	Relies on 4-way handshake between client and AP.
	Vulnerable to dictionary/brute-force attacks if weak passwords are used. 
4. **WPA3**
	Uses `SAE`(Simultaneous Authentication of Equals)
	Stronger, but still has some implementation flaws. 
#### Workflow of WiFi (WPA2 - most common with 4-way handshake)
![[Pasted image 20250905112652.png]]
1. Scanning
There are two methods to scan for available networks, 
2. Passive scan : Listens for a beacon frames broadcast by an AP every 100 ms.
3. Active scan : Sends probe request asking APs  to respond. 
Each AP respond with info, 
- SSID : Network name
- BSSID : AP MAC Address
- Security type : WAP2/WPA3/WEP
- Channel info

2. Selecting a network
When click on a AP, device check if it has a saved password or prompts for the password. 

3. Authentication(802.11 authentication)
WPA2 uses "Open System Authentication". 
- The client, sends an **Authentication Request Frame** to the AP.
- The AP replies with an **Authentication Success Frame**.
**Still the password hasn't verified.**

4. Association
The client sends an **Association Request Frame** telling the AP,
- Its MAC address
- Supported data rates
- Supported features (like `802.11n/ac`)
The AP replies with an **Association Response Frame**, confirming that the client can join. 
Now the client is "associated" with the AP and they can exchange data frames.
But the connection hasn't established yet. 

5. WPA2 4-way handshake
![[Pasted image 20250905120651.png]]
This is where the real password verification and encryption happen.
Purpose : Both client and AP need to derive the same **Pairwise Transient Key(PTK)** from the **Pre-Shared Key(PSK)** you entered(your Wi-Fi Password).

Steps,

| Step | Sender | Action                                                                                                                              |
| ---- | ------ | ----------------------------------------------------------------------------------------------------------------------------------- |
| 1    | AP     | Sends a nonce(random number) to the client(ANonce)                                                                                  |
| 2    | Client | Generates its own nonce(SNonce), combines it with ANonce, PSK, MAC addresses an derives the PTK. Sends SNonce to AP.                |
| 3    | AP     | Use SNonce, ANonce, PSK and MAC addresses to derive the same PTK. Sends **message integrity code(mic)** to client for verification. |
| 4    | Client | Verifies MIC from AP, confirms key agreement and sends ACK.                                                                         |
After this handshake, both sides have the same encryption keys. 
All traffic is now encrypted with `AES-CCMP`.

> [!NOTE] Attackers target
> If you capture all 4 handshake messages, they can attempt offline brute-force attacks to guess your PSK. 

6. DHCP & IP assignment
Once the secure channel is established, 
- Client request an IP via DHCP.
- AP or router assigns an IP address.
- Default gateway, DNS, etc are configured. 

6. Data Transmission
All frames are now encrypted using the PTK.
Device can securely send/receive data.

#### Attack Types,
1. [[1. Packet sniffing & Reconnaissance]]
Goal : Capture packets, identify SSIDs, BSSIDs, channels, connected clients.
Tools : `airodump-ng`, `kismet`, `wireshark`

2. WEP Cracking
Exploit weak IVs in RC4 encryption.
Tools: `aircrack-ng`

3. WPA/WPA2 Cracking
Capture the 4-way handshake between client and AP(using de-authentication attacks to force re-connection)
Then use dictionary/brute-force attacks on the captured handshake. 
Tools: `aircrack-ng`, `hashcat`

4. Evil Twin/Rogue AP
Create a fake AP with the same SSID as the target. 
Victim connect and you capture credentials. 
Tools : `airbase-ng`, `hostpad`

5. KRACK Attack(Key Re-installation)
Exploit flaws in WPA2's 4-way handshake implementation.
Not a password crack, it forces key re-installation.

6. WPS Attacks
Many routers have WPS(Wi-Fi Protected Setup) enabled.
Vulnerable to PIN brute-force attacks.
Tools: `reaver`, `bully`
