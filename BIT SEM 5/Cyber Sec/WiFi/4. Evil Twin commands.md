People uses "Connect automatically" feature on trusted networks. 
This option allows user devices to connect with the Wi-Fi network when it comes to the range of it. 

what if, an attacker creates a rogue AP with similar SSID(my be MAC and security details) to the original network.
That "Connect automatically" feature will try to authenticate with the attackers rogue Wi-Fi.

If victims device share enough info to crack the password, attacker can get access to the original network.
(Offline password cracking using `hashcat` or `Aitcrack-ng` suite)

Extension: If the attacker let the victim access internet through his rogue AP,
	Victim won't see suspicion.
	Attacker can monitor network traffic of the target user. 
	Attacker can re-direct victim to phishing sites. 
##### Pre-requisites
- A pentesting OS to use tools. 
- Two Wi-Fi interfaces. 
	1. Support monitor mode and packet injection. (ex: Alfa USB)
	2. Act as the rogue AP.(built-in NIC is suitable)
- Tools,
	1. `aircrack-ng` (airmon-ng, airodump-ng, aireplay-ng, aircrack-ng)
	2. `hostpad`
	3. `dnsmasq` (for DHCP)
	4. `hcxtools` (hcxcaptools) and/or `cap2hccapx`
	5. `hashcat` or `aircrack-ng` for offline password testing.
	6. `wireshark` for packet inspection and 
	7. Client logs (WPA_supplicant logs on Linux, Event Viewer on Windows)

Steps:
1. Prepare the 
2. Passive capture of a legitimate handshake
Put monitoring interface up,
```sh
sudo airmon-ng start wlan0
```
Check Wi-Fi networks,
```sh
sudo airodump-ng wlan0mon #note the target network
```
Start capture on channel and BSSID of the target AP
```sh
sudo airodump-ng -bssid <REAL_AP_BSSID> -c <Channel> -w capture wlan0mon
```

3. Wait for the client to connect(or force a reconnect - `de-auth` attack)
Force a reconnect(`de-auth`)
If no client is reconnecting naturally, you can trigger `de-auth`.
```sh
sudo aireplay-ng --deauth 1 -a <REAL_AP_BSSID> -c <CLINET_MAC> wlan0mon
```
This will send a `de-auth` message so the target client will re-connect and perform the handshake. 

When the 4-way handshake occurs, `airodump-ng` will indicate **WPA handshake** captured and a `.cap` file will include the `EAPOL` frames.

Open the `.cap` in Wireshark and filter for `eapol` to inspect the 4-way handshake.
This include nonce, MIC, MACs but as cryptographic values.

3. Evil-Twin(rogue AP) setup for Auto-connect
(If you configure your rogue AP to use the same SSID _and same PSK_ (only if you  control both), the client will happily connect to the rogue AP and complete a full 4-way handshake. That lets you observe the full connection and capture `EAPOL` frames that are valid for offline testing. This demonstrates how a rogue AP can become the client's active association point when SSID + PSK match.)

To run a rogue AP with `hostapd`,
Create a `hostapd.conf`,
```ini
interface=wlan1
driver=nl80211
ssid=rogue_SSID
channel=6
hw_mode=g
wpa=2
wpa_passphrase=TestPass123
```
```sh
sudo hostapd hostapd.conf
```
And provide DHCP with `dnsmasq` for clients to get IPs.

Watch client logs while your rogue AP is up,
```sh
sudo journalctl -u NetworkManager 
#or
wpa_supplicant
```
Look for lines like: `WPA: 4-Way Handshake failed - pre-shared key may be incorrect` or `WPA: MIC failure`.
