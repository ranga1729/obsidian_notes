An Evil Twin Attack is a type of Wi-Fi attack where and attacker sets up a rogue(fake) Wi-Fi access point(AP) that looks identical to a legitimate one. 

Workflow,
1. Impersonation
	- The attacker creates a Wi-Fi hotspot with the same SSID as a trusted one.
	- Might use the same security settings and even spoof the MAC address of the real AP.
2. Victim Connection
	- Victim's devices try to connect to this network since its looks legitimate and similar to that known wifi network.
	- Device may connect automatically if that devices is allowed that option by the user on the target network.
3. Data interception
	- Once connected, all traffic flows through the attacker's AP. 
	- This allows attackers to perform victims credential on the target Wi-Fi network and sniff un-encrypted traffic, capture login credentials, injecting malicious code or re-directing user to phishing pages.
4. Escalation
	- Even if the traffic is encrypted (HTTPS), attackers can attempt SSL stripping or push fake certificates to downgrade security.

*****
#### Capture Victim's handshake packets to gain access to the original network

**WPA/WPA2 4-way handshake**
The handshake happens when a client authenticate with the AP. 
It proves that both sides share the same Pre-shared key(PSK/Password).
By capturing it, you get a encrypted challenge-response exchange that can be testes offline against candidate passwords. (Not the plain password)

**Step 1 : Capture the handshake(Passive sniffing)**
- Put the Wi-Fi adapter to the monitor mode.
- Listen on the channel of your target AP.
- When a client connects/reconnects, the handshake is exchanged and can be captured.
- If no client reconnects, you can trigger a **de-authentication** to force a reconnect.
Tools : `airmon-ng`, `airodump-ng`, `airplay-ng` (Aircrack suite)

**Step 2 : Build the Evil Twin**
- Setup a fake AP with the same SSID as your real one. 
	Tools: `airbase-ng`, `hostpad`, `wifiphisher`
- Broadcast with network and wait for your client to connect.
- When it connect, it will try the handshake with your rogue AP.
- You capture the handshake exchanged. 

> [!NOTE] Note
> In WPA2-PSK, the client proves the PSK via cryptographic operations, but doesn’t reveal it. The captured handshake is only useful for offline guessing.

**Step 3: Offline Password Testing**(brute-forcing)
- Use `aircrack-ng` or `hashcat` or similar to attempt guess against the handshake.


> [!NOTE] WPA3 is a bitch !
> **WPA3** changes the game by using **SAE (Simultaneous Authentication of Equals)** which resists offline cracking entirely.
